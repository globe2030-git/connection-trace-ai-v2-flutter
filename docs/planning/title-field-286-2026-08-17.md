# 직함 — **지금 정답지로는 손댈 수 없다** (2026-08-17, 추가 286)

**결론부터**: 파서를 두 번 고쳐 재 봤고 **둘 다 실패했다**(하나는 0장, 하나는
**−5장**). 되돌렸다. 남은 오류의 상당수가 **파서가 맞힐 수 없는 정답**이다.

```
기준선  직함 66% (일치 68 · 틀림 28 · 미검출 6 · 오검출 1)
시도 ①  연락처 라벨 찌꺼기 제거      →  ±0장   (실제 데이터에 그 모양이 없었다)
시도 ②  한글 직함 뒤 영문 꼬리 제거  →  −5장   (되돌림)
```

---

## 1. ⚠️ 왜 맞힐 수 없나 — 정답지 쪽 문제 셋

### ① 원문에 없는 구분자가 정답에 들어 있다 — 2장

```
card_20    원문 `… 01045481893 부장 스포츠기획팀 박지웅`
           정답 `부장 | 스포츠기획팀`          ← ⚠️ 원문에 `|`가 없다
card_113   정답 `경영지원실 인사팀 | 팀장`     ← 같은 모양
```

**OCR이 읽지 않은 글자는 파서가 만들어 낼 수 없다.** 이 두 장은 어떤 파서로도
100% 못 맞힌다.

### ② 정답 직함에 **사람 이름**이 들어 있다 — 3장

```
card_14    정답 `안민식.이사`          파서 `이사`        ← 파서가 맞다
card_26    정답 `파트너 변리사 김세진`  파서 `파트너 변리사` ← 파서가 맞다
card_128   정답 `수석 규`              파서 `수석`        ← `규`는 이름 조각
```

정답지 규칙은 *"이름 빼고 직함·부서만"*이다(`tool/ocr_review/README.md`).
**세 장 다 파서 쪽이 규칙에 맞는다.**

### ③ ⭐ 정답의 **자세함이 장마다 다르다** — 이게 가장 크다

```
card_135   정답 `대리`                    (원문: `경영지원팀 | 대리 안해인 …`)
card_113   정답 `경영지원실 인사팀 | 팀장`  (부서까지 통째로)
card_136   정답 `CEO`                     (원문: `CEO & Founder Joyce Choi`)
card_121   정답 `부장 Enterprise팀 | 사업개발파트`
```

⚠️ **부서를 넣을지 말지가 정해져 있지 않다.** 어떤 장은 직함만, 어떤 장은
부서까지다. **파서를 어느 쪽에 맞춰도 반대쪽이 틀린다** — 회사 칸의 로고
문제(추가 278)와 **똑같은 모양**이다.

---

## 2. 시도한 것과 결과

### 시도 ① 연락처 라벨 찌꺼기 제거 — **±0장**

명함은 `… 인사팀 | 팀장 M010-… E …@… T 031-…`처럼 직함과 연락처를 한 줄에
적는다. 번호·이메일은 앞에서 뽑아 가고 **라벨 글자만 남아** 직함에 붙는다.

```
경영지원실 인사팀 | 팀장 M E T   →  경영지원실 인사팀 | 팀장
```

📌 **내가 만든 입력에서는 재현됐는데 실제 103장에서는 한 장도 안 바뀌었다.**
실제 OCR은 줄을 다르게 끊어서 그 모양이 안 나온다. **재현이 곧 실측은 아니다.**

### 시도 ② 한글 직함 뒤 영문 꼬리 제거 — **−5장, 되돌림**

```
연구소장 Green IT Korea Plus Newness  →  연구소장     (맞음)
대표 GODN                             →  대표         (맞음)
```

3장을 얻을 것으로 봤는데 **5장을 잃었다.** 정답지가 **영문 꼬리를 직함에
포함하는 장**이 더 많았다. ①과 같은 이유다 — **정답의 범위가 정해져 있지 않다.**

---

## 3. 📌 그래서 무엇을 먼저 정해야 하나

**사용자에게 물을 것 셋.** 정해지면 정답지를 통일하고, 그 다음에 파서를 맞춘다.

| | 물음 | 예 |
|---|---|---|
| **가** | 부서를 직함에 **넣나** | `대리` vs `경영지원팀 \| 대리` |
| **나** | 구분자 `\|`를 **쓰나** | 원문에 없으면 어떻게 하나 |
| **다** | 영문 병기를 **넣나** | `대표` vs `대표 CEO` |

⚠️ **정하기 전에 파서를 손대면 숫자만 움직이고 사용자가 보는 값은 안 나아진다.**
오늘 로고(278)·팩스(282)에서 이미 두 번 겪었다.

## 4. 오늘 네 번째다

```
① 정답지 86행이 인식 결과 복사본        (280)
② 로고 표기가 장마다 다름               (278)
③ 팩스 칸이 비고 사무실에 팩스가 적힘    (282)
④ 직함의 자세함이 장마다 다름           (286)  ← 지금
```

📌 ①②③은 **재고 나서** 알았고, ④는 **재기 전에** 멈췄다. 그게 이번의 소득이다.

## 5. ✅ 사용자 확정 (2026-08-17) — **직함도 「인쇄된 그대로」**

회사 칸(추가 278)과 **같은 원칙**이다.

| 물음 | 답 |
|---|---|
| **가** 부서를 넣나 | **넣는다** — `경영지원팀 | 대리` |
| **다** 영문 병기 | **넣는다** — `CEO & Founder` |
| — 이름 | ⚠️ **뺀다.** 이름 칸이 따로 있다 |

→ 이름이 섞인 3장(`card_14`·`card_26`·`card_128`)은 **파서가 맞다.** 정답지를
고친다.

## 6. ⭐ 나(구분자)는 정답지가 아니라 **자를 고쳤다**

`card_20`의 명함에는 **`|`가 실제로 인쇄돼 있다**(사진으로 확인). OCR이 그걸
읽을 때도 있고 놓칠 때도 있을 뿐이다.

> ⚠️ **정답은 "명함에 뭐라고 쓰여 있나"이지 "인식이 뭘 읽을 수 있나"가 아니다.**

읽을 수 있는 것만 정답으로 적으면 **정답지가 파서를 따라가게 된다.** 그건 오늘
아침 씨앗값 문제(추가 280)와 **같은 자리**다. 그래서 **정답지를 되돌리지 않고
채점기가 칸막이 기호를 무시하게** 했다.

```
직함 66% → 68%     (일치 68 → 70, 정확히 card_20 · card_113 두 장)
전체 87% → 88%
⚠️ 다른 열 칸은 한 자리도 안 움직였다
```

### ⚠️ 자를 넓히는 일이라 좁게 넓혔다

| | |
|---|---|
| 무시한다 | `\|` · `·` · `｜` — **칸막이 기호만** |
| ⚠️ **안 지운다** | `/` — 칸막이가 아니라 **내용**이다(`영업대표/부장`, `Module/Pack개발그룹`, `https://`) |
| 안 지운다 | 글자 · 숫자 · 괄호 · 하이픈 |

📌 PM은 `/`까지 무시하자고 했지만 **근거가 없어 뺐다.** `/` 때문에 틀린 장은
실측에 없었고, `/`는 값의 일부인 경우가 더 많다. **근거가 있는 것만 넓힌다.**

**검사 넷으로 고정했다** — 칸막이는 무시되고, `/`·글자·숫자는 안 건드리고,
**서로 다른 값이 같아지지 않는다**는 것까지.

## 7. ⭐ 통일된 자로 잰 기준선 — **여기서부터다** (2026-08-17)

**무엇으로 쟀나**: 103장(사람이 전수 검수) · 정답지 = *"인쇄된 그대로"*로 통일 ·
채점기 = 칸막이 기호 무시.

```
이름 85% · 회사 66% · 직함 58% · 휴대폰 98% · 사무실 96% · 팩스 97%
이메일 94% · 홈페이지 100% · 우편번호 92% · 주소 92% · 상세주소 86%

전체 86% (808 / 937)
```

### ⚠️ 직함 68% → 58%는 **성능이 아니라 자가 바뀐 것이다**

**파서는 이 브랜치에서 한 줄도 안 고쳤다.** 그러니 10점 하락은 전부 정답지
통일 때문이다.

```
68%   자가 뒤죽박죽일 때 — 같은 명함인데 정답이 둘이었다
      (이정현 3장이 `상무(실장)` ↔ `상무(실장) 경영기획실`로 갈려 있었다)
58%   통일된 자로 잰 첫 값        ← 여기서부터
```

📌 **앞의 68%가 격차를 가리고 있었다.** 부서가 빠진 짧은 정답과 파서의 짧은
답이 **짝이 맞아** 맞은 것으로 세어졌다.

### 📌 오늘 네 번 다 같은 모양이었다

```
추가 280  정답지가 인식 결과 복사본이었다
추가 278  로고 표기가 장마다 달랐다
추가 282  팩스 칸이 비고, 사무실 칸에 팩스가 적혀 있었다
추가 286  직함의 자세함이 장마다 달랐다
```

⚠️ **넷 다 "파서와 정답지가 같은 실수를 함께 해서 만점이 나오던" 자리다.**
자를 고치면 숫자가 내려간다. **내려간 것이 나빠진 것이 아니다.**

## 8. 4단계(파서) — **세 번 시도해 셋 다 실패했다**

| 시도 | 결과 |
|---|---|
| ① 연락처 라벨 찌꺼기 제거 | **±0장** — 실제 데이터에 그 모양이 없었다 |
| ② 한글 직함 뒤 영문 꼬리 제거 | **−5장** |
| ③ **직함에 부서 붙이기** | **±0장** — `card_111`을 얻고 `card_122`를 잃었다 |

③이 목표였던 *"덜 가져옴 9건"*을 노린 것이다. **9건 중 1건만 잡혔다.**

⚠️ 나머지 8건은 **각자 다른 이유**로 막혀 있다.

```
card_121·32   정답 `Enterprise팀`, 원문 `Enterprise 팀`   ← 띄어쓰기가 달라 못 맞힌다
card_03·12    부서 줄이 이미 **회사 칸**에 들어가 있다      ← 빼 오면 회사가 손해
card_24·25    ⚠️ 줄 여섯으로 재현하면 맞는데 실제 전체 줄로는 안 맞는다
```

📌 **`card_24`·`25`가 이번의 교훈이다.** 앞 여섯 줄만 떼어 만든 입력에서는
**정확히 맞았는데** 실제 원문 전체로는 안 맞았다. 시도 ①과 **똑같은 함정**이다 —
**재현이 곧 실측은 아니다.**

## 9. 그래서 직함은 여기서 멈춘다

세 번 시도해 셋 다 0 이하다. **규칙 하나로 올릴 수 있는 자리가 아니다.**
남은 36건은 각자 다른 이유로 틀리고, 그중 상당수는 **OCR이 줄을 어떻게 끊었는지**에
달려 있다(R-03 쪽).

⚠️ **여기서 더 밀어붙이면 "맞을 때까지 규칙을 바꾸는" 일이 된다.** 오늘 그
함정을 네 번 봤다.
