## 1. 맡을 일 두 가지

### F-13 · 지도 기준 위치 직접 지정

**지금**: 거리 계산의 기준점이 항상 **내 현재 위치**다.

**바꿀 것**: 지도에서 **원하는 지점을 눌러 기준점으로 삼고**, 그 점 기준으로
주변 인맥 거리를 다시 계산한다.

왜 필요한가 — 테스터 요구다. 지금 있는 곳이 아니라 **내일 갈 곳 주변에 누가
있는지** 보고 싶다는 것이다. 출장·미팅 전에 "그 동네에 아는 사람 있나"를 보는
쓰임이다.

**미결(당신이 사용자에게 확인할 것)**
- 지정 방식: **탭인가 드래그인가**. 기획 문서에는 "드래그/탭"으로 둘 다 적혀 있다
- **되돌리기**: 내 위치로 돌아오는 버튼이 필요한가 (지금 `_MapButton`이 있다)
- **지속성**: 앱을 껐다 켜면 지정한 기준점이 남아야 하나, 아니면 매번 초기화인가
  → **남긴다면 저장이 생기고, 저장은 검증 등급이 올라간다**(3절 참고)
- 목록 화면(`radar_view.dart`)의 거리 표시도 함께 바뀌어야 하나, 지도에서만인가

### F-14 · 지도 제스처·Quick Action 통일

**지금**: 지도와 목록에서 **같은 동작이 다르게** 반응한다. 지도 핀은 `onTap`으로
바텀시트를 열고(`_showContactSheet`, 257행), 목록은 목록대로 다르다.

**바꿀 것**: 제스처와 빠른 동작(전화·문자 같은)의 규칙을 정리해 **지도와 목록이
같게** 만든다.

**이건 규칙을 먼저 적고 그다음 코드다.** 화면마다 고쳐 나가면 또 어긋난다.
**표를 먼저 만들어 사용자 승인**을 받아라.

⚠️ **길게 누르기에 빠른 동작을 얹지 마라.** 이 저장소는 이미 그렇게 결정해 뒀다
(2026-08-16 지도 세션이 실물에서 확인):

- `onLongPress`가 **저장소 전체에서 딱 한 군데**다(`radar_view.dart:1426`,
  위치 버튼의 감지 토글). 지갑 선택 모드도 길게 누르기가 아니라 **상단 버튼**이다
- 그 한 군데조차 **옆에 글자 설명을 붙여 놨다.** 주석에 이유가 있다 —
  *"길게 누르기는 눌러 보기 전에는 알 수 없는 동작이라 설명을 옆에 붙인다.
  툴팁만으로는 길게 눌러야 뜨는데, 그 자체가 길게 눌러야 아는 사람에게만 보인다."*

→ **빠른 동작은 눈에 보이는 버튼으로 통일한다.** 숨은 제스처에 얹으면 ① 발견이
안 되고 ② 설명 줄을 또 붙여야 하고 ③ E-11이 났던 자리에 제스처를 하나 더 얹게
된다.

📌 **초판에 PM이 예시로 적은 "탭=상세, 길게=빠른 동작"은 틀린 것이었다.**
예시로 던진 문구가 규칙처럼 굳을 뻔했다 — **인계 문서의 예시도 실물로 검증하라.**

## 3. ⚠️ 이 저장소에서 반드시 지킬 것

### 검증 종류를 **사용자에게 물어 고르게 하라**

사용자가 못박은 것이다(`CLAUDE.md` 4절). **묻지 않고 바로 돌리지 마라.**

```
이번 수정: <무엇을 고쳤는지 한 줄>

  전체 테스트 — 전 항목 실기기 (~1시간)      [배포 직전용]
  부분 테스트 — <이번에 볼 화면·영향 범위>   (~N분)  ← 권장
  자동 테스트 — flutter test/analyze (~수 초)

어느 것으로 할까요?
```

**F-13에서 기준점을 저장하기로 하면 등급이 올라간다** — 저장·복원은
**전체 테스트** 칸이다. 저장하지 않으면 부분 테스트로 끝난다. 그래서 1절의
"지속성" 미결이 일정에 영향을 준다.

### 실기기로 봐라. 테스트 통과는 동작 증거가 아니다

이 저장소에서 실제로 터진 결함은 **코드는 맞는데 실물이 틀린** 유형이었다.
바로 오늘도 세 건 나왔다(탈퇴 시 사진 미삭제 · 묘비 잔존 · `Wrap` 안
`Container`의 `alignment`가 최대 폭까지 늘어나 칩이 세로로 쌓임).

**지도는 특히 그렇다.** 제스처·좌표·줌은 위젯 테스트로 안 잡힌다.
실행 절차는 `.claude/skills/run-app/SKILL.md`에 있다(폴더블 화면 ID 함정 포함).

### 가짜 데이터를 만들지 마라

기준점 기능을 보여 주려고 **예시 인물·가짜 좌표를 넣지 마라.** 데이터가 없으면
빈 상태를 그대로 보여준다.

⚠️ **확인 못 한 것을 "확인했다"고 적지 마라.** 오늘 두 건이 그렇게 남았다 —
F-15는 같은 주소 짝이 없어 묶음 머리글을 못 봤고, F-10은 30일 초과 후보가 없어
섹션이 뜬 모습을 못 봤다. **못 본 것은 "미확인"으로 적어라.** 그게 배포 직전
전체 테스트의 확인 목록이 된다.

### 개인정보

로그에 이름·전화번호·주소를 남기지 마라. **좌표도 마찬가지다** — 위치는
개인정보다. 디버그 출력에 위경도를 찍지 마라.

## 4. 절차

1. **번호는 PM에게 받아라.** `backlog.md`의 "추가 N"을 스스로 집지 마라 —
   2026-08-15 하루에 세 번 겹쳤다. 완료 시점에 PM에게 요청하면 배정한다
2. **F 상태표(`tester-feedback-resolution-2026-08-14.md`)는 직접 고치지 마라.**
   완료 보고만 하고 갱신은 PM이 한다. 오늘 그 표가 세 줄 어긋난 원인이
   "코드 넣은 사람과 표 고치는 사람이 달랐던 것"이다
3. **`main`에 직접 커밋·푸시 금지.** 브랜치 → PR. 문서 한 줄이라도
4. **PR 병합·배포는 사용자 승인.** 커밋·푸시까지가 자율이다
5. **착수 전 `origin/main`을 새로 받아라.** 2026-08-15~16 이틀에 main이 스무 번
   넘게 움직였다

### 상의는 PM, 승인은 사용자

사용자가 정한 구조다(2026-08-15). **순서·범위·중복 조정·번호는 PM에게**,
**커밋·PR 병합·배포·정책 변경·검증 종류 선택은 사용자에게** 직접 올린다.
다른 세션이 전한 승인은 사용자 승인을 갈음하지 않는다.
