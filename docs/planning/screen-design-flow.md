# 화면설계 — 어디에 무엇을 두나 (2026-08-27 사용자 확정)

화면설계 문서가 **셋**이고, 각자 맡는 단계가 다르다. 섞이면 다음 사람이
**계획을 구현된 것으로 읽는다.**

## 흐름

```
① 화면설계 모음        단위 화면을 그려 쌓는 곳 — 작업장
       ↓  사용자가 보고 확정
② 화면설계서 · 계획     확정됐으나 아직 안 만든 것
       ↓  🚨 실기기에서 확인했을 때
③ 화면설계서 · 구현     실제로 동작이 확인된 것
```

**지금 앱과 맞는지** 보고 ⓐ 그대로 옮길 것 ⓑ 고쳐야 할 것 ⓒ 폐기된 것으로
가른다.

## 🚨 ②→③ 은 「코드를 짰을 때」가 아니라 「실기기에서 확인했을 때」다

**사용자 확정이고, 이유가 실물에 있다.**

2026-08-26 광고 수신 동의 화면에서 **결함이 둘이었는데 하나가 다른 하나를
가리고 있었다.** 실패 경로를 고치고 자동 테스트까지 통과시켜 *"통과"*로
보고했는데, **실기기에서 보니 성공 경로에 화면을 닫는 코드가 아예 없었다.**
그때까지 그 코드는 **한 번도 돌아 본 적이 없었다** — 앞의 결함이 항상
실패시켜 가려져 있었다.

> **코드를 짠 것은 「만들었다」이지 「된다」가 아니다.**

⚠️ **코드 기준으로 ③에 올렸으면 틀린 것을 「구현됨」이라고 적어 둔 셈이 된다.**

## 이 구조가 막는 것 — 이미 두 번 데였다

| 언제 | 무슨 일 | 방향 |
|---|---|---|
| 2026-08-26 | 설계서에 **폐기된 광고 동의 배치**가 남아 있었다 | 문서가 실물보다 **뒤짐** |
| 2026-08-26 | 설계서의 **내보내기 상단 액션 줄**이 실물에 없었다 | 문서가 실물보다 **앞섬** |

📌 **방향은 반대인데 원인은 같다** — *"이것이 계획인가 구현인가"*가 문서에
없었다. ②와 ③을 가르면 그 질문에 문서가 스스로 답한다.

## 함께 지키는 것 (2026-08-26 사용자 확정)

```
구현 전   화면을 어떻게 만들지 설계서에 그린다 → 사용자가 보고 확인
구현 후   실물에 맞춰 설계서를 보강한다
```

⚠️ **둘 다 필요하다.** 앞의 것만 하면 문서가 실물보다 앞서고, 뒤의 것만 하면
만들고 나서야 그림을 보게 된다.

## Figma·Canva 로 옮기는 것 — 아직 아니다 (2026-08-27 상의)

**공유해서 보는 것**은 캔버스 링크로 충분하다(계정 없이 브라우저로 열리고
화면마다 댓글이 달린다). **디자이너에게 편집을 맡길 때**는 Figma 가 맞는데,
`.dc.html` → Figma 자동 변환은 없어 **화면을 하나씩 다시 그려야 한다.**

⚠️ **설계가 확정되기 전에 옮기면 두 곳을 다 고치게 된다.** 어제만 해도
내보내기 배치와 광고 동의 화면이 각각 바뀌었다.

📌 **기존 Figma 파일은 비어 있다** — 기록에는 *"11화면 + 컴포넌트 + 토큰"*이
있다고 적혀 있었으나 **2026-08-15 실물 확인 결과 텍스트 2개뿐**이었다.
계획을 실물처럼 적어 둔 자리다. Figma 로 간다면 **채우는 것이 아니라 새로
만드는 것**이다.
