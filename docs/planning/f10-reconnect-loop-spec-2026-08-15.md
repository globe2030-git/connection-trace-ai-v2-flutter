# F-10 확정 스펙 — 재연락 루프 (A+C)

방향 확정 2026-08-15 (사용자, 지갑/과금 세션과 함께 잡음). F-10은 그동안
"방향 결정 선행"으로 대기하던 항목이고, **그 방향이 이제 확정됐다 — 이 결정
자체가 산출물이다.** 구현은 F 담당 세션(`connection-trace-ai-v2-flutter-52`) 몫.

**핵심**: AI 브리핑을 "말 만들어주는 도구" → **"관계 굴려주는 파트너"**로 확장.

```
A(누구+왜) → AI 브리핑(뭐라고, 기존) → 연락 → C(어땠나 한 탭) → 다음 시점 → 다시 A
```

**왜 급소인가**: 영업직의 1번 고통은 "무슨 말"이 아니라 "누굴 까먹었나". A는 매일
앱 여는 이유(리텐션 훅), C는 그 훅을 매일 똑똑하게 만드는 연료. **C의 실제 결과
데이터가 A의 우선순위를 정확하게 만든다** — 둘을 한 바퀴로 묶는 이유.

---

## A. 재연락 우선순위 (누구 + 왜)

- **배치**: '주변' 탭 상단 "오늘 연락하면 좋은 사람" 섹션.
- **정렬 = 기기 안 규칙** (AI 호출 없음, 서버 전송 없음, 투명). AI는 [연락 가이드]
  탭 시에만(기존 브리핑).
- **후보**: 마지막 소통일 **30일 초과** · 최근연락/스누즈 제외.
- **점수 = 방치도 + 근거강도 (+ C 후속 신호)**. 신호 출처: 소통기록 마지막 시점,
  메모, 태그, 등록 시점, + C 후속 기록.
- **이유 표시 — 실제 근거로만**:
  - Tier1(강): 구체 근거(메모/기록/C 후속) → "2주 전 통화 반응 좋았어요" / "5개월 전 통화 · 메모: '만기 8월'"
  - Tier2(약): 방치만 → "4개월째 연락 없음"
  - 데이터 전무: "한 번도 연락 기록 없음" (억지 스토리 ✗)
- **N = 하루 3명**. **스누즈**("이번엔 넘김" → 7일 뒤 재후보). **빈 상태 정직**
  (후보 없으면 "없어요", 최근 연락한 사람 억지로 끌어오지 않음).

## C. 연락 후 후속 (한 탭 · 선택 · 안 해도 됨)

- **트리거 = 연락 가이드 직후** (그 자리에서).
- 흐름: "연락 어땠어요?" [좋음][보통][없음] → [좋음]이면 "언제 다시?"
  [1주][2주][1달][안 정함]. **아무것도 안 눌러도 됨(닫으면 그만).**
- **저장**: 연락처별 `lastOutcome`/`lastOutcomeAt`/`nextFollowUpAt`. **기존 명함처럼
  암호화.**
- ⚠️ **C 강요 금지 — 한 탭·선택·스킵 가능. 못 지키면 C는 죽는다.**
- **C→A 되먹임(루프 핵심)**: `nextFollowUpAt`이 되면 A 상위 후보 + 이유 Tier1
  ("2주 전 반응 좋았어요"). 반응 "없음" 반복 → A에서 덜 자주. 즉 **A는 수동 신호로도
  돌지만, C가 쌓일수록 정확**해진다.

## 확정 결정 (전부 확정)

| # | 결정 | 확정값 |
|---|---|---|
| 1 | A 배치 | '주변' 탭 상단 "오늘 연락하면 좋은 사람" |
| 2 | N | 하루 3명 |
| 3 | 방치 임계 | 30일 |
| 4 | 중요표시 가중 | 1차 제외, 2차 검토 |
| 5 | 스누즈 | 포함, 7일 |
| 6 | C 결과 묻는 시점 | 연락 가이드 직후 |

## 가드레일

- **가짜 이유 금지** — 근거 없으면 지어내지 않음. C 후속도 사용자가 실제 누른 것만.
  ⚠️ **이 가드레일이 기능의 성패를 가른다.** A의 "이유"는 사용자가 그걸 보고 연락
  여부를 정하는 값이라, 근거 없는 문장이 하나라도 섞이면 기능 전체 신뢰가 무너진다.
- **C 강요 금지** — 한 탭·스킵. 안 해도 A는 돎.
- **개인정보** — A 리스트·이유는 기기 안. C 기록은 암호화. AI 전송만 기존 경계.
- **과장 금지** — N 작게, 스누즈, "당신을 기다려요" 류 ✗. 빈 상태 정직.
- ⚠️ **서버 데이터 정리 시 tombstone 주의** — 동기화가 tombstone 기반이라 서버만
  지우면 로컬이 도로 올라옴(정리 세션 인수인계). C 후속기록 삭제 설계 시 확인.

## 검증

- 규칙(우선순위·C 되먹임) = **자동 테스트**(날짜·메모·후속 조합 → 기대 정렬·이유).
- 화면(A 리스트·이유·빈 상태·스누즈, C 한 탭·시점) = **부분 테스트**.
- C가 저장·동기화를 건드리면 = **전체 테스트(실기기)** (저장·복원 변경).
- **⚠️ 회귀 방지 테스트를 처음부터** — 근거 없는 "이유"가 리터럴로 대입되는 것을
  소스 훑어 차단(`test/no_seeded_form_defaults_test.dart` 방식). PM 권고 반영.
  근거: 오늘 같은 유형 결함 둘을 잡음 — 태그 기본값 `'AI, IT'`, 메모에 박히던
  `'AI OCR 스캔으로 자동 추출된…'`. **둘 다 앱이 만든 문장이 사용자 데이터로 저장돼
  AI에까지 실려 나갔다.** A는 같은 실수가 더 치명적이다.
- 진짜 가치 = 테스터 피드백(이거 보고 실제 연락했나 · 매일 여나 · C 눌렀나) →
  리텐션 검증과 연결.
