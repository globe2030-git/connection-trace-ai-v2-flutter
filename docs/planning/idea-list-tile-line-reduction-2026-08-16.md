## 1. 지금 구조 (두 화면 동일)

```
공은성                     ← 이름   15pt 굵게
사업 1팀 I 과장             ← 직함   12.5pt
RAUM fax                  ← 회사   12.5pt
📍 경기도 성남시 …           ← 주소   (주변만)
```

- 주변 인맥: `radar_view.dart:1508~` — **최대 4줄**
- 명함 지갑: `wallet_view.dart:612~` — **최대 3줄**(주소 없음)

셋 다 `maxLines: 1` + `ellipsis`, 줄 간격 2~3px.

## 2. ⚠️ "이름 옆에 직함"의 문제 — 실제 데이터가 들쭉날쭉하다

기기에 등록된 명함에서 뽑은 직함 값이다.

| 실제 값 | 길이 |
|---|---|
| `과장` | 2자 |
| `사업 1팀 I 과장` | 10자 |
| `부사장 / R&D Center` | 17자 |
| **`대표 IG: www.instagram/ium-gallery`** | **33자** |

마지막은 **OCR이 직함 칸에 웹주소를 넣은 것**이다. 이런 값이 이름 옆에 오면
**이름이 밀려 잘린다**(`공은성` → `공은…`).

**명함 목록에서 이름은 잘리면 안 되는 정보다.** 나머지는 잘려도 누구인지
알아볼 수 있지만 이름이 잘리면 그 줄의 목적이 사라진다.

## 3. 권고 — **직함과 회사를 합친다**

```
공은성                          ← 이름 (그대로, 안 잘림)
사업 1팀 I 과장 · RAUM fax      ← 직함 · 회사
📍 경기도 성남시 …
```

| | 이름 옆에 붙이기 | **직함·회사 합치기** |
|---|---|---|
| 줄어드는 줄 | 1줄 | 1줄 (같음) |
| 이름 잘림 | ⚠️ 있음 | ✅ 없음 |
| 긴 값 처리 | 이름을 밀어냄 | 뒤쪽만 `…` |

**같은 효과를 얻으면서 이름을 안 건드린다.** 직함·회사는 원래 같은 성격(소속)
이라 묶이는 것이 자연스럽다.

⚠️ 합칠 때 **회사가 비어 있는 경우**를 처리해야 한다. 지금은 회사가 비면
`'회사 정보 없음'`을 표시하는데, 합친 줄에서 `과장 · 회사 정보 없음`은 어색하다.
직함만 남기는 편이 낫다.

## 4. ⚠️ 착수 전에 실측할 것 — 정말 줄어드나

**줄 하나가 빠져도 타일 높이가 눈에 띄게 줄지 않을 수 있다.** 줄 간격이 2~3px
이고, **아바타 크기가 타일 높이를 정하고 있을 가능성**이 있다. 그렇다면 글자 줄만
줄고 타일은 그대로여서 **얻는 것이 없다.**

→ **화면에서 먼저 재고 결정한다.** 이 저장소에서 반복된 "코드는 맞는데 실물이
다른" 유형을 피하는 방법이다.
