# 리멤버 설정 화면 실물 분석 — 우리와 무엇이 다른가 (2026-08-26)

## 0. 무엇을 봤나

사용자가 촬영한 **iOS 리멤버 설정 화면 녹화 86초**를 2초 간격 43프레임으로 뜯어
전부 확인했다. 아래 내용은 **화면에 적힌 문구를 그대로 옮긴 것**이고, 추측한
부분은 그렇게 표시했다.

🚨 **원본 영상과 프레임을 저장소에 들이지 않는다.** 사용자 본인의 계정 이메일·
휴대폰번호가 그대로 찍혀 있다. 이 문서에도 옮기지 않았다(마스킹).

---

## 1. 🚨 가장 큰 것 — `#`는 그룹 구분자가 아니다

이 분석을 시작한 계기는 *"리멤버는 `#`을 이름 앞에 구분자로 두고 그룹으로
묶어서 내보내더라"*였다. **실물은 다르다.**

```
설정 → 휴대폰 연락처에 저장 → 저장 옵션 설정

  「카카오톡 자동 친구 추가 방지」          [토글 — 꺼짐]
    이름 앞에 # 추가하여 저장합니다
```

📌 **`#`의 목적은 분류가 아니라 카카오톡 차단이다.** 카카오톡이 주소록에 있는
사람을 자동으로 친구로 추가하는 것을 막으려고 이름 앞에 `#`를 붙인다. 한국에서
널리 쓰이는 우회법이고, **기본값은 꺼짐**이다.

⚠️ **그러니 이것을 "겹치는 것을 구분하는 장치"로 가져오면 목적이 어긋난다.**
우리가 풀려던 문제(내보낸 것과 원래 있던 것이 섞인다)는 `#`로 안 풀린다.

### 그럼 리멤버는 무엇으로 구분하나 — **이름 형식**이다

같은 화면의 두 번째 줄:

```
  「연락처에 저장」   이름+직책(회사명)  >
    이름 항목에 이름 외 다른 정보를 함께 저장할 수 있습니다
```

즉 주소록의 이름 칸에 `홍길동 부장(가상상사)`처럼 저장한다. **동명이인도, 내가
넣은 것인지도 이름만 보고 알 수 있다.** `#`와는 별개의 장치이고, 이쪽이 우리
질문의 실제 답이다.

---

## 2. 내보내기가 **두 갈래**다 — 우리는 한 갈래만 생각했다

| | 리멤버 | 성격 |
|---|---|---|
| **휴대폰 연락처에 저장** | 구글 주소록 · 휴대폰 연락처 **각각** 자동 저장 토글 | **지속 동기화** |
| **내 명함첩 파일로 내보내기** | 엑셀(.xlsx) · 아웃룩 주소록용(.csv) · 휴대폰 연락처용(.vcf) | **일회성 파일** |

### 2-1. 동기화 쪽에 딸린 것들 (실물)

```
구글 주소록에 자동 저장   [켜짐]
  연락처 계정            g******@gmail.com      ← 어느 계정에 넣을지 고른다
  마지막 저장            2026-08-24 17:37:53
  명함 정보가 추가/수정되면 자동으로 업데이트됩니다.
  저장 옵션 설정 >
휴대폰 연락처에 저장     [켜짐]
  마지막 저장            2026-08-25 10:11:49
  [지금 업데이트하기]                          ← 수동 트리거도 따로 있다
```

📌 **"마지막 저장 시각"과 "지금 업데이트하기"가 있다는 것이 핵심이다.** 자동
동기화는 *"됐는지 안 됐는지"*를 이용자가 못 보면 불안해지는 기능이라, 그
불안을 시각 하나로 눌렀다.

### 2-2. 파일 쪽에 딸린 것들 (실물)

```
탭: [파일 생성] [파일 관리]

생성 중인 파일   파일 크기가 큰 경우, 여러 개로 나눠서 생성합니다.
                생성에 실패한 파일은 7일 후 자동 폐기됩니다.
생성된 파일     생성일로부터 최대 30일 보관됩니다.
                30일이 지나면 파일은 자동폐기됩니다.
                개인명함첩_2608161…   파일 유효기간 2026.09.15까지  [⤓]
```

⭐ **이 설계가 말해 주는 것: 리멤버는 파일을 서버에서 만든다.** 그러니
"보관 기간"과 "자동 폐기"가 필요하다. **제3자 개인정보가 담긴 파일이 서버에
30일 남는다는 뜻**이기도 하다.

📌 **우리는 기기에서 만들어 바로 공유하면 이 문제 자체가 없다.** 보관도
폐기도 유효기간도 필요 없다 — 만들고 넘기고 지우면 끝이다. **더 가벼운
쪽이 우리에게 이미 열려 있다.**

## 3. 계정 영역 — 우리와 축이 다르다

| | 리멤버 | 우리 |
|---|---|---|
| 계정 식별 | **이메일**(계정 관리에 이메일 하나) | 소셜 계정별 uid |
| 비밀번호 | **재설정 화면 있음**(현재/새/재입력, 영문·숫자·특수 중 2가지 이상 8자 이상) | 없음 — 자체 비밀번호가 없다 |
| 소셜 로그인 | **「간편 로그인 설정」에서 Naver·Google·Apple·카카오를 개별 토글** | 로그인 수단이 곧 계정 |
| 휴대폰번호 | **「휴대폰번호 변경」 — 현재 번호를 설정에 표시** | 없음 |
| 로그아웃 | 로그아웃 | 로그아웃 + **다른 기기 모두 로그아웃** |
| 탈퇴 | 리멤버 탈퇴 | 계정 삭제(회원 탈퇴) |

### 🚨 「간편 로그인 설정」이 우리 계정 식별 논의와 정면으로 닿는다

리멤버는 **소셜 수단을 붙였다 뗐다 할 수 있다.** 이는 계정의 주인이
**이메일(그리고 휴대폰번호)**이고 **소셜은 로그인 수단일 뿐**이라는 모델이다.

📌 우리가 검토 중인 A안(인증 이메일을 계정의 주인으로)과 같은 방향이고,
**리멤버는 그 모델을 화면으로 이미 구현해 두었다.** 계정 식별 매트릭스에
이 실물을 넣어야 한다.

### 🚨 「휴대폰번호 변경」은 I안을 하면 반드시 필요하다

전화번호를 계정의 주인으로 삼는 순간, **번호가 바뀌는 사람**을 위한 경로가
있어야 한다. 없으면 번호를 바꾼 이용자가 계정에 못 들어간다.

⚠️ 그리고 이것이 **번호 재사용(통신사 90일 회수)** 문제와 직접 맞물린다 —
바꾸기 전 번호가 다른 사람에게 갈 수 있으므로, 변경 시 **옛 번호의 로그인
권한을 즉시 끊어야** 한다.

## 4. 리멤버에 있고 우리에 없는 것 (검토 대상)

| 무엇 | 우리에 넣을 만한가 |
|---|---|
| **전화 수신 시 상대방 명함정보 표시** | ⚠️ 통화 상태 권한이 필요하다. 우리는 `READ_CALL_LOG`·`READ_PHONE_STATE`를 **정책 때문에 이미 뺐다**(추가 312). 넣으려면 그 결정을 뒤집어야 한다 |
| **암호 잠금 설정**(앱 잠금) | 📌 제3자 개인정보를 다루는 앱이라 **값이 크다.** 기기 잠금과 별개로 앱을 한 번 더 잠근다 |
| **서버와 정보를 다시 동기화하기** | 수동 재동기화. 우리도 동기화 실패 문의가 오면 필요해진다 |
| **화면 테마**(밝은/어두운/시스템) | 지금 우리는 고정이다 |
| **명함 촬영 시 내 명함 보내기** | 명함을 찍으면 상대에게 내 명함을 보내자고 권하는 흐름 |

## 5. 우리에 있고 리멤버에 없는 것

```
위치 서비스 · 위치정보 이용 안내 · 위치 이용 동의 철회   주변 인맥 기능이 우리에만 있다
AI 잔여 횟수 · AI 충전                                  과금 축이 다르다
다른 기기 모두 로그아웃                                  리멤버는 로그아웃만 있다
명함 데이터 "이 기기와 서버에 암호화하여 보관" 표시        보관 방식을 설정에서 말해 준다
```

📌 **마지막 줄은 우리가 앞서 있는 자리다.** 리멤버 설정에는 데이터를 어떻게
보관하는지 말해 주는 줄이 없다.

## 6. 검토 의견

### ① 구분자는 `#`가 아니라 **이름 형식 + 그룹(CATEGORIES)** 으로 간다

- `#`는 카카오톡 차단용이다. 그 목적이라면 **별도 기능으로** 두어야 하고,
  구분 목적에는 안 맞는다
- 구분은 **이름 형식**(이름+직책(회사명))이 실제로 하는 일이다
- 묶음은 vCard의 `CATEGORIES`가 표준 자리다 — ⚠️ **기기가 이것을 라벨로
  받아 주는지는 아직 안 쟀다**(문서 근거뿐)

### ② 카카오톡 자동 친구 추가 방지는 **따로 검토할 값이 있다**

우리 이용자도 명함으로 받은 사람이 **카톡 친구 목록에 자동으로 뜨는 것**을
원하지 않을 수 있다. 이것은 편의 기능이 아니라 **관계 노출** 문제다.
📌 다만 `#`가 실제로 그 효과를 내는지는 **카카오 쪽 동작에 달려 있고 우리가
통제할 수 없다** — 넣는다면 *"막아 준다"*가 아니라 *"이렇게 저장합니다"*로
사실만 적어야 한다.

### ③ 내보내기는 **일회성 파일부터**, 동기화는 나중에

동기화에는 삭제 전파·충돌·주기·계정 선택이 전부 딸려 온다. 리멤버가 그것을
"마지막 저장 시각 + 지금 업데이트하기"로 감싸고 있는 것이 그 무게의 증거다.

### ④ 파일을 **서버에서 만들지 않는다**

리멤버가 보관 기간·자동 폐기를 두는 이유는 서버에서 만들기 때문이다.
우리는 기기에서 만들어 바로 공유하면 그 부담이 통째로 없어진다.
⚠️ 대신 **임시 파일을 확실히 지워야 한다**(추가 247·253에서 두 번 겪은 자리).

### ⑤ 계정 화면 둘은 **계정 식별 결정과 묶어서** 본다

「간편 로그인 설정」과 「휴대폰번호 변경」은 지금 만들 것이 아니라, **A안/I안
결정의 입력값**이다. 계정 식별 매트릭스에 이 실물을 넣는다.

## 7. 사용자 결정이 필요한 것

```
① 카카오톡 자동 친구 추가 방지를 우리도 넣을까
② 이름 형식 옵션(이름+직책(회사명))을 내보내기에 둘까
③ 앱 잠금(암호 잠금)을 검토 대상에 올릴까
④ 전화 수신 시 명함 표시 — 뺐던 권한 결정을 뒤집을 만한가
```

추측한 부분은 본문에 그렇게 표시했다.*
