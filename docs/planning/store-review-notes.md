# 스토어 심사 제출 문안 (TestFlight 베타 심사 · App Store 정식 심사 공용)

App Store Connect의 "테스트 정보"와 심사 제출 화면에 **그대로 붙여넣는** 문안.
TestFlight 외부 테스트 베타 심사와 정식 출시 심사에서 묻는 것이 거의 같으므로
한 곳에서 관리한다.

> **왜 이 문서가 필요한가**: 우리 앱은 ① 소셜 로그인 없이는 아무 화면도 볼 수
> 없고 ② **제3자(명함 주인)의 개인정보**를 다루며 ③ 위치 권한을 쓴다. 심사자가
> 의문을 가질 지점이 여러 개라, 미리 설명하지 않으면 반려 위험이 높다.
> 실제로 흔한 반려 사유가 "심사자가 앱 기능에 접근할 수 없음"이다.

## 1. 베타 앱 설명 (TestFlight "테스트 정보")

```
커넥션센스는 명함을 촬영해 인맥을 등록하고, 실제로 그 사람 근처에 갔을 때
알려주는 앱입니다.

- 명함 스캔: 카메라로 명함을 찍으면 이름·회사·연락처를 자동으로 읽어 등록합니다.
- 주변 인맥: 등록된 명함 주소를 기준으로, 지금 내 위치에서 가까운 인맥을
  보여줍니다.
- AI 대화 가이드: 오랜만에 연락할 때 무슨 말을 꺼낼지 막막한 분을 위해,
  상대방 정보와 최근 소통 기록을 바탕으로 대화 포인트를 만들어 줍니다.
```

## 2. 테스트할 내용 (TestFlight "테스트할 내용")

```
이번 빌드에서 특히 확인해 주실 부분입니다.

1. 명함 스캔 정확도
   다양한 레이아웃의 명함을 찍어 보시고, 이름·회사·직함·연락처가 올바른
   칸에 들어갔는지 봐 주세요. 잘못 인식된 명함이 있으면 어떤 항목이 틀렸는지
   알려주시면 큰 도움이 됩니다.

2. 주변 인맥 화면
   명함에 주소를 입력한 뒤, 그 근처로 이동했을 때 목록에 뜨는지 확인해
   주세요. 거리가 실제와 크게 다르면 알려주세요.

3. AI 대화 가이드
   인맥 상세에서 "AI 대화 가이드"를 눌러 보세요. 나온 문장이 실제로 그 사람에게
   말할 만한지, 어색하지 않은지 봐 주시면 됩니다.

4. 전반적인 사용성
   버튼을 눌렀는데 반응이 없거나, 화면이 어색하거나, 무슨 뜻인지 모르겠는
   문구가 있으면 그대로 알려주세요.

※ 알려진 제약: 통화·문자·카카오톡 기록은 OS 정책상 자동으로 가져올 수 없어
   직접 입력하는 방식입니다.
```

```

  계정: (심사용 계정 입력)
  비밀번호: (심사용 비밀번호 입력)
```

## 6. ⚠️ 심사용 계정 — 먼저 만들어야 함

**심사 노트의 계정란을 비워 두면 반려된다.** 소셜 로그인만 있는 앱이라
심사자가 스스로 로그인할 방법이 없기 때문이다.

준비 방법:

1. 심사 전용 Google 계정을 하나 만든다(개인 계정을 쓰지 말 것 — 비밀번호를
   Apple에 제공하게 된다).
2. 그 계정으로 앱에 로그인해 **테스트용 명함을 3~5건 등록**한다.
   화면이 비어 있으면 심사자가 기능을 확인할 수 없어 그것만으로도 반려된다.
3. 주소를 넣은 명함을 하나 이상 만들어 "주변 인맥"이 동작하는 것을 보이게 한다.
4. 계정/비밀번호를 위 심사 노트에 채워 넣는다.

> ⚠️ **가짜 인물 정보를 만들지 않는다**(CLAUDE.md 4번). 심사용 데이터도
> 실제 존재하는 사람처럼 꾸미지 말고, 명백히 테스트용임이 드러나는 이름
> (예: "테스트 김", "샘플 회사")을 쓴다.

> ⚠️ 2단계 인증이 켜진 계정은 심사자가 로그인하지 못한다. 심사용 계정은
> 2단계 인증을 끄거나, 앱 비밀번호를 제공해야 한다.

## 7. 반려 위험이 있는 지점 (미리 알아둘 것)

| 지점 | 왜 걸리나 | 대응 |
|---|---|---|
| 심사자 로그인 불가 | 소셜 로그인 전용 | 6번 심사용 계정 |
| 빈 화면 | 데이터 없이 기능 확인 불가 | 명함 3~5건 미리 등록 |
| 위치 권한 목적 불명확 | 제3자 정보 + 위치 조합은 심사자가 민감하게 본다 | 심사 노트에 "서버 미전송" 명시 |
| **Sign in with Apple 미구현** | Google 로그인을 제공하면 Apple 로그인도 제공해야 한다(가이드라인 4.8) | 코드는 구현돼 있으나 **Firebase에 Apple 제공사 등록이 아직 안 됨(P0-2)** — 정식 심사 전 반드시 완료 |
| 개인정보처리방침과 실제 동작 불일치 | 즉시 반려 사유 | 방침은 코드 전수 조사 기반으로 작성됨(추가 75) |

**P0-2(Apple 로그인)는 정식 심사 전 반드시 끝내야 한다.** 가이드라인 4.8은
제3자 소셜 로그인을 제공하는 앱에 Sign in with Apple도 제공하도록 요구한다.
TestFlight 베타 심사는 이 항목을 보지 않을 수 있으나, 정식 심사에서는 걸린다.
