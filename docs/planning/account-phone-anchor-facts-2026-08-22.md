# I안(전화번호 앵커) 판단용 사실 확인 메모 — 2026-08-22

> **위치**: 계정 구조 I안(전화번호로 사람을 묶는 안) 채택은 사용자 결정
> 대기다. 이 문서는 그 판단에 필요했던 **미확인 사실 셋의 조사 결과**다 —
> 결정이 아니라 사실 확인. 배경은
> [`account-identity-matrix-2026-08-21.md`](./account-identity-matrix-2026-08-21.md)
> (I안은 "휴대전화번호를 받지 않는다"는 기존 결정을 뒤집는 안이므로
> 사실관계가 정확해야 한다).
>
> 조사 방법: 공식 문서를 직접 열어 원문 인용. **네이버 개발자센터는 접근
> 차단으로 1차 문서를 끝내 못 열었다** — 해당 부분은 미확인으로 남기고
> 2차 출처·저장소 콘솔 채록으로만 보강했다.

## 1. 카카오 `phone_number` — "인증된 번호"인가

**확인된 사실** (공식 문서 원문):
- 정의: *"카카오계정과 연결된 **카카오톡에 등록된 전화번호**"*. 주의:
  *"카카오톡 미사용자인 경우 **수집 불가**"*.
- 형식: 국내 `+82 00-0000-0000`, 해외는 형식 상이.
- 제공 조건: **비즈 앱 이상** + "개인정보 동의항목" 심사(회원가입 페이지의
  실제 수집 항목과 일치해야 통과, 영업일 3~5일, 사업자 업체명 기재).

⚠️ **문서 어디에도 "인증된 번호"라는 단어는 없다.** "카카오톡 등록
번호"까지가 원문이고, 카카오톡 가입 시 SMS 인증을 거친다는 것은 일반
지식이지 이 문서의 보장이 아니다(계산과 실측을 가르는 원칙대로 구분).
개인 개발자(사업자 미등록)의 심사 통과 가능 여부도 원문 미확인.

확신도: 정의·형식·심사 요건 **높음** / "인증됨" 여부 **미확인**.
**I안 영향**: 앵커 후보는 되지만 **비즈앱+심사 통과가 관문**이고, 카카오톡
미사용자에게선 아예 못 받는다.

출처: developers.kakao.com/docs/ko/kakaologin/utilize · …/kakaologin/rest-api
· devtalk.kakao.com/t/faq/132333 · …/app-setting/app

## 2. 네이버 `mobile` — 제공 조건

**확인된 사실**:
- ⚠️ **1차 문서(profile.md) 미확인** — 접근 차단. "인증된 번호"라는 근거를
  확보하지 못했다.
- 2차 출처: 프로필 응답에 `mobile`·`mobile_e164` 필드 존재(공식 스키마를
  옮긴 라이브러리 타입 정의).
- 콘솔 실물 채록(추가 368): "제공 정보"에 휴대전화번호가 선택 항목으로
  존재(현재 앱은 A안으로 제외). 검수 가이드: *"조회 권한을 선택한 정보는
  **모두 활용 사례를 확인**"* — 받으려면 사전 검수 소명 필요.

⚠️ **전례 경고**: 네이버 "이메일"이 비고유 연락처 값임은 문서가 아니라
**콘솔 안내가** 알려 줬다(추가 368). mobile도 같은 함정이 있을 수 있다 —
**콘솔에서 휴대전화번호 항목을 선택해 안내 문구를 실물로 보기 전에는
성격을 단정하지 않는다.** 이것이 I안 판단의 선행 조건이다.

확신도: 필드 존재 **중** / 인증 여부·제공 조건 **미확인**.

## 3. Firebase Auth — 전화번호 제공자 link

**확인된 사실** (공식 문서 원문):
- **가능하다** — `User.linkWithCredential`이 PhoneAuthCredential을 받는
  것이 API 계약(전화 전용 예외 코드가 명시됨).
- **번호는 계정당 유일** — 이미 다른 계정에 있으면
  `credential-already-in-use`로 실패(자동 병합 없음). 원문 경고: 전화
  credential은 이 오류에서 *"recover할 수 없다"*.
- **비용**: Phone Auth는 SMS 발송 건당 과금, **Spark(무료) 불가 — Blaze
  필요**, 무료 SMS 한도 없음. 실기기·웹에서만 동작(에뮬레이터 불가).

미확인: **커스텀 토큰(카카오·네이버) 계정에의 link** — 계정 유형 제한
언급이 없다는 간접 근거뿐, 실물 검증(테스트 계정 link) 전에는 단정하지
않는다. 한국행 SMS 단가 표 원문도 미확인.

확신도: link 가능·중복 실패·Blaze 필요 **높음** / 커스텀 토큰 link
**중(간접)** / 단가 **미확인**.
**I안 영향**: 번호의 계정당 유일성은 앵커에 오히려 유리하지만, **SMS
과금(Blaze) + "이미 남의 계정에 있는 번호" 충돌 설계 + 커스텀 토큰 계정
실물 link 검증**이 선행돼야 한다.

출처: pub.dev firebase_auth User.linkWithCredential ·
firebase.google.com/docs/auth/flutter/account-linking · …/phone-auth ·
firebase.google.com/pricing

## 남은 확인 방법 (결정 전 필요하면)

```
⑴ 카카오 "인증" 여부      데브톡 문의 또는 실제 심사 신청으로만 확정
⑵ 네이버 mobile 성격      콘솔에서 항목 선택 → 안내 문구 실물 확인 (사용자 콘솔)
⑶ 커스텀 토큰 계정 link    테스트 계정으로 실물 검증
⑷ 한국행 SMS 단가         Identity Platform 가격 페이지 브라우저 열람
```
