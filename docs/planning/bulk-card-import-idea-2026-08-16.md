# 명함 대량 등록 — 아이디어 기록

**작성**: 2026-08-16 (PM 세션)
**상태**: **기록만. 착수하지 않음**(사용자 지시)
**계기**: 유료 저장 확장(₩2,000) 검토 중 **순서가 뒤집혀 있다는 것**이 드러났다.

---

## 1. 어떻게 나왔나

사용자가 *"충전 상한 2,000장 + 2,000~5,000장 구간 1회성 ₩2,000"*을 제안했다.
손익을 대조하다 **아무도 그 상품을 살 수 없다**는 것이 드러났다.

⚠️ **2,000장에 도달할 방법이 없다.** 코드로 확인했다:

| | |
|---|---|
| 일괄 스캔 화면(`ocr_batch_scan_view.dart`) | **명함을 저장하지 않는다** — 파싱 결과를 표로 보여줄 뿐(`addContact`·`saveEncryptedCardImage` 호출 0) |
| 그 화면 | **진입 경로가 코드에 없다** — 관리자용이고 사실상 닫혀 있다 |
| `pickMultiImage` | 그 관리자 화면에서만 쓰인다 |
| CSV·연락처 가져오기 | **없다** |
| `vcard_util.dart` | **QR 프로필 교환용**이지 가져오기가 아니다 |

**일반 사용자는 한 장씩 찍거나 고르는 것뿐이다.**

```
2,000장 = 하루 1장씩 5.5년 = 월 3장이면 55년
```

→ **매출을 만들려면 상품이 아니라 대량 등록 기능이 먼저다.**

## 2. 그런데 이건 매출 장치보다 훨씬 큰 건이다

**영업 10년차가 기존 명함첩을 옮기는 온보딩 경로**다.

- 손익 3번의 핵심 타겟(**보험설계사 71만 · 자동차 영업 3만**)에 정확히 닿는다
- 지금은 **가입한 사람이 명함 1,000장을 들고 있어도 한 장씩 찍어야 한다.**
  그 벽 때문에 안 쓰는 사람이 있을 수 있다(미확인)
- 마케팅의 "비치헤드" 전략과 맞물린다

**한도 상품은 이 기능이 생긴 뒤에야 의미가 생긴다.**

## 3. ⚠️ 착수 전에 확인할 것 — "정말 그 벽 때문인가"

**우리는 모른다.** 표본이 **1명·16장**뿐이다.

이 저장소가 반복해 다친 유형이다 — *"있어야 할 것 같아서" 만든 기능이 실제로는
안 쓰이고, 진짜 문제는 다른 데 있었다.* 착수 전에 **테스터에게 물어보는 것**이
싸다.

## 4. 만든다면 — 걸리는 것들

| | |
|---|---|
| **인식 품질** | 한 장씩 찍을 때도 이름 100/103·주소 85/103이다(추가 202). 대량이면 **틀린 값이 대량으로 들어온다** — 검수 화면이 필수다 |
| **저장 비용** | 1,000장을 한 번에 올리면 **한도(300/2,000)에 즉시 닿는다.** 한도 설계와 함께 봐야 한다 |
| **처리 시간** | 1,000장 OCR은 기기에서 오래 걸린다. 중단·재개가 필요하다 |
| ⚠️ **개인정보** | 명함첩 전체를 한 번에 올리는 것은 **제3자 정보를 대량으로** 다루는 것이다. 수집 항목·목적은 이미 고지돼 있으나, **양이 달라지면 안전성 확보 조치를 다시 봐야 한다** |
| **관리자 화면 재사용** | `ocr_batch_scan_view.dart`가 이미 파싱까지 한다. **저장·검수를 붙이면 되므로 처음부터 만들지 않아도 된다** |

## 5. 정리

| | |
|---|---|
| **가치** | 온보딩 경로. 핵심 타겟에 직접 닿는다 |
| **선행 확인** | *"정말 그 벽 때문에 안 쓰나"* — 테스터에게 물어보기 |
| **재사용 가능** | 관리자 일괄 스캔 화면에 저장·검수를 붙이는 방향 |
| **함께 볼 것** | 한도 설계(`card-photo-storage-cost-spec-2026-08-16.md`), 유료 확장 상품(보류) |

**사용자 지시로 지금은 기록만 남긴다.**

## 6. 갈래 둘 — 직접 촬영 vs **다른 앱에서 가져오기**

사용자 제안(2026-08-16): *"리멤버에 등록된 명함을 받을 수 있는 방법도."*

**이게 더 큰 갈래일 수 있다.** 영업 10년차의 명함은 **이미 리멤버에 들어가 있을
가능성이 높다.** 그 사람에게 "다시 찍으세요"는 답이 아니다.

### ✅ 확인됐다 — 리멤버는 내보내기를 지원한다 (2026-08-16, 실물 확인)

사용자가 **PC 웹에서 실제로 내보내 받은 파일**을 확인했다.

**"파일 내보내기" → 파일 유형 3가지**

| 형식 | |
|---|---|
| 엑셀(`.xlsx`) | 받은 실물로 구조 확인 |
| CSV(`.csv`) | |
| **휴대폰 연락처용(`.vcf`)** | ✅ **vCard다 — `vcard_util.dart`의 `decode()`가 이미 있다** |

**실물 구조**(개인정보 값은 열지 않고 열 이름과 건수만 확인): **13열 × 50건**

### 열 매핑 — 우리 필드와 거의 그대로 맞는다

| 리멤버 | 우리 `ContactModel` | |
|---|---|---|
| 회사 | `company` | ✅ |
| 이름 | `name` | ✅ |
| 부서 | `title`에 합침 | ⚠️ 우리는 부서 필드가 따로 없다(`직함/부서` 한 칸) |
| 직함 | `title` | ✅ |
| 전자 메일 주소 | `email` | ✅ |
| 근무지 주소 번지 | `address` | ✅ |
| 근무처 전화 | `officePhone` | ✅ |
| 근무처 팩스 | `fax` | ✅ v2.1에서 추가해 둔 필드 |
| 휴대폰 | `phone` | ✅ |
| 명함 등록일 | — | 참고용. 우리 `createdAt`에 넣을지 결정 필요 |
| 명함첩 이름 | — | 리멤버 내부 개념. 버린다 |
| 그룹 | `tags` | 후보 |
| 메모 | `memo` | ✅ |

**막히는 곳이 거의 없다.** `직통전화`·`웹사이트`는 리멤버 내보내기에 없으니 빈 값이 된다.

### ✅ `.vcf` 실물 분석 (2026-08-16) — 구조가 완전히 파악됐다

받은 파일: **50장 · 12KB · vCard 3.0**(우리 `VCardUtil`과 **같은 버전**).

**들어 있는 항목**

| 항목 | 몇 장 | 우리 매핑 |
|---|---|---|
| `N` | 50 | `name` ⚠️ **아래 참고** |
| `ORG` | 50 | `company` |
| `TITLE` | 50 | `title` |
| `EMAIL` | 50 | `email` |
| `ADR` | 50 | `address` |
| `TEL;TYPE=WORK,CELL` | 50 | `phone`(휴대폰) |
| `TEL;TYPE=WORK` | 50 | `officePhone` |
| `TEL;TYPE=WORK,FAX` | 50 | `fax` |

**전화가 타입으로 정확히 나뉘어 온다.** 휴대폰·근무처·팩스가 각각 구분돼 우리
세 필드에 그대로 들어간다.

### ⚠️ 우리 `decode()`로는 지금 못 읽는다 — 세 가지를 고쳐야 한다

`vcard_util.dart`의 `decode()`는 **QR 프로필 한 장**을 읽으려고 만든 것이라,
이 파일에 그대로 쓰면 **이름이 전부 비어 나온다.**

| | 문제 | 고칠 것 |
|---|---|---|
| **1** | `FN`만 이름으로 읽는데 **이 파일에는 `FN`이 없다**(`N`만 있다) | `N`도 읽는다. `N`은 `성;이름;…` 5칸 구조인데 **리멤버는 2번째 칸에 전체 이름**을 넣는다 |
| **2** | `TEL`을 `putIfAbsent`로 **첫 번째만** 받는다 | `TYPE`을 보고 **휴대폰·근무처·팩스로 나눈다.** 안 그러면 3개 중 1개만 남고 팩스가 전화로 들어갈 수 있다 |
| **3** | 한 장만 파싱한다(`Map` 하나 반환) | **`BEGIN:VCARD`~`END:VCARD` 반복**을 처리해 50장을 읽는다 |

**셋 다 `vcard_util.dart` 안에서 끝난다.** 기존 QR 경로를 깨지 않으려면 **새
함수를 더하는 편**이 안전하다(`decodeAll()` 같은).

### ⚠️ 사진은 안 온다 — 확정

`PHOTO` 항목이 **한 장에도 없다.** 엑셀에도 사진 열이 없었으니 **리멤버 내보내기는
텍스트만** 준다.

→ **가져온 명함은 사진이 없는 상태**가 된다. 사용자에게 **가져오기 전에** 알려야
한다. 나중에 사진만 따로 붙이는 경로가 필요할 수 있다.

### ⚠️ 주소가 한 칸에 통째로 들어온다 — **이게 가장 큰 문제다**

`ADR`은 표준이 7칸(`사서함;상세;거리;도시;시도;우편번호;국가`)인데, **리멤버는
2번째 칸 하나에 주소 전체**를 넣는다(50장 중 48장. 2장은 주소가 비어 있다).

우리는 `address`(도로명) + `addressDetail`로 나뉘고, **그 주소로 좌표를 구해
(지오코딩) '주변 인맥'에 띄운다.**

**한 덩어리 주소가 지오코딩되는지 확인해야 한다.** 안 되면 **50장이 들어와도
주변 인맥에 하나도 안 뜬다** — 이 앱의 핵심 기능이 죽은 채로 가져오는 셈이다.

→ 착수 전에 **그 주소 형식 몇 개를 실제 지오코딩에 넣어 보는 것**이 첫 검증이다.

### ⚠️ 엑셀에만 있고 vCard에 없는 것

`메모` · `그룹` · `명함 등록일` · `명함첩 이름`이 **vCard에는 없다.**

**메모를 살리려면 CSV/엑셀 경로가 필요하다.** 다만 vCard가 파싱이 훨씬
간단하고 표준이라, **1차는 vCard로 하고 메모가 필요하다는 요구가 나오면 CSV를
더하는** 순서를 권한다.

### 그 밖에 확인이 남은 것

1. **명함 사진이 나오는가** — 열 목록에 **없다.** 텍스트만 오는 것으로 보인다.
   그러면 **가져온 명함은 사진이 없는 상태**가 된다. 사용자에게 그 사실을 알려야
   하고, 나중에 사진만 따로 찍어 붙이는 경로가 필요할 수 있다
2. **이용약관이 반출을 막는가** — 내보내기 기능을 리멤버가 **공식 제공**하므로
   반출 자체는 정상 경로다. 다만 **재배포·상업적 이용** 제한이 있는지는 확인이
   필요하다(우리는 이용자 본인 기기로 옮기는 것이라 해당 없을 가능성이 높다)
3. **주소 형식** — "근무지 주소 번지" 한 칸이다. 우리는 `address`+`addressDetail`로
   나뉘고 **좌표 변환(지오코딩)**이 붙는다. 가져온 주소가 지오코딩되는지 봐야
   한다 — 안 되면 **주변 인맥에 안 뜬다**

### 경로 후보 — 위험 순

| | 방법 | 판단 |
|---|---|---|
| **B** | **`.vcf`(vCard)를 읽는다** | ✅ **1순위.** 리멤버가 공식 지원하는 형식이고 `vcard_util.dart`의 `decode()`가 **이미 있다**. 표준이라 다른 앱에서도 통한다 |
| **A** | **`.csv`를 읽는다** | ✅ 2순위. 열 매핑이 확인됐다(위 표). 엑셀(`.xlsx`)은 파싱 의존이 늘어 CSV가 낫다 |
| **C** | 화면을 캡처해 OCR로 읽는다 | ⚠️ 부정확하고 사용자가 수백 번 캡처해야 한다 |
| **D** | 계정을 연동해 자동으로 긁어온다 | ❌ **하지 않는다** — 아래 참고 |

### ❌ D를 하지 않는 이유

**타사 계정으로 로그인해 데이터를 긁어오는 것(스크래핑)은 하지 않는다.**

- 대개 **이용약관 위반**이고, 이용자 계정이 정지될 수 있다
- 이용자에게 **타사 비밀번호를 입력받게 된다** — 우리가 절대 하지 않는 일이다
- 상대 서비스가 화면을 바꾸면 조용히 깨진다
- **법적 분쟁 위험**을 이용자와 회사가 함께 진다

**"사용자가 자기 데이터를 내보내고, 우리는 그 파일을 읽는다"**는 선을 넘지 않는다.

### ⚠️ 법적으로 짚을 것

**명함 주인 입장에서는 처리자가 하나 늘어난다.** 이용자가 자기 명함첩을 옮기는
것이지만, 그 안의 정보는 **제3자(명함 주인)의 것**이다.

- 우리 방침의 수집 항목·목적은 **이미 고지돼 있다**(명함 촬영·스캔으로 수집).
  **"파일로 가져오기"라는 수집 경로가 그 서술에 들어가는지** 법무 확인이 필요하다
- 양이 달라지면 **안전성 확보 조치**를 다시 봐야 한다
- 개인정보 보호법 §35-2(전송요구권) 맥락과도 닿는다 — **이용자가 자기 데이터를
  옮길 권리**는 오히려 우리 편이다

### 재사용할 수 있는 것

| | |
|---|---|
| `vcard_util.dart` `decode()` | **이미 있다.** 지금은 QR 프로필 교환용이지만 vCard 파싱 자체는 같다 |
| `ocr_batch_scan_view.dart` | 파싱 결과를 표로 보여주는 **검수 화면**이 이미 있다 |
| `share_plus` | 있다. **파일 선택**은 없다 — `file_picker` 계열이 필요하다 |

### 이 갈래가 큰 이유

**경쟁 앱에서 갈아타는 경로**다. 마케팅의 비치헤드 전략(보험설계사)에서
*"쓰던 것 버리고 처음부터"*는 가장 큰 벽인데, 그 벽을 없앤다.

다만 **§3의 경고가 그대로 적용된다** — *"정말 그 벽 때문에 안 쓰는지"*를 먼저
물어야 한다. 표본이 없다.
