# 지갑(과금) 테스터 배포 런북 (2026-08-14)

목표: **AI 크레딧 지갑을 테스터 기기에서 실제로 써보게 하는** 배포 절차.
안전하게 "잠든 채 배포 → 플래그로 켜기 → 문제 시 즉시 끄기" 방식.

**원칙**: 되돌리기 쉬운 스위치(플래그)를 활성화 수단으로 삼는다. 배포·플래그
켜기·스토어 출시의 go/no-go는 **전부 사용자 최종 결정**(최상위 지침).

표기: 🔒 = **사용자 게이트**(사용자만 실행/승인) · 🤖 = 내가 준비/실행 가능.

---

## 0. 왜 이렇게 하나 — 핵심 3줄

1. 테스터는 **실서버(Firebase) 하나**를 공유한다. 지갑 rules/functions를 배포하면
   전 테스터에 영향이 갈 수 있다.
2. 그래서 **`config/billing.model` 플래그**로 켜고 끈다 — `reset`이면 코드가 올라가도
   **동작은 그대로**(테스터 영향 0), `wallet`로 바꾸는 순간 활성화.
3. 문제가 있으면 플래그를 **다시 `reset`**으로 → 즉시 원복. (단 §6 데이터 주의)

## 1. 선행조건 체크리스트 (전부 충족 후 진행)

| 조건 | 상태/담당 |
|---|---|

| Firebase Blaze 요금제(Functions 배포 가능) | ✅ 이미 전환됨(HANDOFF 0-5) |

| 배포 전 서버 실물 백업(현 rules·functions 스냅샷 = main 커밋) | 🤖 커밋 해시 기록 |

## 2. 단계별 절차

### Phase A — 엔진 완성 · 병합 (배포 아님)
1. 🤖 U3·U5·U7뼈대·계측 완성, 자동+부분 검증, `feat/ai-credit-wallet` 커밋·push.
2. 🔒/🤖 D22 순서로 최신 origin/main에 rebase → **main 병합**(관리자 하드닝·F-07
   보존 확인). *병합 자체는 코드일 뿐 — 테스터 영향 없음.*
3. 🤖 병합 직전 main 커밋 해시를 **롤백 기준점**으로 기록.

### Phase B — 코드 배포 (잠든 채, `model='reset'`)
> 이 단계에서 지갑은 **작동 안 함**. 동작은 배포 전과 동일해야 한다.
1. 🤖 `config/billing.model`이 **`reset`인지 확인**(안 켜져 있어야 함).
2. 🔒 서버 배포 승인·실행:
   ```bash
   firebase deploy --only functions,firestore:rules
   ```
3. 🤖 배포 후 검증: 기존 AI 브리핑·사용량 동작이 **배포 전과 동일**한지(reset 모드),
   신규 규칙(`creditGrants`·`deviceLedger`)이 서버에서 평가되는지(`verify_rules.py`를
   실서버 대상으로). **테스터 체감 변화 0**이어야 정상.

### Phase C — 테스터 앱 배포
> 지갑 코드가 든 빌드를 테스터 폰에. 아직 `reset`이라 화면 변화 없음.
1. 🤖 **Android** 릴리스 빌드:
   ```bash
   tool/build_app.sh android --release   # 커밋 해시 임베드(설정→앱버전 확인용)
   ```
   → 🔒 Firebase App Distribution으로 테스터 그룹 배포(무료).
2. 🔒 **iOS**: 403 해소 후 TestFlight 업로드(미해소면 이 단계 건너뛰고 Android 먼저).
3. 🤖 테스터가 새 빌드 설치 확인(설정→앱 버전 = 방금 커밋 해시).

### Phase D — 플래그 켜기 = 진짜 go/no-go 🔒
> **이 스위치가 지갑을 실제로 켠다. 전 테스터 동시 적용.**
1. 🔒 관리자 콘솔에서 `config/billing.model` = **`wallet`** 전환.
2. 즉시 발생: 신규/기존 테스터에 무료체험 10회 지급(`bootstrapAccount`), 사용 시
   잔여 차감, 5회 미만 충전 안내, 리퍼럴 코드 발급.
3. 🤖 켠 직후 스모크 체크(§5).

### Phase E — 관찰 (수 일)
1. 🤖 `aiAuditLogs`·`creditGrants`·`creditGrantAudits` 모니터, 오류율, 테스터 피드백.
2. 🤖 §7 검증 항목 실측(무료 10회 지급/차감/잔액표시/리퍼럴/무한증정 가드).

### Phase F — 판단
- 정상 → 과금 UX·가격 실사용 데이터 축적, 스토어 출시 준비(별도 🔒 게이트).
- 문제 → §6 롤백 후 수정·재배포.

## 4. 되돌리기(롤백)

| 무엇이 문제 | 롤백 |
|---|---|
| 지갑 동작 이상 | 🔒 플래그 `wallet`→**`reset`** (즉시 잠듦, 가장 빠름) |
| 서버 rules/functions 자체 문제 | 🔒 롤백 기준점(Phase A-3) 커밋에서 `firebase deploy` 재실행 |
| 앱 빌드 문제 | App Distribution에서 이전 빌드로 롤백 안내 |

⚠️ 플래그를 `reset`으로 되돌려도 **이미 지급·차감된 회차 원장(creditGrants) 기록은
남는다** — 켜져 있던 동안의 데이터는 그대로다. 다시 켜면 그 상태에서 이어진다.

## 5. 켠 직후 스모크 체크 (5분)
- [ ] 새 계정 로그인 → 무료체험 **10회** 지급되나(`bootstrapAccount`)
- [ ] AI 브리핑 1회 → 잔여 **9회**로 차감되나
- [ ] 잔여 5회 미만 → 충전 안내 뜨나
- [ ] 리퍼럴 코드 발급·표시되나
- [ ] 오류 로그 급증 없나

## 6. 확장 검증 (수 일, 파일럿 계측과 연동)
- [ ] 무한증정 가드(`deviceLedger`): 탈퇴→재가입 시 무료체험 재지급 안 되나
- [ ] 리퍼럴: 초대→활성화 시 양쪽 +5회, 상한 동작
- [ ] 사용 분포·활성화율·리텐션(파일럿 지표) 수집되나
- [ ] 개인정보 로깅 없나(값 대신 유무/카운트)

---

## 7. 리스크 & 주의
- **단일 백엔드**: 개인별 켜기 없음 — 플래그는 전 테스터 동시 적용. 소수 테스터
  그룹으로 시작 권장.
- **firestore.rules 배포는 즉시 적용**: 신규 규칙은 additive(신규 컬렉션 서버전용)라
  기존 동작 파괴 없어야 하나, 배포 전 `verify_rules.py`로 재확인.
- **결제(IAP)는 이 런북 밖**: U7 실연동·스토어 상품ID는 별도 게이트. 이번 테스터
  검증은 무료체험·회차·리퍼럴 로직까지(실결제 제외).
- **과장·개인정보 금지** 원칙 유지.
