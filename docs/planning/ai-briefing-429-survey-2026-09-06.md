## 2. ① 429 의 정체 — **「월 한도」 가설은 데이터가 반박한다**

⚠️ **이 가설은 내가 냈다.** [추가 710]에서 `index.ts:266` 의 주석
(*"하루 20회를 5일 채우면 **여기에 먼저 걸린다**"*)을 보고 **월 한도일 수 있다**고
적었다. **재보니 아니었다.**

```
월 한도라면   달이 갈수록 쌓이므로 **뒤로 갈수록 429 가 늘어야** 한다
실제          🚨 **정반대다** — 08-07 에 14건으로 시작해 08-12 에 끝난다
              그 뒤 14일(08-13~08-26) 동안 **한 건도 없다**
```

⭐ **모양이 정반대라 이 하나로 갈린다.** 📌 **주석이 예고한 것은 「테스트가 길어지면」
이었는데, 테스트가 길어지기 전에 사용이 먼저 꺾였다.**

### 그날 몇 번째 호출에서 429 가 났나

```
08-07   그날 33건 중  11 12 13 … 24 번째   ← **11번째부터 연속 14건**
08-08   그날 49건 중  11 12 · 42 번째
08-12   그날 32건 중  28 29 30 31 번째
```

⭐ **08-07 의 「11번째부터」가 눈에 띈다** — **한도가 10이었다면 정확히 맞는 자리**다
([추가 147] 이 08-10 에 20→10 으로 되돌렸다가 같은 날 다시 20 으로 올렸다고
적고 있다).

### 🚨 그런데 **「몇 명에게서 나왔는지」는 못 잰다 — 영영 못 잰다**

```
로그에 uid 가 없다        확인함. 함수가 uid 를 안 찍는다 —
                         제3자 개인정보를 로그에 안 남기는 규약대로다(4장)
users/{uid}.aiUsage 도 없다   09-06 에 서버 자료를 전부 지웠다(승인·실행 완료)
```

⚠️ **그래서 「한 사람이 몰아 썼나」는 답할 수 없다.** 위 표의 「그날 n번째」는
**모든 이용자를 합친 순번**이라 **한 사람의 한도와 직접 맞대 볼 수 없다.**
🚨 **08-08 의 42번째나 08-12 의 28번째가 「20을 넘겨서」인지 「다른 사람의 첫
호출인지」 가릴 수단이 없다.**

📌 **재려면 로그에 uid 해시를 남겨야 하는데, 그것은 개인정보 판단이 걸린다** —
**여기서 멈추고 적어 둔다.**

## 🚨 3. ② 실패했을 때 화면이 하는 일 — **여기가 이 조사의 본론이다**

**「조용히 아무 일도 안 일어나는가?」 → 아니다. 문구는 있다. 그런데…**

```dart
// briefing_overlay_view.dart:784~808 (문구는 :800 · 크기는 :802)
if (_errorMessage != null)
  Row(children: [
    Icon(Icons.error_outline, size: 16, color: _onPageErrorText),
    Text('새로 생성하지 못해 이전 결과를 보여드려요: $_errorMessage',
         style: TextStyle(fontSize: 11, color: _onPageErrorText)),   // ← 11pt
  ])
..._points.asMap().entries.map(…)      // ← 그 아래 **이전 결과 3개가 그대로**
```

| | 무엇이 보이나 |
|---|---|
| 🚨 **크게** | **이전에 보던 대화 포인트 세 개 — 한 글자도 안 바뀐 채** |
| 작게 | 그 위에 **11pt** 한 줄: *"새로 생성하지 못해 이전 결과를 보여드려요: …"* |

> 🚨 **문구가 있어도 11pt 한 줄이면, 그 아래 크게 뜬 「같은 세 문장」이 이긴다.**
>
> **이용자가 겪는 것은 「실패했다」가 아니라 「새로고침을 눌렀는데 같은 것이 나온다」**다.
> ⭐ 그리고 그것이 **globe2030님이 말씀하신 그대로**다.

📌 **「있는지」를 보면 통과하고 「눈에 띄는지」를 봐야 잡히는** 자리다.

### ⚠️ 이 경로는 429 만의 것이 아니다 — **실패 62건 전부**가 여기로 온다

```
429  21건   "오늘 사용 가능한 AI 브리핑 횟수를 모두 사용했어요. 내일 다시 시도해 주세요."
400  31건   "필수 정보가 누락됐어요."
503   9건 · 504 1건
```

⭐ **서버 문구 자체는 좋다** — 일/월 한도를 갈라서 알려 준다(`index.ts:679`·`:684`).
**앱도 그것을 그대로 쓴다**(`ai_briefing_service.dart:204~207`, *"서버 문구가 이미
한글이고 어느 한도인지까지 알려주므로"*). 🚨 **문제는 문구가 아니라 「그 문구가
놓인 자리와 크기」다.**

### 📌 갈래가 하나 더 있다 — **최초 생성이면 화면이 다르다**

```
_points 가 비어 있으면   ✅ 빨간 GlassCard 로 **크게** 오류를 보여 준다 (:687~)
_points 가 있으면        🚨 11pt 한 줄 + 이전 결과 그대로            (:784~)
```

⚠️ **「새로 생성」은 언제나 후자다** — 이전 결과가 있으니까. **실패가 가장 안 보이는
자리가 하필 재생성이다.**

### ⚠️ 그리고 **정말로 조용한 길이 하나 있다**

```dart
// briefing_overlay_view.dart:131
if (selection == null || !mounted) return;    // ← 아무 표시 없이 되돌아간다
```

**AI 자료 확인 시트를 쓸어내려 닫으면** 아무 일도 안 일어난다. 📌 **이용자가 스스로
닫은 것이라 그 자체는 맞는 동작**이지만, ⚠️ **`_consentedSelection` 이 명함별로
캐시되므로 두 번째부터는 시트가 아예 안 뜬다** — **첫 번째와 두 번째의 동작이 다르다.**

## 4. ③ 08-26 이후 0건 — **「안 쓴 것」이 더 그럴듯하지만 확정은 못 한다**

```
마지막 호출   2026-08-26T02:20:31Z (UTC) = 11:20 KST
그 뒤         호출 자체가 0건 — 실패조차 없다
```

**갈래 셋을 재 봤다.**

| 갈래 | 재 본 것 | 판정 |
|---|---|---|
| 안 썼다 | 사용량이 이미 꺾여 있었다 — 08-22 **1** · 08-24 **7** · 08-25 **1** · 08-26 **3** | ⭐ **가장 그럴듯하다** |
| 못 썼다(서버가 막음) | 막혔으면 **실패 로그가 남는다.** 실패조차 0건이다 | ❌ 아니다 |
| 앱이 그 화면에 못 감 | 🚨 **못 갈랐다** — 호출이 0이라 로그로 볼 것이 없다 | ⬜ **남는다** |

⚠️ **셋째가 남는다.** 후보 하나를 적어 둔다 — **08-30 에 안드로이드 패키지 ID 가
바뀌었다**(`com.creamhouse.connectionsense`, HANDOFF 1-5). **테스터 기기에 앱이 두
개로 깔리고 이름·아이콘이 같다.** 📌 **옛 앱을 계속 쓰면 새 기능이 안 보이고, 그것은
로그에 아무 흔적도 안 남긴다.**

🚨 **다만 08-26 → 08-30 은 순서가 안 맞는다** — 호출이 끊긴 것이 **먼저**다.
⭐ **그러니 패키지 교체는 「그 뒤로 안 돌아온 이유」는 될 수 있어도 「끊긴 이유」는
아니다.**

### ⚠️ 「그날 배포 때문」 가설도 시간이 안 맞는다

```
마지막 AI 호출     08-26  11:20 KST
그날 main 커밋     08-26  21:41 ~ 21:54 KST   ← 전부 **그 뒤**다
```

📌 **[추가 514] 의 「배포가 방어막을 걷는다」를 떠올려 의심했는데, 시간순으로 맞지
않는다.** ⚠️ **다만 `firebase deploy` 시각은 커밋 시각과 다를 수 있어 이것만으로
완전히 지우지는 않는다** — **호출이 0이라 어차피 서버 쪽으로는 더 볼 것이 없다.**
