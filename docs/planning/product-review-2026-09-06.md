## 1. 기능 개선

### 1-1. 🚨 E-04(문자 오독) · R-03(다중 OCR) — **테스터 피드백에서 유일하게 남은 것**

```
tester-feedback-resolution-2026-08-14.md:49   오류(E) 14건 중 13건 종결 · 남음 **E-04**
                                       :50   기능(F) 15건 **전부 종결**
                                       :449  R-03 ⬜ 남음 — "E-04를 푸는 유일한 길"
```

**근거**: 테스터가 직접 겪은 것(`길`→`킬` 오독). **F가 15/15 종결인데 E와 R만
남았다** — 즉 **남은 것은 「기능」이 아니라 「인식 품질」**이다.

**왜 지금**: 출시하면 **첫 화면이 명함 스캔**이다. 이름·주소가 틀리게 읽히면
그 뒤 기능이 다 좋아도 **첫인상에서 진다.**

**안 하면**: 스토어 리뷰의 첫 불만이 여기서 나온다.

⚠️ **다만 R-05 실측이 경고를 남겼다**(`:451`) — 좌표 기반 분류는 **16.2%로 지금
파서(56.6%)의 3분의 1**이었고 폴백도 **+0장**이었다. **「새 신호를 넣자」가 아니라
「다듬기」쪽에서 +6장이 나왔다.** R-03도 **먼저 재고 들어가야 한다.**

### 1-2. 🚨 비밀번호 재설정에서 **새 비밀번호를 한 번만 받는다**

```
우리 화면   password_reset_view.dart:153  "재설정 메일 보내기" — 여기까지가 우리 것
그다음      Firebase 기본 웹 화면 — 새 비밀번호를 **한 번만** 받는다
backlog     ⬜ "비밀번호 재설정 화면을 우리가 만든다 — 새 비밀번호를 두 번 받는다"
```

**근거**: 이미 접수된 항목(backlog ⬜). **실물로 확인했다** — 우리 코드에 새
비밀번호를 받는 화면이 없다.

**왜 지금**: 이메일 가입이 열려 있고, **오타 한 번이면 계정에 못 들어온다.**
그리고 그 사람은 **명함이 서버에 있는데 못 꺼내는** 상태가 된다.

**안 하면**: 문의가 온다. 그리고 우리가 해 줄 수 있는 것이 없다(비밀번호는 우리도
모른다).

### 1-3. 재연락 알림이 **앱 밖으로 안 나간다**

```

        ⬜ "착수는 globe2030님 결정 대기"

🚨 **F-10(관계 관리)이 만든 「오늘 연락하면 좋은 사람」을 앱을 열어야만 본다.**
그런데 이 앱은 **매일 여는 앱이 아니다** — 명함을 받았을 때 연다. **알려 주는
기능이 알림으로 안 나가면 사실상 없는 기능**이다.

⚠️ **이름을 알림에 넣지 않는 것**이 이미 정해져 있다(제3자 개인정보). 그 제약이
있어 문안이 *"오늘 연락하면 좋은 분이 있어요"* 수준이 된다 — **그래도 여는

### 1-5. ⬜ 명함 기반 메신저 — **범위부터 정할 것**(1이 아니라 3에 가깝다)

**저장소에 없어서 다음 사람이 모른다**는 것 하나다.
