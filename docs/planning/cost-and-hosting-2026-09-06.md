## 4. 홈페이지 — Firebase Hosting vs 내부 개발서버

### 🚨 먼저 — **옮길 것이 둘이 아니라 셋이다**

처음에 `docs/site` 와 `docs/legal` 둘만 셌는데, **실측하니 셋이다.**

```
connection-sense.web.app         ← docs/legal    법적 고지
                                    🚨 앱스토어·카카오·네이버에 **등록돼 있다**
connectionsense.web.app          ← build/site    대표 사이트(connectionsense.co.kr)
connection-sense-admin.web.app   ← docs/admin    🚨 **관리자 콘솔**  (4파일 96KB)
```

🚨 **관리자 콘솔을 안 셌다.** 그리고 그것은 **관리자 2차 인증 4단계 화면이 들어갈
자리**다([추가 682]) — **지금 비어 있는 것이 아니라 앞으로 커질 자리**다.

⚠️ **관리자 콘솔이 밖에 있는 것 자체가 따로 볼 거리다** — 내부 서버로 옮기면
**관리자 화면이 사내망 안**으로 들어간다. 🚨 **그것은 보안상 오히려 나을 수 있다.**
이 문서는 그것까지 안 쟀다.

### 🚨 그리고: **아낄 돈이 0에 가깝다**

```
지금 규모   5MB · 방문 거의 없음
무료 등급   저장 341MB · 전송 360MB/일
→ **지금도 앞으로 한참도 $0 이다**
```

⭐ **그러므로 이 결정은 「무료 vs 얼마」가 아니라 「무료 vs 무료 + 관리 부담」이다.**

### 무엇이 걸려 있나 — 🚨 **밖에 등록된 주소들이다**

```
connection-sense.web.app        앱스토어 · 카카오 · 네이버에 등록돼 있다
connectionsense.co.kr/legal/*   방침 · 약관 — **앱이 읽고 스토어가 심사한다**
```

⚠️ **죽으면 로그인과 심사가 깨진다.** 홍보 페이지가 죽는 것과 무게가 다르다.

### 옮기면 우리가 지는 것

| | Firebase Hosting | 내부 개발서버 |
|---|---|---|
| 돈 | **$0** (무료 등급 안) | 서버 유지비 + 회선 |
| 가용성 | Google SLA | 🚨 **우리 책임** — 죽으면 로그인·심사가 깨진다 |
| SSL 인증서 | 자동 갱신 | **갱신 실패 = 앱이 방침을 못 읽음** |
| DDoS·CDN | 포함 | 우리 몫 |
| 보안 패치 | 없음(정적 호스팅) | **웹서버를 계속 패치해야 한다** |
| 배포 | `firebase deploy --only hosting` | 새 절차를 만들어야 한다 |
| **사람 시간** | ≈ 0 | 🚨 **이것이 가장 큰 비용일 수 있다** |

### ⭐ 셋이 아니라 **갈래가 넷**이다

```
갑  전부 Firebase 유지          지금 그대로. 돈 $0
을  전부 내부로                 🚨 방침·약관까지 우리 책임이 된다
병  **부분** — 홍보는 내부, 법적 문서는 Firebase
    ⭐ 죽었을 때 깨지는 것으로 가른 것이다
정  전부 내부 + Firebase 를 **예비**로 남김
    ⚠️ 두 벌을 유지해야 하고, 이 저장소는 오늘 「두 벌로 갈라져 한쪽만 고쳐진」
       사고를 겪었다([추가 696] 파기 경로) — **두 벌은 공짜가 아니다**
```

📌 **가르는 기준은 「죽으면 무엇이 깨지나」다.**

```
방침·약관이 죽으면    앱이 못 읽고 스토어 심사가 막힌다   → 🚨 못 죽는다
홍보 페이지가 죽으면   방문자가 못 본다                  → 복구할 시간이 있다
```

### 🚨 배포 파이프라인 — **여기가 관리 부담의 가장 큰 덩어리다**

지금은 한 줄이고, `firebase.json` 이 나머지를 한다.

```
firebase deploy --only hosting
  target=site   predeploy: bash tool/build_site.sh   ← **자동으로 돈다**
  target=legal  docs/legal 그대로
  target=admin  docs/admin 그대로
```

⭐ **`build_site.sh` 가 하는 일이 핵심이다** — 스스로 이렇게 적어 두었다:

> *"법적 고지 원본은 **하나만** 둬야 한다 — `connection-sense.web.app` 이 이미
> 이용자·구글 플레이 콘솔·카카오·네이버에 등록돼 있어서 절대 없애면 안 된다.
> 그래서 `docs/legal` 을 `docs/site` 밑으로 옮기지 않고, **배포 직전에 결과
> 디렉터리 아래 `legal/` 로 복사해 합친다.** 원본은 항상 `docs/legal` 하나다."*

🚨 **즉 지금 구조는 「두 벌」이 아니라 「원본 하나 + 배포 둘」이다.** 그것을
**스크립트가 자동으로** 해 준다.

### 내부 서버로 가면 **그 자리를 우리가 다시 만들어야 한다**

```
⬜ 어떻게 올리나        rsync? CI? 수동?
⬜ 누가 올리나          지금은 아무나 `firebase deploy` 한 줄
⬜ 실패하면 어떻게 아나   지금은 CLI 가 즉시 알려 준다
⬜ 원본 하나 원칙        `build_site.sh` 가 지켜 주는 것을 새 절차가 지켜야 한다
```

📌 **오늘 홈페이지가 「배포만 안 돼서」 약관이 404 였다.** 🚨 **배포가 쉬운 것 자체가
값이다** — 어려워지면 **안 하게 되고, 안 하면 404 가 다시 난다.**

### ⭐ 관리 부담 — **각 줄에 「할 사람이 있나」를 붙인다**

⚠️ **없으면 그것은 비용이 아니라 위험이다.**

| | Firebase | 내부 서버 | 할 사람이 있나 |
|---|---|---|---|
| SSL 인증서 | 자동 갱신 | Let's Encrypt **90일마다** | ⬜ **갱신 실패 = 앱이 방침을 못 읽음** |
| 가용성 | Google SLA | 죽으면 우리가 복구 | ⬜ **밤·주말은?** |
| DDoS·급증 | Google 이 흡수 | 우리 회선 | ⬜ |
| CDN | 전 세계 엣지 | 서버 한 대 | — |
| 배포 | `deploy` 한 줄 | 🚨 **새로 만들어야 함**(위) | ⬜ |
| 보안 패치 | 없음(정적) | OS·웹서버 지속 | ⬜ |
| **사람 시간** | ≈ 0 | 🚨 **가장 큰 비용일 수 있다** | ⬜ |

🚨 **⬜ 가 일곱 중 여섯이다.** 서버가 **있다**는 것만으로는 이 표가 안 채워진다 —
**「누가 언제 할 것인가」가 비어 있으면 을·정은 고를 수 없다.**

### ⬜ 이 비교가 못 본 것

```
⬜ 내부 개발서버가 **지금 있는지** · 사양 · 회선 · 남는 용량
   🚨 없으면 **새로 사는 비용**이 들어가고, 그러면 비교가 통째로 달라진다
⬜ 그 서버의 현재 관리자가 누구이고 시간이 있는지
⬜ 도메인·DNS 를 어디서 관리하는지 (Cloudflare 계정을 못 찾은 기록이 있다 — 추가 654)
⬜ 🆕 **관리자 콘솔을 사내망 안으로 넣는 것의 값** — 보안상 오히려 나을 수 있다
⬜ 🆕 배포 실패를 **어떻게 알 것인가** — 지금은 CLI 가 즉시 알려 준다
```

**방향만 보고 금액으로 쓰면 안 된다.**
