# 내 명함 전달 기능 — 스펙 (2026-08-16)

**작성**: PM 세션 · **상태**: 설계 결정 대기(사용자)
**근거**: 사용자가 리멤버 실물 흐름을 화면 녹화로 제공(2026-08-16)

---

## 0. 왜 이것을 보나

사용자가 짚은 것:

> **"이 기능은 상대방도 리멤버를 이용하게 유도하는 아이디어 같은데."**

맞다. **광고비 없이 사용자가 사용자를 데려오는 장치**다. 우리 마케팅 방향이
*"예산 0원 시작 · 보험설계사 비치헤드"*인데, **영업직은 하루에 명함을 여러 번
주고받으므로 전달 횟수 자체가 많다.** 이 고리가 우리 계획과 정확히 맞는다.

---

## 1. 리멤버는 어떻게 하나 — 실물 관찰

화면 녹화 4건에서 확인한 것이다. **추정이 아니라 본 것만 적는다.**

### 흐름

```
내 명함 화면 → [내 명함 전달하기]      ← 카드 바로 아래, 검은 버튼(강조)
   → 카카오톡 친구 선택 (문자·이메일도 같은 자리에서)
   → 상대에게 메시지 도착
   → 상대가 누르면 리멤버 앱이 열림
```

### 받는 메시지 — **여기가 핵심이다**

```
이름: … / 회사: … / 부서: … / 직책: …
휴대전화 · 유선전화 · 이메일 · 주소 · 팩스   ← 전부 텍스트로

명함 저장 버튼은 개인정보 보호를 위해 72시간 동안만 유효합니다.

           [ 명함 저장하기 ]              ⓡ 리멤버
```

**설계 의도가 셋 읽힌다.**

| 무엇 | 왜 그렇게 했나 |
|---|---|
| **정보를 텍스트로 전부** | 앱이 없어도 **정보는 읽힌다.** 링크가 죽어도 남는다 |
| **72시간 만료** | 개인정보 보호가 명분이지만, **실제로는 빨리 누르게 만든다** |
| **리멤버 브랜딩** | 메시지마다 이름이 노출된다 |

### 받는 쪽 화면

앱이 열리고 버튼이 **둘**이다.

```
[ 명함만 저장 ]
[ 명함 저장과 함께 1촌 신청 ]     ← 검은색, 강조
```

**저장만 하면 한 방향, 1촌은 양방향 연결.** 상대가 수락하면 둘 다 리멤버 안에
묶인다 — **여기가 고리의 마지막 칸이다.**

---

## 2. 우리는 그 마지막 칸이 비어 있다 — 그러나 막지는 말자

우리에겐 **1촌에 해당하는 것이 없다.** 그러면 상대가 *"저장했다"*에서 끝난다.

⚠️ **다만 사용자가 짚었다.**

> **"우리는 1촌 기능이 없지만 리멤버도 원래는 없었어. 우리도 인적 네트워크를
> 고려하면 다른 방식으로 2차 고도화 때 고려해야 해."**

**그래서 이 스펙의 설계 원칙 하나가 여기서 나온다.**

> **지금 만드는 전달 기능이 나중의 네트워크 기능을 막지 않아야 한다.**

구체적으로:

- **전달 기록을 남긴다** — 누가 누구에게 언제 보냈는지(식별자 수준). 나중에
  *"이 사람과 명함을 주고받았다"*를 관계의 씨앗으로 쓸 수 있다
  ⚠️ 단 **지금 쓰지 않을 개인정보를 미리 모으지 않는다.** 방침 위반이고, 이
  저장소가 이미 겪은 함정이다(추가 77 — 안 쓰는 좌표가 서버에 남아 있었다)
- **받는 쪽 화면을 나중에 늘릴 수 있게** 만든다. 지금은 버튼이 [저장] 하나뿐이라도
  자리를 둘로 나눠 둔다
- **"내 명함"이라는 개념을 명확히 한다** — 네트워크는 결국 *"내 명함을 가진
  사람들"*의 집합이다. 그 정의가 흔들리면 나중에 못 만든다

⚠️ **2차 고도화의 형태는 지금 정하지 않는다.** 리멤버가 1촌으로 간 것이 유일한
답은 아니다. 우리에겐 **"주변 인맥 레이더"**라는 다른 축이 이미 있고, 그쪽과
어떻게 묶을지가 오히려 우리다운 답일 수 있다.

## 3. 무엇을 만드나

### 3-1. 보내는 쪽

| | |
|---|---|
| 진입 | **내 명함 화면**에 `내 명함 전달하기` 버튼. 리멤버와 같은 자리가 맞다 |
| 경로 | OS 공유 시트 하나로 **문자·카톡·이메일·기타**를 다 덮는다 |

⚠️ **카카오톡 전용 SDK를 따로 붙일지는 결정이 필요하다.** OS 공유 시트만 쓰면
카톡에 **글자만** 간다. 리멤버처럼 **미리보기 카드**로 예쁘게 나오려면 카카오
공유 SDK가 필요하고, 그러면 **카카오 개발자 등록·앱 키·심사**가 딸려 온다.

### 3-2. 보내는 내용

리멤버를 따른다 — **정보를 텍스트로 전부 + 링크**.

```
이름 / 회사 / 부서 / 직책
휴대전화 / 직통 / 대표번호 / 팩스 / 이메일 / 주소 / 웹사이트
(우리는 직통·팩스·웹사이트가 이미 있다 — 추가 215)

이 링크는 개인정보 보호를 위해 N시간 동안만 열립니다.
[ 명함 저장하기 ]
```

⚠️ **명함 사진을 함께 보낼지는 결정이 필요하다.** 보내면 친절하지만 **제3자에게
이미지 파일이 넘어간다.** 처음에는 **텍스트만** 권한다.

### 3-3. 받는 쪽

```
앱이 있으면   → 앱이 열리고 명함 정보 + [저장]
앱이 없으면   → 웹 페이지로 정보가 보이고 + [앱 받기]
```

⚠️ **앱이 없을 때 무엇을 보여줄지가 유입의 갈림길이다.**

| | |
|---|---|
| **웹에서 바로 보여준다** | 친절하다. 대신 **앱을 안 깔아도 된다** |
| **앱을 깔아야 보인다** | 유입은 세다. 대신 **거부감이 크고, 정보를 못 본다** |

**권고: 웹에서 보여주되 "앱에 저장하면 자동으로 들어온다"를 함께 보여준다.**
정보를 인질로 잡지 않는다 — 우리는 개인정보를 다루는 앱이고, **첫인상이 그렇게
시작되면 안 된다.**

### 3-4. 링크 만료

**필수다.** 리멤버는 72시간이다.

⚠️ 우리는 **더 짧아도 된다**(24~48시간). 개인정보처리방침과 직결되고, **짧을수록
방어가 쉽다.** 만료 뒤에는 링크가 죽고 **서버에서도 지운다.**

## 6. 재보지 않은 것

- ⚠️ **앱이 없는 사람이 링크를 눌렀을 때 리멤버가 무엇을 보여주는지** — 녹화가
  전부 앱이 깔린 기기였다. **이걸 봐야 ②의 근거가 생긴다**
- ⚠️ 리멤버가 **문자·이메일에서도 같은 형식**인지 — 카톡만 확인됐다
- ⚠️ 카카오 공유 SDK의 심사·등록 비용과 기간
- ⚠️ 만료된 링크를 눌렀을 때의 화면
