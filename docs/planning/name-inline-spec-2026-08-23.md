# 이름이 줄 안에 묻힌 12장 — 규칙 스펙

작성: 2026-08-23 · 근거: [추가 411·425·429](backlog.md) 실측 · **아직 구현 안 함**
· 기준 상태: **추가 429 적용 후**(이름 74/91 = 81%)

> ⚠️ **여기는 추가 425에서 벽을 만난 자리다.** 그때 줄에서 영문을 떼려다
> 자동 테스트 3건이 깨져 규칙을 좁혔다. **같은 벽을 다시 넘으려는 것**이므로
> 위험도 같다.

---

## 1. ⚠️ 먼저 — 숫자를 두 번 고쳤다

처음에 **OCR 원문 줄**로 세어 "② 10장"이라고 했다. 그런데 **파서는 자간
붙이기(`_collapseCharSpacing`)를 거친 뒤의 줄을 본다.** 파서가 실제로 보는
줄로 다시 세니 갈래가 달라졌다.

```
원문 줄 기준      한 글자씩 쪼개짐 4 · 낱말 2개로 갈림 6
파서가 보는 줄     ① 붙이기 뒤 낱말 하나로 섬 6 · ② 낱말 2개로 갈림 6
```

📌 **자간 붙이기가 이미 절반을 해결해 놓았다.** 남은 문제는 "붙이기"가 아니라
그 뒤다.

## 2. 두 갈래

### ① 붙여 놓았는데 **못 고른다** — 6장

이름이 낱말 하나로 멀쩡히 서 있는데 다른 칸이 가져가거나 비운다.

| 사진 | 같은 줄의 다른 낱말 | 경로 |
|---|---|---|
| 1234·1295·1306 | `클라우드솔루션팀` | leftoverFallback |
| 1238 | `개발본부` · `사원` | hangulTokenPreferred |
| 1290 | `Choi` | leftoverFallback |
| 1286 | `Ma)soft` · `(주)엠투소프트` · `주임\|` | leftoverFallback |

⭐ **네 장에서 같은 줄에 부서명이 붙어 있다**(`클라우드솔루션팀`·`개발본부`).
추가 413에서 확인했듯 **행 묶기가 부서와 이름을 한 줄로 합친 것**이고, 그 줄
전체가 회사·부서 쪽으로 간다.

### ② 낱말 2개로 갈린다 — 6장

```
1214·1274   [5, 2, 1]   개발협력부 · 김수 · 진      ← 이름이 "김수"+"진"
1231        [2, 2, 1]   팀장 · 이정 · 현            ← "이정"+"현"
1273        [2, 3, 2, 1] 총괄 · 매니저 · 김지 · …    ← "김지"+…
1284        [3, 5, …]   산드라 · 하리리투불 · Sandra  ← 외국인 이름
1311        [4, 3, 1, 2] 사업개발 · 본부장 · 맹 · …   ← "맹"+…
```

⚠️ **`_collapseCharSpacing`은 한 글자 낱말이 3개 연속일 때만 붙인다.**
`김수 진`은 [2,1]이라 조건에 안 걸린다. 그래서 이 여섯 장이 남았다.

## 3. 제안 — **①만 손댄다**

### ①: 부서명이 붙은 줄에서 이름을 떼어낸다

같은 줄에 **부서 접미어로 끝나는 낱말**(`팀`·`본부`·`부`)과 **이름 모양
낱말**이 함께 있으면, 이름 쪽을 이름으로 확정한다.

⚠️ **이미 있는 재료를 쓴다** — `_departmentSuffixes`와 `_hangulNameLooksReal`.
새 판정을 만들지 않는다.

**기대: 4장**(1234·1295·1306·1238). 1290·1286은 다른 결이라 이 규칙 밖이다.

### ②: ⚠️ **손대지 말 것을 권한다**

`[2,1]` 붙이기를 허용하면 `팀장 이정 현`에서 `이정현`을 얻지만, **`김수 진`과
`영업 부장`을 구별할 근거가 없다.** 한 글자 낱말은 명함에 흔하다.

📌 **추가 425가 바로 이 자리에서 깨졌다.** 그때도 "줄에서 떼어내면 +2"였는데
자동 테스트가 `장 장동일 (Daniel)`·`하나 Control`을 들고 왔다.

⚠️ 1284는 **외국인 이름**(`산드라 하리리투불`)이라 성씨 규칙 자체가 안 통한다.
1311은 `맹`이 성씨 목록에 없다.

**②의 6장 중 규칙으로 안전하게 열 수 있는 것은 보이지 않는다.**

## 4. 예상 효과와 위험

```
①만 적용        기대 +4  (이름 74 → 78 / 91 = 86%)
②까지 적용      기대 +6 이지만 425에서 깨진 것과 같은 위험
```

⚠️ **기대는 기대다.** 오늘 규칙 셋이 전부 스펙 예측보다 작게 나왔다
(+7→+3 · 7장→3장 · +4→+3). **넣는 자리에 따라 절반이 날아간다.**

## 5. 검증 절차

1. 전 필드 전후 대조(`score_matrix.py`) — **깨짐 0**
2. `flutter analyze` · `flutter test` — 기존 1,225건 유지
   ⚠️ **425에서 96장 대조는 깨짐 0인데 자동 테스트가 3건을 잡았다.** 이
   자리에서는 **자동 테스트가 더 민감한 자**다
3. 규칙 자체 테스트: 부서+이름 줄 분리 · 부서 없는 줄 불변 · 이름 모양이
   아닌 낱말 불변

## 6. 이 스펙이 닿지 않는 곳

```
② 낱말 2개로 갈림      6장   ← 위험 대비 이득이 안 맞는다
③ OCR에 정답이 없음     5장   ← 파서 밖
```

천장(95%)까지 가려면 ②를 열어야 하지만, **지금 있는 신호로는 안전하게 못
연다.** 열려면 새 신호가 필요하다 — 낱말 사이 틈(v3)은 [추가 416](backlog.md)
에서 **못 가른다고 판가름났다.**
