## 1. 무엇을 하려는 것인가

명함을 등록할 때 **사진 1장을 서버 AI에 1회 보내** 12칸을 인식하고, 처리 후
사진은 보관하지 않는 구성. 지금은 기기 안에서 ML Kit + 자체 규칙으로 인식한다.

## 2. 왜 검토하게 됐나 — 실측 숫자

같은 명함 96장·같은 정답지·같은 채점기로 쟀다(추가 415·419).

```
앱 단독(11칸)                65%
전부 서버 12칸               94%
```

칸별로 보면 이름 100% · 휴대폰 100% · 팩스 99% · 우편번호 99% · 사무실 98% ·
이메일 98% · 주소 86% · 상세주소 85% · 홈페이지 85% · 직함 82% · 부서 73% ·
회사 45%(관대 94%).

📌 **가장 큰 이유는 성능 자체보다 "고칠 여지"다.** 앱 쪽 약점(회사 14%·부서
26%)은 규칙으로 메우기 어려운 종류였고, 오늘 하루에만 이름 규칙을 세 번
파고도(추가 409·412·416) **행 묶기라는 같은 벽에 세 번 부딪혔다.**

## 3. ⚠️ 법적 관문 — 여기가 실제 문턱이다

[법무 조사 메모](server-ocr-legal-research-2026-08-23.md) 참고. **성능이 아니라
이쪽이 채택을 가른다.**

### 3-1. 국외 이전(§28조의8) — **Vertex 서울로 해소 가능**

Vertex AI 서울 리전(`asia-northeast3`)에서 **Gemini 2.5 Flash** 사용 가능함을
확인했고, 처리까지 리전 내 보장이면 국외 이전 논점이 소멸한다.

⚠️ **3.x 계열은 서울 미지원**이다. 실측에서 가장 좋았던 축(Gemini 1차)은
3.x이고 **서울에서 쓸 수 있는 것은 2.5-flash**다 — 위 94%는 2.5-flash로 잰
값이니 그대로 유효하다.

### 3-2. ⚠️ 게시된 문서가 **이미 반대로** 적혀 있다

이번 기능은 문안을 *추가*하는 개정이 아니라 **단언을 철회**하는 개정이다.
법무 메모가 짚은 자리 여섯 곳 — `app-permissions.html`의 *"OCR은 기기 안에서
처리됩니다"*, 방침의 *"국외로 이전하지 않습니다"* 둘, 국외 이전 표, 약관의
이용 목적 한정, 그리고 가장 무거운 것:

```
"정보를 외부로 전송하는 기능은 전송 항목을 화면에 먼저 보여주고
 이용자가 동의한 경우에만 동작합니다."          (방침 1번 총칙)
```

📌 **이 문장이 설계를 정한다.** §30③은 방침과 계약이 다르면 **이용자에게
유리한 쪽**을 적용한다 — 넓게 적어 둔 약속이 회사를 구속한다. 즉

- **전송 전 확인 화면을 두면** 이 약속을 지키는 것이고, 고지 기간이 짧다(7일)
- **자동 전송으로 가려면** 이 문장을 먼저 지워야 하는데, 그것은 **이용자에게
  불리한 개정**이라 30일 고지 + 리스크가 붙는다

⚠️ **그래서 이 계획서는 "전송 전 확인 화면" 쪽을 기본으로 잡는다.** 그것이
성능과 무관하게 이미 정해져 있는 제약이다.

## 4. 단계 — 순서가 바뀌면 안 되는 이유까지

```
① 전송 전 확인 화면 설계·구현      ← 3-2의 약속을 지키는 형태
② 방침·약관·안내 문서 개정 + 7일 고지
③ 서버 호출 구현 (Vertex 서울 · 2.5-flash · 12칸 프롬프트)
④ 429 재시도 설계                 ← 아래 5-2, 없으면 등록이 통째로 실패
⑤ 실기기 검증 (전체 테스트)
```

⚠️ **②가 ③보다 먼저다.** 구현이 먼저 나가면 **게시된 방침과 실물이 어긋난
상태**가 생긴다 — 그 자체가 법적 리스크다(CLAUDE.md 4절, BYOK 서술 불일치로
이미 한 번 겪었다).

⚠️ **④를 ⑤ 앞에 둔다.** 재시도 없이 검증하면 혼잡 때 나온 실패를 **코드
결함으로 오인**한다.

## 5. 리스크 — 성능표에 안 나타나는 것들

### 5-1. ⚠️ 모델은 **틀려도 채운다**

실측(추가 415): 모델의 빈칸은 거의 전부 *정답도 없는 칸*이고, **정답이 있는
칸은 확신이 없어도 채운다.**

```
Gemini(1차)   빈칸 30 = 옳게 비움 30 + 놓침 0
2.5서울(기본)  빈칸 29 = 옳게 비움 27 + 놓침 2
```

*"모르면 비워라"* 프롬프트로 바꿔 봤지만 **665칸 중 빈칸이 2개 늘었을 뿐**이고
정확도만 조금 깎였다. **프롬프트로는 못 바꾼다.**

📌 이 프로젝트는 **"값이 없는 것이 틀린 값보다 낫다"**(추가 183)로 정해 뒀다.
서버를 쓰면 **반대 성향의 값이 조용히 저장된다** — ①의 확인 화면이 그래서
법적 요구인 동시에 **품질 장치**다.

### 5-2. ⚠️ 서울 리전 혼잡(429) — 하루 **세 번** 관측

```
1회차   첫 시도 95건 전멸
2회차   재실행 중반 33건 밀림
3회차   1차 50건만 성공, 45건 밀림
```

세 번 다 최종적으로는 "95장 전부 성공"으로 남지만 **매번 재시도했기 때문**이다.
**재시도 설계 없이 온디맨드로 부르면 사용자 등록이 통째로 실패한다.**

### 5-3. 회사 칸은 **완전일치 45%로 미해결**

관대 기준으로는 94%다. 정답지가 영문 병기를 담는 관행과 아직 안 맞는다 —
**정답지를 정리할지, 프롬프트를 더 조일지**가 남은 선택이다. 채택하더라도
회사 칸은 사용자 손이 갈 가능성이 있다.

### 5-4. 되돌리기

서버 인식은 **켜고 끄는 스위치로 둘 수 있다**(과금 `config/billing.model`이
쓰는 방식과 같다). 다만 **방침 개정은 되돌리기 어렵다** — 한 번 *"기기 안에서
처리됩니다"*를 지우면 다시 그 문장을 쓰려면 또 개정해야 한다.

## 6. 비용 — 계산 틀만 두고, 숫자는 채택 시점에 잰다

원가 공식은 이미 저장소에 있다([`tool/analyze_ai_cost.py`](../../tool/analyze_ai_cost.py)).

```
원가(USD) = (입력토큰 × 단가_in + (출력토큰 + 사고토큰) × 단가_out) / 1,000,000
```

⚠️ **건당 원가를 아직 안 쟀다.** 이번 실측은 정확도만 봤고 **토큰 수를 안
남겼다.** 사진은 축소본 기준 **236KB/장**(추가 414 실측)이라 입력 토큰이
적지 않을 것이고, 명함 등록마다 1회 호출이므로 **사용량에 정비례한다.**

📌 **채택을 결정하기 전에 반드시 잴 것**: 12칸 프롬프트로 명함 1장을 처리할
때의 입력·출력·사고 토큰 수. 재는 데 사진 몇 장이면 충분하다.

⚠️ 지금 충전 티어(1,000원=10회)는 **원가를 모른 채 정한 잠정치**다. 서버
인식이 붙으면 **호출이 늘어 그 잠정치의 전제가 바뀐다.**

## 7. 결정 시점에 **다시 재야 할 것**

이 문서의 숫자는 2026-08-23 것이다. 보류 기간이 길어지면 아래는 낡는다.

| 무엇 | 왜 |
|---|---|
| **모델 버전** | 2.5-flash가 서울에서 계속 최신인지. 세대가 바뀌면 성능·단가가 다 바뀐다 |
| **정확도 재측정** | 같은 96장·같은 채점기로. 도구는 [`score_matrix.py`](../../tool/ocr_review/score_matrix.py)에 남아 있다 |
| **건당 토큰·원가** | 위 6절 — 아직 한 번도 안 쟀다 |
| **429 혼잡** | 하루 세 번은 **그날의 값**이다. 재시도 설계의 강도를 정하려면 다시 봐야 한다 |
| **법무 재확인** | 조문·약관은 바뀐다. 메모의 조문 확인일은 2026-08-23이다 |
| **앱 쪽 개선분** | 그사이 앱이 좋아지면 격차가 줄어 판단이 달라진다(추가 421~ 진행 중) |

⚠️ **가장 낡기 쉬운 것은 정확도가 아니라 단가와 조문이다.** 정확도는 크게
안 변하지만 그 둘은 분기마다 바뀐다.

## 8. 이 계획서가 답하지 않는 것

- **표본 한계**: 96장은 사용자가 하루에 찍은 것이라 촬영 조건이 고르다.
  테스터가 겪는 분포와 같지 않다
- **지연**: 서버 왕복이 등록 체감에 얼마나 붙는지 안 쟀다
- **오프라인**: 지금은 비행기 모드에서도 인식된다. 서버로 가면 못 한다 —
  **되돌릴 수 없는 기능 상실**이고, 이 문서에서 값을 매기지 않았다
