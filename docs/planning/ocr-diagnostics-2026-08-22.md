# OCR 진단 수치 — 착수 순서 결정용 재료

2026-08-22 저녁, 폴드 실기기(빌드 `b1fbd68`)의 **설정 → 명함 인식 진단** 화면을
읽은 값이다.

**결정을 담은 문서가 아니다.** 추가 329(OCR 착수 순서, 사용자 결정 대기)와
추가 401(우선 필드: 이름·핸드폰·주소)에 쓸 **재료**다.

⚠️ 이 문서의 숫자는 전부 **앱이 스스로 센 값을 읽은 것**이다. 정답지와 대조한
정확도가 아니라 **"칸이 채워졌는가"**다. 둘은 다른 값이다 — 잘못된 값이 채워져도
여기서는 성공으로 잡힌다.

---

## 1. 한눈에

```
스캔 파싱 횟수            166회
자동 인식을 고친 명함     102건 (61%)   ← 열에 여섯은 사람이 손을 봤다
```

📌 **61%가 이 문서에서 가장 무거운 숫자다.** 채움률이 아무리 높아도 **열에 여섯을
고쳐야 한다면 그게 실제 품질**이다. 아래 채움률(74~95%)과 나란히 놓고 봐야 한다.

⚠️ 다만 "고쳤다"에는 **자리채움을 넣은 것도 섞여 있다**(추가 400 — 명함에 없는
값을 앱이 요구해서 사용자가 임의값을 넣은 것). 그 몫이 얼마인지는 안 갈렸다.

## 2. 필드별 채워진 비율 (분모 166)

```
회사명      158  (95%)
주소        151  (91%)
직함        149  (90%)
상세주소    139  (84%)
이름        138  (83%)
사무실 전화 134  (81%)
휴대폰      128  (77%)
이메일      123  (74%)
우편번호     82  (49%)   ← 가장 낮다
```

### 추가 401(우선 필드)과 대조

사용자가 정한 우선 필드는 **이름·핸드폰·주소**다.

| 우선 필드 | 채움률 | 읽는 법 |
|---|---|---|
| 주소 | **91%** | 채움률은 높다. ⚠️ 그런데 **좌표로 바뀌는 비율은 31%**다(3절) — 채워진 것과 쓸 수 있는 것이 다르다 |
| 이름 | **83%** | 못 찾음 17%가 그대로 드러난다(4절) |
| 휴대폰 | **77%** | 우선 필드 중 가장 낮다 |

📌 **우선 필드 셋이 전체 평균보다 낮거나 비슷하다.** 회사명(95%)·직함(90%)처럼
덜 급한 필드가 오히려 잘 잡힌다.

---

## 3. 주소 → 좌표: 채워지는 것과 쓸 수 있는 것이 다르다

```
주소가 있는 명함    97장
좌표가 붙은 것      30장 (31%)
좌표가 없는 것      67장 (69%)
```

⭐ **이 값이 08-21 실측과 만난다.** 그때 OS 지오코더 적중률을 **32.3%**로 쟀는데
(추가 384), 기기 실물이 **30.9%**다. **다른 방법으로 잰 두 숫자가 일치했다.**

| | 적중률 | 97장 환산 |
|---|---|---|
| 지금(OS 지오코더) | 32.3% (실측) · 30.9% (기기) | **30장** |
| 행안부 | 67.7% (실측) | **약 66장** (예측) |

📌 즉 **주소 채움률 91%가 실제로는 31%만 쓰인다.** 주소를 더 잘 읽는 것보다
**읽은 주소를 좌표로 바꾸는 쪽**의 이득이 크다는 뜻이다 — 행안부 교체(좌표 운영키
발급 대기 중)가 우선순위에서 앞설 근거다.

⚠️ 66장은 **예측**이다. 실제로 바꿔 보기 전까지는 잰 값이 아니다.

## 5. ⚠️ 가설 — 추가 396(이름 칸 오염)의 발생 경로

추가 396에서 **좌표 없는 64명 중 적어도 14건**이 이름 칸에 사람 이름이 아닌 것
(부서명·영문 문구·지점명)이 들어 있었다.

위 경로 분포에 짝이 맞아 보이는 것이 둘 있다.

```
맨 앞 줄 폴백(약함)   8%    이름을 못 고르면 맨 앞 줄을 그냥 쓴다
못 찾음              17%    아예 못 찾은 것
```

**둘 다 "약한 근거로 채운" 경로**이고, 396에서 본 오염 유형(부서명·영문 회사
문구가 이름 자리에)과 결이 같다.

⚠️ **가설이다. 아직 안 쟀다.** 확인하려면 **오염된 14건이 실제로 어느 경로로
뽑혔는지**를 대조해야 한다. 지금 화면은 **경로별 합계만** 주고 명함별 경로는 안
준다 — 그 대조를 하려면 계측을 명함 단위로 남기거나, 정답지 대조에서 갈라야 한다.

📌 가설이 맞다면 **"맨 앞 줄 폴백"을 쓰지 않고 비워 두는 것**이 나을 수 있다.
추가 400에서 드러났듯 **빈 칸은 사용자가 채울 수 있지만, 틀린 값은 틀린 줄
모른다.** 다만 필수 검증과 얽히므로(#434) 함께 봐야 한다.

## 6. 아직 신호가 없는 것

```
필드별 사용자 수정(오인식 신호)   아직 기록 없음
형태별 좌표 변환 실패            ⚠️ 비어 있음 → 추가 404
```

둘 다 **"쌓이기로 되어 있는데 안 쌓인 것"**이다. 404에서 후자의 원인(집계가 시도
시점에만 쌓이는 구조적 공백)을 적었고, 전자도 같은 종류일 수 있다 — 확인 안 했다.

---

## 7. 이 문서가 답하지 않는 것

- **정확도** — 여기 있는 것은 채움률이다. 정답지 대조는 별도 채점기가 한다
- **자리채움이 61%에서 차지하는 몫**
- **396 가설의 검증**
- **행안부 교체 후 실제 좌표 적중률** — 운영키 발급 대기
