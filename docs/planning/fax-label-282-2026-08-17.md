# 팩스 — 번호마다 제 라벨을 본다 (2026-08-17, 추가 282)

> ## ⚠️⚠️ 오늘 배운 것 중 가장 값어치 있는 한 줄
>
> **파서가 팩스를 사무실 칸에 넣고 있었는데, 정답지도 팩스를 사무실 칸에 적어
> 놓아서 서로 맞아떨어지고 있었다.**
>
> 그래서 사무실 전화가 **98%**로 보였다. 자를 고치니 **같은 파서가 91%**로
> 내려간다. **같은 실수를 양쪽이 함께 하면 채점은 만점을 준다.**

```
팩스   35% → 97%      사무실 91% → 96%      전체 83% → 88%
```

## 0. ⭐ 가장 중요한 것부터 — **팩스 번호가 사무실 칸에 들어가 있었다**

점수 이야기보다 이것이 먼저다.

```
원문   T02-6360-69/LĻ  F 02-6360-6930  MO10-5024-8727      (card_115)

예전   사무실 = 02-6360-6930   ← ⚠️ 이건 팩스 번호다
지금   사무실 = (빈 칸)        · 팩스 = 02-6360-6930
```

**왜 그렇게 됐나**: OCR이 앞의 사무실 번호를 `02-6360-69/LĻ`로 읽어 번호 규칙에
안 걸렸다. 그러면 **뒤에 있는 팩스 번호가 첫 매칭**이 되어 사무실 칸을 차지한다.

⚠️ **사용자가 그 번호로 전화를 건다.** 팩스로 걸면 안 받고 끊긴다. 상대가
누구인지 알 수 없게 되고, 앱이 준 번호라 사용자는 자기가 잘못 걸었다고
생각하지 않는다.

📌 **빈 칸이 틀린 번호보다 낫다.** 이 변경으로 그 자리가 빈 칸이 된다. 채점에서는
*"미검출"*로 세어져 **점수가 오히려 내려가지만**, 사용자에게는 분명한 개선이다.

⚠️ **정정**: 처음에는 *"card_115의 사무실은 빈 칸이 맞다"*고 적었는데 틀렸다.
PM이 사진을 확인해 보니 **인쇄 번호 위에 손글씨로 `02-6360-6914`가 적혀
있었다**(같은 명함인 card_37도 같은 손글씨). **파서가 못 읽는 것과 명함에 없는
것은 다르다** — 빈 칸은 *"맞는 답"*이 아니라 *"틀린 답을 안 낸 것"*이다.

## 1. 무엇이 문제였나 — **줄 전체로 판단하고 있었다**

103장에서 팩스를 놓친 **16장을 전부 뜯어봤다. 모두 원문에는 있었다. 오독은
한 건도 없었다.** 파서가 안 고른 것뿐이다.

원인은 `_looksLikeFaxLine`이 *"`fax` 라벨이 있고 `tel` 라벨이 **없을 때만**"*
팩스로 보는 것이었다. 한국 명함은 **한 줄에 둘 다 적는 경우가 흔하다.**

```
Tel 02-6053-9142  Fax 070-7600-0812     ← tel이 있으니 규칙이 통째로 꺼진다
```

그래서 **번호마다 제 라벨을 본다.** 국가번호 표기(`T+82 … F+82 …`)에는 이미
그렇게 하고 있었다 — 국내 표기에만 없었다.

### 놓친 16장의 갈래

| 모양 | 장 |
|---|---|
| **한 글자 `F`** (`F031-…` · `F. 02-…` · `F 02-…`) | **9** |
| `Fax`/`FAX` 낱말이 `Tel`과 한 줄에 | **6** |
| ⚠️ 라벨이 OCR에서 사라짐 (`f)` → `)`) | 1 |

마지막 1장(card_11)은 **한 사진에 명함 5장**이 있는 장이라 목표에서 뺐다.

⚠️ `Fäx`(card_54)는 **일부러 안 받는다.** 오독이다. 한 장 때문에 오독까지 받으면
규칙이 지저분해지고, 다음 사람이 *"왜 ä를 받지"* 하고 헤맨다. R-03 쪽이다.

### 한 글자 `F`는 경계를 건다

```dart
if (head.toLowerCase().endsWith('f')) {
  final prev = i - 1;
  return prev < 0 || !_letterRegExp.hasMatch(s[prev]);   // `Staff 02-…`는 라벨이 아니다
}
```

⚠️ 이 저장소가 **부분 문자열로 반복해 데인 자리**라(추가 178·180·182·183)
처음부터 경계를 걸었다.

## 2. ⚠️⚠️ 숫자로는 판정할 수 없었다 — **정답지가 자를 못 댄다**

```
팩스   59% → 52%    (맞춘 것은 23 → 34로 늘었는데 "오검출"이 26 생겼다)
사무실 98% → 91%
```

**착수 전에 정해 둔 멈춤 조건에 걸렸다.** 그래서 멈추고 26건 + 6건을 하나씩
뜯어봤다. **틀린 것은 파서가 아니라 정답지였다.**

### ① 팩스 칸이 체계적으로 비어 있다 — 103장 중 64장

검수 도구는 **인식값을 미리 깔고** 시작한다. 팩스는 **예전 파서가 못 찾은 칸이
빈 채로** 깔렸고, 빈 칸은 그대로 지나가진다.

새로 채운 26건의 근거:

```
앞에 fax/팩스 낱말이 붙어 있다   6건   ← 의심의 여지 없음
앞에 한 글자 F가 붙어 있다      19건
설명 안 됨                       1건   ← card_104, ③ 참조
```

📌 **사진으로도 확인했다** — `card_65`에 `FAX. 02-2606-3026`,
`card_13`에 `F 02-3788-0899`가 인쇄돼 있다.

### ② 팩스 번호가 사무실 칸에 적힌 행이 있다

사무실이 떨어진 것은 **전부 이것**이었다.

| | 원문 | 정답지 |
|---|---|---|
| card_09 | `F. 031 715 7873` | 사무실 |
| card_123 | `T1588-3112 F02-468-8251` | 사무실 |
| card_37 · card_51 | SSiS·이랜서의 팩스 번호 | 사무실 |
| card_115 | (0절 참조) | 예전 파서값이 그대로 |

### ③ card_104 — 같은 회사 명함 두 장이 답을 준다

card_104는 줄이 뭉개져 라벨을 못 본다. 그런데 **같은 회사 명함이 두 장 더
있다.**

```
card_43 · card_114:   tel 070-4736-6106
                      RAUM fax 070-4735-7770
```

정답지의 card_104는 **사무실 = 070-4735-7770**이다. **팩스를 사무실로 적었다.**

### ④ 점 표기를 그대로 적은 행 셋

`02.6177.7587` — 정답지 규칙은 하이픈이다(`tool/ocr_review/README.md`).

> **검수 도구가 인식값을 미리 깔고, 빈 칸은 그냥 지나가진다.**

값이 차 있으면 맞는 것처럼 보이고, 비어 있으면 *"이 명함엔 없나 보다"*로 읽힌다.
**둘 다 사람이 확인한 것과 구별되지 않는다.**

📌 **남은 일**: 검수 도구에 *"빈 칸을 봤다"*와 *"빈 칸을 안 봤다"*를 가르는 표시를
넣는 것. 없으면 **칸을 늘릴 때마다 같은 일이 반복된다**(팩스·홈페이지를 넣은
것이 바로 오늘이다). ⚠️ 282가 먼저라 지금은 안 한다.

## 4. ⭐ 재측정 — **파서 몫과 자 몫을 갈랐다**

정답지의 팩스 칸이 채워진 뒤 **네 번 재서** 갈랐다. 두 번만 재면 *"팩스가
59%에서 88%가 됐다"*가 되는데, **그 말은 틀리다.**

| | 옛 정답지 | **고친 정답지** |
|---|---|---|
| **옛 파서** | 팩스 59% · 사무실 98% · 전체 86% | 팩스 **35%** · 사무실 **91%** · 전체 83% |
| **새 파서(282)** | 팩스 52% · 사무실 91% · 전체 84% | **팩스 97% · 사무실 96% · 전체 88%** |

### ⚠️ 옛 59%·98%는 **부풀려진 값이었다**

같은 파서인데 자만 바꾸니 **팩스가 59% → 35%로 떨어진다.** 정답지에 팩스가
26칸 비어 있어서, **파서가 놓친 것이 "놓쳤다"로 세어지지 않았다.**

📌 **사무실 98%가 더 뼈아프다.** 자를 고치니 같은 파서가 **91%**로 내려간다.

> **파서가 팩스를 사무실 칸에 넣고 있었는데, 정답지도 팩스를 사무실 칸에 적어
> 놓아서 서로 맞아떨어지고 있었다.**

같은 실수를 양쪽이 함께 하면 **채점은 만점을 준다.** 이 저장소에서 자를 의심해야
하는 이유가 이보다 분명할 수 없다.

### 갈라 놓은 몫

```
파서 몫  (같은 정답지)   팩스 35% → 97%   사무실 91% → 96%   전체 83% → 88%
자   몫  (같은 파서)     팩스 59% → 35%   사무실 98% → 91%   ← 거품이 빠진 것
```

**이 작업이 실제로 한 일은 팩스 35% → 97%, 사무실 91% → 96%다.**

## 5. 재측정에서 더 찾은 구멍 둘

숫자를 보고 남은 오류를 다시 뜯어보니, 팩스와 무관한 **사무실 전화 구멍**이
둘 나왔다. 같이 막았다.

| 구멍 | 예 | 장 |
|---|---|---|
| **대표번호(15xx·16xx·17xx·18xx)** — `0`으로 시작하지 않아 규칙에 안 걸림 | `T. 18779920` · `T1588-3112` | 2 |
| **OCR이 점을 쉼표로 읽음** | `Tel 02.3468,0020` | 1 |

⚠️ 대표번호는 **앞에 숫자·하이픈이 오면 안 잡는다** — `010-1588-3112`의 뒷부분을
뜯어 가면 안 된다(검사로 고정).

📌 사용자가 짚은 ***"`F` 공백 뒤 번호가 `F02`로 붙어 읽히는 경우"***는 **이미
잡고 있었다.** 숫자 **바로 앞 글자**를 보기 때문에 `F02…`든 `F 02…`든 같다.
`T02…`도 마찬가지로 문제가 아니었다 — `card_115`가 안 잡힌 것은 T가 붙어서가
아니라 **번호 자체가 `02-6360-69/LĻ`로 깨졌기** 때문이다.

## 6. 아직 남은 것 — **파서가 더 할 수 있는 것이 없다**

정답지의 점·괄호 표기를 하이픈으로 고치자(PM이 9칸) 팩스가 **88% → 97%**가
됐다. 남은 것은 이게 전부다.

```
팩스   틀림 1    ⚠️ `Fäx` 오독 — 일부러 안 받는다. R-03 쪽이다
       미검출 1  한 사진에 명함 5장인 장(card_11) — 원리상 못 잰다
사무실 미검출 3  card_115·37은 손글씨 정정이라 원문에 없다
                 card_50은 OCR이 끝자리를 다음 토큰으로 떼어 놨다
```

📌 **다섯 건 다 파서를 고쳐서 될 일이 아니다.** 오독(R-03)이거나, 한 사진에
명함이 여럿이거나, 원문에 아예 없다.
