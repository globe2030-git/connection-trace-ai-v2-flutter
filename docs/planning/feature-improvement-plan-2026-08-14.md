## F-02 · 주소 없는 명함 등록 허용 🎯 1순위

- **현재 상태(확인함)**: 주소가 **필수**라 비우면 저장이 막힌다. 차단 지점 2곳 +
  라벨 1곳:
  - `add_card_modal_view.dart:1138-1142` — `_saveCard` 명령형 검사(`rawAddress.isEmpty` → 포커스+에러)
  - `add_card_modal_view.dart:2407-2412` — 주소 필드 `validator`
  - `add_card_modal_view.dart:2405` — 라벨 `'회사 주소 (도로명) *'`(별표 = 필수 표기)
- **방안**:
  1. 위 두 검사를 제거(주소를 선택 항목으로). 라벨의 `*` 삭제.
  2. 주소가 비면 이 명함은 **'주변' 목록에 안 뜬다** — 이미 있는 `_addressGeoFailed`
     안내(`:2422~`)와 같은 톤으로, 저장 시 **한 번** 부드럽게 고지하거나 주소 칸
     아래에 상시 안내. "주소가 없으면 주변 거리 기능에서 제외됩니다" 수준.
  3. 지오코딩 흐름 점검 — 주소 빈 값이 `AddressGeocodingService`로 넘어가
     불필요한 실패/재시도를 만들지 않는지 확인(빈 값이면 지오코딩 skip).
- **영향 범위**: 저장 로직 + 라벨. 다른 필수 필드(이름/회사/휴대폰/이메일)는 유지.
  ⚠️ **회사·휴대폰·이메일도 테스터가 "선택으로" 요구했는지 별도 확인 필요** —
  F-02 원문은 "주소"만 명시. 지금은 이름·회사·휴대폰·이메일 4개가 여전히 필수.
- **검증**: 자동 테스트(저장 로직 분기) + 부분 테스트(등록 화면에서 주소 비우고 저장
  → 성공, 지갑에 뜨는지 / 주변에서 제외되는지).

## F-12 · 검색어 지우기 + 가까운 인맥 주소 표시 🟡 부분

- **현재 상태(확인함)**: 검색 X 버튼은 완료(추가 194). `_NearbyContactTile`
  (`radar_view.dart:1402~`)은 **이름·직함·회사**만 보여주고 **주소는 없음**(1444~1475).
- **방안**: 타일 회사 줄 아래(또는 회사 대체)에 `contact.address` 한 줄 추가
  (`maxLines:1`, ellipsis, `textMuted`). 주소 빈 경우(F-02 결과) 줄 자체를 숨김.
- **영향 범위**: `_NearbyContactTile` 1곳. 지갑 목록 타일과 형태를 맞춰 온 이력이
  있으므로(1399), 지갑 타일에도 같은 처리를 할지 사용자에게 확인.
- **검증**: 부분 테스트(주변 화면 타일에 주소 표시 + 주소 없는 명함은 줄 숨김).

## F-06 · 삭제 발견성 + 일괄 삭제 ⬜ 남음

- **현재 상태(확인함)**: 지갑 목록은 **왼쪽 스와이프 삭제만** 있음
  (`wallet_view.dart:359` `Dismissible`, `:519-523` 주석 — 목록에 삭제 버튼을
  일부러 안 둠, 사용자 결정 2026-08-10). 확인 다이얼로그 있음(`:576`).
- **긴장 관계**: "삭제 버튼을 목록에 두지 않는다"는 **과거 사용자 결정**과
  "삭제 발견성을 높여 달라"는 **테스터 요청**이 부딪힌다 → **사용자 확인 필요**.
- **방안(안)**: 지갑 상단에 "선택" 모드 진입(예: 우상단 액션). 진입 시 각 행에
  체크박스, 하단에 "N개 삭제" 바. 스와이프 삭제는 그대로 유지(단건 빠른 삭제).
  선택 모드가 "발견성"과 "일괄"을 동시에 해결.
- **영향 범위**: `wallet_view` 목록 상태(선택 모드 플래그·선택 집합), 삭제 호출은
  기존 `deleteContact` 반복. 새 위젯이라 자동 테스트로 상태 전이 커버 가능.
- **검증**: 부분 테스트(선택→다건 삭제→목록 갱신, 확인 다이얼로그) + 자동 테스트
  (뷰모델 선택 상태).

## F-04 · 자동 추출 정보와 내 메모 분리 / F-09 · 읽기 전용·입력 영역 시각 구분 ⬜ 남음

- **현재 상태(확인함)**: 등록 폼은 OCR가 채운 값과 사용자가 친 값을 **같은 모양의
  입력칸**으로 보여준다. 다만 **어느 칸을 OCR가 채웠는지 추적하는 데이터는 이미 있다**
  — `_ocrParsedSnapshot`(add_card_modal, "저장 시점 비교" 용도, `:81~`,
  `:403~418`), `_lastScanFilledKeys`. F-04/F-09는 이 정보를 **시각화**만 하면 됨.
- **방안**:
  - F-09: OCR가 채운 칸에 옅은 배지/좌측 색막대("자동 인식") 표시. 사용자가 그 칸을
    고치면 배지 제거(이미 값 변경 비교 로직 존재).
  - F-04: 'AI에 보낼 정보'(자유 메모)를 명함 기본 정보와 **시각적으로 다른 블록**으로
    분리 — 배경/섹션 헤더로 "명함에서 읽은 정보"와 "내가 덧붙인 메모"를 구분.
- **영향 범위**: `_buildFormField`에 "자동 인식 여부" 파라미터 추가 + 스타일 분기.
  로직 신규 없음(스냅샷 재활용).
- **검증**: 부분 테스트(스캔 후 배지 표시, 수정 시 사라짐 / 메모 블록 구분).
