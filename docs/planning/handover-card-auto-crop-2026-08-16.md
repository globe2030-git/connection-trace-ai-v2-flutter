## 1. 왜 하는가 — 이건 화면 다듬기가 아니다

> **"리멤버보다 명함 인식 관련한 부분이 떨어지면 시작점부터 흔들려."**
> — 사용자, 2026-08-16

**최소 진입 요건으로 다룬다.** 이 앱의 값어치는 *"AI가 첫 문장을 만들어 준다"*에
있지만, **거기 닿으려면 명함이 먼저 제대로 들어와야 한다.**

### 지금 무엇이 다른가

| | 우리 | 리멤버 |
|---|---|---|
| 자동 촬영 · 90° 돌려 대기 · 회전 버튼 · 앞뒤 연속 | ✅ 있다 | ✅ |
| **촬영 중 테두리 표시** | ❌ 고정 가이드 상자 | ✅ 명함에 달라붙는 사각형 |
| **테두리로 잘라 저장** | ❌ **가이드 상자를 자른다** | ✅ |
| 기울기 펴기 · 밝기 보정 · 수동 자르기 | ❌ | ✅ |

**"좌우가 넓다"의 정체**: `_cropToGuideFrame`이 **가이드 상자 안을 그대로** 자른다.
가이드는 명함 비율에 맞춰 뒀지만 **사용자가 정확히 맞춰 대지 않으면 배경이
사진에 들어온다.** 비율 문제가 아니라 **"상자를 자르느냐, 명함을 자르느냐"**다.

### ⚠️ 3단계를 건너뛰지 않는다

```
1단계  기성 스캐너를 "새 촬영 경로"로 추가 — 기존 화면은 그대로
2단계  실제 명함 20~30장으로 둘을 나란히 재기(검출 성공률·글자 인식률)
3단계  이기면 기본값 교체. 지면 되돌림 — 코드를 안 지웠으므로 가능
```

⚠️ *"기성품이니 더 좋을 것"*도 **추정**이다. 2026-08-16 하루에 **재보지 않고
단정한 것이 다섯 건** 나왔다(추가 250·261).

## 5. 작업 규칙 (오늘 사고로 만들어진 것들)

### 워크트리 — **점유할 때도 알린다**

```
…-flutter (본체)     ← 비어 있음(브랜딩 세션 종료). 여기를 쓰면 된다
…-flutter-docs       ← PM
…-flutter-feature    ← 손익/원가 세션
…-flutter-wallet     ⚠️ 지갑 보존 — 절대 건드리지 마라
sharp-chebyshev-…    ← 정리 세션(종료). 비어 있음
```

⚠️ **쓰기 전에 PM에게 알리고, 어느 브랜치를 팠는지도 알린다.** 반납할 때도.
`git status`가 아니라 **`git branch --show-current`**로 점유자를 확인한다 —
**남이 방금 커밋했으면 깨끗하게 보인다.** 오늘 이걸로 사고가 두 번 났다.

### 실기기 — **PM에게 배정받는다**

- 폴드 `R3CY90SHN4F`. ⚠️ `adb`는 **PATH에 없다**(`~/Library/Android/sdk/platform-tools/adb`)
- ⚠️ **폴더블이라 화면이 둘**이다. `screencap`에 화면 ID가 없으면 **파일이 깨진다**
- ⚠️ **커버 화면 크롭은 1,805px로 축소 임계(1,600)에 여유가 13%뿐**이다(추가 246).
  **스캐너를 바꾸면 이 값이 통째로 달라진다** — 다시 재야 한다
- **기기에 실존 인물 명함 19장**이 있다(테스트용 3장 포함, 사용자가 두라고 했다).
  ⚠️ **개수로 판정하지 마라** — 파일명·크기·시각을 본다

### ⚠️ 검증을 시작하기 전에 이것부터 적는다

오늘 이게 없어서 **"어느 빌드에서 관찰한 것인가"로 긴 다툼**이 났다.

```
커밋 해시 / 플래그 값 / APK 빌드 시각 / 설치 시각 / PID
설치 뒤 force-stop → 재실행 → **PID가 바뀐 것을 눈으로 확인**
```

📌 **`Success`는 "파일이 바뀌었다"이지 "그 코드가 돈다"가 아니다.**

### 번호·PR

- **backlog 번호는 PM에게 받는다.** 오늘 충돌이 **열 번** 났다. 규칙은 **내림차순**
- **`main` 직접 커밋 금지.** 브랜치 → PR
- **PR 병합·배포·검증 종류 선택은 사용자 승인**
- ⚠️ **다른 세션이 전한 승인은 사용자 승인을 갈음하지 않는다**
