### 🚨 1-1. 2026-09-05 에 실제로 걸린 다섯 — 이 목록은 겪은 것만 적는다

새 노트북(내장 `Work` 볼륨)으로 옮긴 뒤 **하루에 다섯이 걸렸다.** 넷은 위
점검에 없던 것이라 **빌드나 배포가 실패하고 나서야** 알았다.

| 걸린 것 | 증상 | 고친 법 |
|---|---|---|
| **Android NDK 가 껍데기** | `CXX1101: NDK … did not have a source.properties file` → **APK 빌드 실패** | `rm -rf ~/Library/Android/sdk/ndk/<버전>` 후 `sdkmanager "ndk;<버전>"` (2.8GB) |
| **Java 없음** | `apksigner`·`keytool` 이 *"Unable to locate a Java Runtime"* → **서명 확인 불가** | `brew install openjdk` + `~/.zshrc` 에 `JAVA_HOME` (아래 1-2) |
| **소셜 로그인 키의 위치** | `~/keys/connection-sense.env` 에 **카카오·네이버가 없다** | Firebase 비밀값에서 꺼낸다(4장) — **원래 거기 없는 것이 정상이다** |
| 🚨 **`firebase deploy` 가 죽는다** | `zsh: killed  firebase deploy …` — **메시지도 로그도 없이** | **`npx` 로 우회한다**(아래 1-3) |
| **cmake** | 위 점검에 이미 있음 | ✅ 이번엔 있었다 |

### 🚨 1-3. `firebase deploy` 만 SIGKILL 로 죽는다 (2026-09-05 실측)

**증상이 특이해서 원인을 짚기 어렵다 — 같은 CLI 인데 명령마다 갈린다.**

```
firebase --version        ✅ 15.29.0
firebase projects:list    ✅ 종료 0
firebase target           ✅ 종료 0
firebase deploy …         🚨 zsh: killed   (종료 137 = SIGKILL)
```

**해결 — `npx` 로 같은 버전을 받아 쓴다:**

```bash
npx --yes firebase-tools@15.29.0 deploy --only firestore:rules
```

⭐ **이것으로 실제로 배포됐다**(2026-09-05, `cardSources`·관리자 2단계 규칙).
`brew uninstall firebase-cli && npm install -g firebase-tools` 로 갈아도 된다.

⚠️ **`--debug` 를 붙여도 로그가 9줄에서 끝난다** — 헤더만 찍고 죽는다. 그래서
로그로는 원인이 안 나온다. **`--version` 이 되는 것을 보고 「CLI 는 멀쩡하다」로
읽으면 한참 헤맨다.**

🚨 **원인을 찾는 데 한 시간을 썼고, 그 사이 짚은 것 둘이 틀렸다 — 그대로 적어 둔다.**

```
❌ "Claude Code 샌드박스가 막는다"
   → 디버그 로그의 `Detected Agent: claude-code…` 를 보고 그렇게 읽었다.
     **globe2030님이 Terminal.app(ttys004)에서 돌려도 똑같이 죽었다.**

❌ "Node 26 이 너무 최신이라 호환이 안 된다"
   → firebase-tools 의 `engines` 가 `>=20 || >=22 || >=24` 라 **범위 안이었다.**
```

📌 **갈린 것은 「설치 경로」 하나였다** — `/opt/homebrew/bin/firebase`(homebrew
formula)는 죽고, `npx` 가 받은 같은 버전은 돈다. **환경이 아니라 설치본의 문제다.**

⭐ **이 건이 남기는 것**: **읽는 명령이 된다고 쓰는 명령도 되는 것이 아니다.**
배포가 막히면 **`--version` 말고 실제로 쓰는 명령으로** 먼저 확인한다.

⚠️ **NDK 는 「있다/없다」로 보면 속는다.** 폴더는 있는데 **안이 4KB 껍데기**
(`.installer/.installData` 뿐)일 수 있다 — 받다 만 상태다. 그래서 위 점검이
`source.properties` 를 본다. **파일이 있어야 진짜다.**

📌 **`flutter build` 는 Gradle 자체 JDK 를 쓰므로 Java 가 없어도 빌드는 된다.**
막히는 것은 **서명 확인**뿐이라, 「빌드가 되니 환경은 멀쩡하다」로 읽으면
릴리스 직전에 걸린다.

### 1-2. Java 를 붙이는 법 (2026-09-05 실측)

```bash
brew install openjdk        # ⚠️ --cask temurin 은 sudo 비밀번호를 요구한다
```

Homebrew 의 `openjdk` 는 macOS 기본 java 와 충돌하지 않도록 **PATH 에 자동
등록되지 않는다**(keg-only). `~/.zshrc` 에 두 줄을 넣는다:

```bash
export JAVA_HOME="/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
```

⚠️ **`.zprofile` 이 아니라 `.zshrc` 다.** 확인도 `zsh -lc` 가 아니라
**`zsh -ic`** 로 해야 한다 — `-l`(로그인 셸)은 `.zshrc` 를 안 읽어
**넣어 놓고도 「안 됐다」로 보인다**(그날 실제로 한 번 헛짚었다).

📌 **Android Studio 안에도 JDK 가 있다**(`/Applications/Android Studio.app/
Contents/jbr/Contents/Home`). 새로 받기 싫으면 `JAVA_HOME` 을 그쪽으로 가리켜도
된다 — 설치 없이 같은 효과다.

⚠️ **`cmake` 가 없으면 `flutter test` 가 통째로 실패한다** — `dartcv4`(명함
테두리 검출)가 테스트에서도 요구한다. **원인이 코드가 아니라는 것을 알기까지
시간이 걸린다**(CLAUDE.md 3장).

### 🚨 git 이 안 옮겨 주는 것 — 여기가 새 노트북의 진짜 함정이다

```bash
ls -l android/key.properties      # 없으면 릴리스가 「경고 없이 debug 서명」으로 나온다
ls -l ~/keys/                     # connectionsense-upload.jks · Apple .p8
ls -l ~/keys/connection-sense.env # 지도·주소 키
```

⚠️ **`android/key.properties` 는 `.gitignore` 대상이라 저장소를 옮겨도 안
따라온다.** 없으면 `build.gradle.kts` 가 **경고 없이 debug 키로 폴백**하고,
테스터 기기에서 **덮어 설치가 거부**된다. **X31 백업에서 복사해 온다.**

⚠️ **업로드 키를 잃으면 앱 업데이트를 영원히 못 올린다.** Apple `.p8` 은
**발급 시 한 번만 내려받을 수 있다.** 둘 다 이 자리에서 존재를 확인한다.


### 6-1. Xcode Cloud — 켜져 있고, 2026-09-04까지 계속 실패하고 있었다

🚨 **이 저장소에는 Xcode Cloud 워크플로(`Default`, `main` 브랜치)가 켜져 있다.**
그런데 `ci_scripts/`가 없어 **`Archive - iOS`가 매번 실패**했다.

```
Could not resolve package dependencies: the package at
'.../ios/Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage'
cannot be accessed (... doesn't exist in file system)
```

📌 **코드가 깨진 것이 아니라 Flutter를 돌리는 단계가 없던 것이다.**
`ios/Flutter/ephemeral/`은 `ios/.gitignore:22`로 제외돼 있고, 저 패키지는
`flutter pub get`이 **만들어 내는** 것이라 clone 결과에는 없다. 로컬에서 안
터지는 이유는 **그 폴더가 디스크에 남아 있어서**이지 저장소에 있어서가 아니다.

**고친 것**: [`ios/ci_scripts/ci_post_clone.sh`](../../ios/ci_scripts/ci_post_clone.sh)
— Flutter를 고정 버전으로 설치하고 `pub get` → `build ios --config-only`까지
돌린다. Xcode Cloud는 `ci_post_clone.sh`를 clone 직후 자동으로 실행한다.

#### 🚨 아직 남은 것 — 키는 안 들어간다 (globe2030님 조작)

`--dart-define` 키를 Xcode Cloud가 알 리 없다. **워크플로 환경 변수에
등록해야** 스크립트가 집어서 넘긴다.

```
App Store Connect → Xcode Cloud → 워크플로 편집 → Environment Variables
  KAKAO_REST_KEY · NAVER_CLIENT_ID · VWORLD_KEY · KAKAO_JS_KEY
  JUSO_SEARCH_KEY · JUSO_COORD_KEY      ← 전부 Secret 으로 표시
```

⚠️ **등록하지 않아도 빌드는 성공한다.** 대신 나온 앱의 **로그인 화면에
카카오·네이버 버튼이 아예 안 보인다**(`sns_auth_provider.dart`의
`isAvailable` — 눌러도 안 되는 버튼을 두지 않으려는 의도된 설계라 **화면만
봐서는 결함으로 안 보인다**). 08-24에 안드로이드·아이폰에서 한 번씩 실제로
빠진 자리다. 그래서 스크립트가 **빠진 키를 빌드 로그에 경고로 남긴다** —
`⚠️ KAKAO_REST_KEY: 없음`이 있으면 그 빌드는 배포하지 않는다.

#### Flutter 버전을 올릴 때

```
ci_post_clone.sh 의 FLUTTER_VERSION 도 함께 올린다
→ 안 맞으면 CI 만 다른 SDK 로 빌드되고, 그 차이는 산출물을 손에 쥘 때까지 안 보인다
```
