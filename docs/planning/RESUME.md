### ⭐ 설계를 짜다 한 곳을 고쳤다 — 이어받는 사람이 먼저 알아야 한다

설계 §3-2 는 *"만료 계산은 TypeScript 한 곳에만"* 인데, 기존 관리자 조작에도
20분 만료를 걸려면 rules 도 판정해야 한다. 둘 다 하면 **상수가 두 곳에 생긴다**
(ADMIN-VULN-001 과 같은 구조).

```
adminSessionExpiresAt(session) = min(활동+20분, 인증+12시간)   ← TypeScript 가 계산
rules 는  request.time < expiresAt  한 줄로 비교만 한다        ← 숫자를 모른다
```

⭐ **한 필드가 두 만료를 다 담는다.** 20분을 30분으로 바꿔도 rules 는 안 고친다.

### ⬜ 남은 것 — `firestore.rules` (아직 한 줄도 안 건드렸다)

```
① adminSessions/{uid}   allow read, write: if false    전면 차단 · Admin SDK 만
② config/admins         allow read, write: if false    🚨 읽기도 막는다
③ isAdmin() 에 신선도    get(adminSessions/$(uid)).data.expiresAt 비교 추가
```

**②의 이유**: 관리자가 그 문서를 고칠 수 있으면 **다른 관리자의 2차 인증 번호를
자기 것으로 바꿀 수 있다** — 그러면 2차 인증이 아무것도 막지 못한다.

### 🚨 ③을 배포할 때의 함정 — 이것 때문에 멈춰도 된다

```
isAdmin() 을 고치면 기존 관리자 조작이 전부 2차 인증을 요구하게 된다
   → 콘솔 화면(4단계)이 없는 상태로 배포하면
   → 🚨 관리자가 아무것도 못 하게 된다 (인증할 화면이 없으니까)
```

⭐ **③은 화면(4단계)과 함께 배포해야 한다.** ①②는 먼저 배포해도 안전하다 —

#### 🚨 돌아온 것 — **전문**

⚠️ **줄여 적지 않는다.** 처음에 앞 한 줄만 적었다가 고쳤다 — 원인을 좇으려면
**뒷부분이 더 중요하다**(어디까지 되고 어디부터 막히는지가 거기 있다).

```json

  "success": false,
  "message": "Failed to send to bridge:session_013QGj2WPa6UQ2V3DCeTXnDM: auth: this cloud session cannot message other sessions yet — its credential is accepted for its own work but not for delivering to another session, so a reply from here is not possible; say so in your response instead of retrying"
}
```

옮기면: *"이 클라우드 세션은 아직 다른 세션에 메시지를 보낼 수 없다. **이 세션의
자격증명은 자기 작업에는 받아들여지지만 다른 세션으로의 전달에는 받아들여지지
않는다.** 그래서 여기서 답장하는 것은 불가능하다. 재시도하지 말고 그 사실을
응답에 밝혀라."*

#### 이 문구가 **실제로 말하는 것**

```
분류      auth        인증·권한 문제다. 네트워크나 주소 오류가 아니다
경계      자기 작업 ✅ / 남에게 전달 ❌     ← 자격증명 자체는 유효하다
범위      this cloud session               세션 종류에 걸린 제약으로 읽힌다
지시      재시도하지 말라
"yet"                                     나중에는 될 수 있다는 뉘앙스
```

#### ⚠️ 이 문구가 **말하지 않는 것** — 짐작으로 채우지 않는다

```
⬜ 계정·워크스페이스 설정으로 켤 수 있는 것인지
⬜ Claude Code 버전이나 환경(anthropic_cloud) 때문인지
⬜ 상대가 bridge 세션이라 그런지, 아무 세션에나 그런지
⬜ 언제 풀리는지
```

📌 **실측으로 아는 것은 하나뿐이다 — 받는 것은 된다.** 같은 날 빌드(터미널)
세션이 보낸 메시지가 실제로 도착했다. **채널은 살아 있고 방향만 막혀 있다.**

⚠️ **한 번만 시도했고 재시도하지 않았다.** 오류가 그렇게 지시했고 `auth` 라
반복해도 같을 종류다. 🚨 **다른 상대(bridge 가 아닌 세션)로는 시험하지 않았다**
— 시험하려면 남의 세션에 시험용 메시지를 넣어야 해서 그냥 하지 않았다.
**그래서 위 셋째 줄(⬜)이 아직 안 갈렸다.**

📌 **그래서 클라우드 세션의 보고는 이 문서(와 커밋)로 온다.** 안 보내는 것이
아니라 못 보내는 것이다 — **PM 이 먼저 물어야 답이 온다.**

⚠️ **세션 이름은 도중에 바뀐다.** 오늘 `…-97` → `…-9a` 로 바뀌었다.
🚨 **바뀌지 않는 것은 대괄호 안의 ref 다** — 위 표에 그 값을 적어 둔다.

## 7. 이 프로젝트에서 반복해 확인된 것 (짧게)

1. **"테스트 통과 = 동작함"이 아니다.** 오늘 잡은 결함 넷 중 셋이 테스트·코드
   리뷰로는 안 나오는 종류였다 — 메모에 박히던 가짜 문구(AI 요청에 실려 나감),
   스크린리더 중복 읽기(화면상 정상), 켜면 실패하는 토글.
2. **"의도한 실패"도 사용자 눈에는 결함이다.** 게이트를 닫아 둔 기능은
   화면에서도 닫아야 한다.
3. **정리·마이그레이션 도구는 실제 데이터에 돌려 봐야** 판정 규칙의 사각지대가
   드러난다(추가 226).
4. **회귀 방지 테스트는 검사 지점이 하나면 부족하다**(추가 225).
5. **문서 사이 상태가 어긋나면 이미 답한 질문을 다시 묻게 된다**(추가 218).
