## 3. 법무 회신 후 — 켜는 순서 (건너뛰면 고지 없는 수집이 된다)

```
① 법무 회신 (고지 기간 7일/30일 확정)
      ↓
② 방침 v2.2 게시     firebase deploy --only hosting:legal      ← 사용자 승인
      ↓  (고지 기간 경과를 기다린다)
③ rules 배포         firebase deploy --only firestore:rules,storage  ← 사용자 승인
      ↓
④ 플래그 켜기        kCardPhotoBackupEnabled = true
      ↓
사진 업로드·복원 동작 + 설정에 동의 토글 나타남
```

- ②를 건너뛰고 ④를 켜면 **고지 없이 제3자 사진을 수집**하게 된다.
- `test/card_photo_backup_gate_test.dart`가 플래그를 고정하고 있어, ④를 하려면
  그 테스트를 **함께 고쳐야 한다**(실수로 켜지는 것을 막는 장치).
- ⚠️ **`firebase deploy --only hosting`처럼 타겟 없이 배포하면 `legal`과 `admin`이
  둘 다 나간다.** 관리자 콘솔만 배포할 때는 반드시 `--only hosting:admin`.

## 7. 이 프로젝트에서 반복해 확인된 것 (짧게)

1. **"테스트 통과 = 동작함"이 아니다.** 오늘 잡은 결함 넷 중 셋이 테스트·코드
   리뷰로는 안 나오는 종류였다 — 메모에 박히던 가짜 문구(AI 요청에 실려 나감),
   스크린리더 중복 읽기(화면상 정상), 켜면 실패하는 토글.
2. **"의도한 실패"도 사용자 눈에는 결함이다.** 게이트를 닫아 둔 기능은
   화면에서도 닫아야 한다.
3. **정리·마이그레이션 도구는 실제 데이터에 돌려 봐야** 판정 규칙의 사각지대가
   드러난다(추가 226).
4. **회귀 방지 테스트는 검사 지점이 하나면 부족하다**(추가 225).
5. **문서 사이 상태가 어긋나면 이미 답한 질문을 다시 묻게 된다**(추가 218).
