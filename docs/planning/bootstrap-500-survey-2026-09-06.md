## 3. ③ 무엇이 던졌나 — **Firestore 접근이 통째로 거부됐다**

**한 요청 안에서 이 순서로 났다:**

```
1  WARNING  Failed to validate AppCheck token … Decoding App Check token failed
2  WARNING  Allowing request with invalid AppCheck token because enforcement is disabled
            ⭐ 막지 않았다 — AppCheck 은 원인이 아니다
3  WARNING  **config/billing 조회 실패 — 기본 무료 회차/reset 모드로 폴백**
4  ERROR    🚨 **Unhandled error Error: 7 PERMISSION_DENIED: Missing or insufficient permissions**

⭐ **3번이 결정적이다.** `config/billing` **읽기도 실패했다** — 즉 **특정 문서의
규칙 문제가 아니라 Firestore 접근 전반**이 막힌 것이다. 📌 이 함수는 Admin SDK 를
쓰므로 `firestore.rules` 를 안 탄다 — **`PERMISSION_DENIED` 는 IAM/서비스 계정
쪽**을 가리킨다.

🚨 **그리고 3번은 잡혔는데(폴백) 4번은 안 잡혔다.** 같은 원인인데 **한쪽만 방어돼
있었다** — 그래서 500 이 됐다.

⬜ **왜 그 10분에 권한이 없었는지는 못 쟀다.** 배포·IAM 변경·서비스 계정 회전 중
무엇인지 갈리지 않았다. **2026-08-20 의 배포 이력을 봐야 한다.**

## 5. 🚨 남는 위험 — **실패가 어디에도 안 보인다**

```

⭐ **이 판단 자체는 옳다** — 주석대로 *"부가 기능이라 로그인 자체를 막지 않는다"*.
🚨 **문제는 「막지 않는 것」이 아니라 「아무도 모르는 것」이다.**

```
이용자   무료 회차·리퍼럴 코드가 없는데 **왜인지 모른다**
개발     🚨 **서버 로그를 뒤져야만 안다** — 오늘 우리가 그렇게 알았다
```

📌 오늘 규약에 들어간 「초록이 무엇을 뜻하는가」와 같은 결이다 — **실패가 조용하면
「안 난 것」과 구별되지 않는다.** 그리고 이 저장소가 겪은
*"재시도 로직이 죽어 있었다 — 서비스는 정상, 부르는 쪽이 없었다"* 와도 같은 자리다.

⚠️ **다만 이번엔 자가 복구가 있어서 실제 피해는 없었다.** 그래서 **급하지 않다.**
