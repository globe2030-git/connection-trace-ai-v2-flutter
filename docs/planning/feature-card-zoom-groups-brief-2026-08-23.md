## 426 — 편집·상세에서 명함 크게 보기 (앞/뒤 포함)

**요청 원문**: *"편집에 명함을 크게 볼 수 있도록 해주면 좋겠어. 명함 앞과
뒤가 있을 수 있으니까 그것도 감안하고."*

### 화면 (캔버스 ①②)

1. **편집 화면 상단에 명함 사진 크게** 배치(높이 ~196dp 카드), 좌하단
   **앞면/뒷면 세그먼트**(뒷면 없으면 숨김), 우하단 돋보기 버튼.
   아래 안내 한 줄: "사진을 누르면 크게 볼 수 있어요."
2. **전체화면 확대 뷰어**: 사진 탭 → 검은 배경 전체화면. 핀치 줌 + 더블탭
   줌, **좌우 스와이프로 앞/뒤 전환**(페이지 점 표시 + "앞면 1/2" 배지),
   회전 버튼(보기 회전만 — 저장물은 안 건드림), 닫기 X.
3. 상세 화면(⑤ 시트)의 기존 이미지 영역도 같은 뷰어를 재사용해 탭 확대.

### 구현 노트

- 이미지 소스는 로컬 암호문 복호화 캐시(ContactImageService) — **평문 파일을
  새로 만들지 않는다**(메모리 표시만). 회전 보기도 위젯 변환으로만.
- 뷰어는 공용 위젯 하나로(편집·상세 재사용).
- 편집 중 확대는 "값과 대조하며 고치기" 용도 — 뷰어에서 돌아와도 입력 중이던
  폼 상태가 유지돼야 한다.

### 인수 기준

- 앞뒤 2장 명함: 세그먼트 전환·전체화면 좌우 전환 모두 동작, 1장이면 UI 숨김
- 핀치 줌·더블탭 줌 동작, 닫으면 편집 폼 상태 그대로
- 평문 이미지 파일이 디스크에 생기지 않는다(기존 캐시 정책 유지)

## 427 — 그룹 + 명함지갑 정렬

**요청 원문**: *"명함이 그룹이 없네. 그룹별로 볼 수 있으면 좋겠는데"* +
*"그룹별은 명함지갑에도 정렬도 넣으면 좋겠어."*

### 화면 (캔버스 ③④)

1. **그룹 지정 바텀시트**(상세·편집에서 진입): 다중 선택(한 명함 여러 그룹),
   그룹별 인원 표시, **검색창 = 새 그룹 만들기 겸용**(입력값과 일치하는
   그룹이 없으면 "'○○' 새 그룹 만들기" 행 노출). 리멤버의 별도 관리 화면
   대신 검색 통합으로 단순화(설계 결정).
2. **명함지갑 상단 그룹 칩**: [전체] [그룹A n] [그룹B n] … [+ 그룹]. 가로
   스크롤. 그룹 미지정 명함은 "전체"에서만 보인다는 안내 한 줄.
   ⚠️ ⑦(상단 고정 헤더)의 기존 구조를 해치지 않는다 — 칩 행은 고정 헤더에
   포함.
3. **정렬 메뉴**(상단 버튼): 최근 등록순(기본) · 이름 가나다순 · 회사명순 ·
   가까운 거리순. 선택은 기기에 기억(개인정보 아님 — 일반 키 허용).
4. 명함 카드에 소속 그룹 꼬리표(최대 2개 + n).

### 저장 구조 (구현 전 확정 필요 사항)

- 그룹은 **이용자 생성 데이터**: 그룹 목록(이름·생성일) + 명함별 그룹 참조.
- **서버 백업에 포함**돼야 기기 변경 시 그룹이 살아남는다 — 기존 명함 백업과
  같은 암호화 경로. ⚠️ 저장 구조 변경이므로 **마이그레이션 왕복 확인이 전체
  테스트급**(추가 425와 같은 절차 — 아이폰에서).
- 방침 검토: 그룹명은 이용자가 만든 값으로 "저장·조회·관리" 고지 목적 안으로
  판단되나, **스펙 확정 시 legal-researcher 1회 확인**을 거친다(그룹명에
  제3자 정보가 들어갈 수 있음 — 예: "삼성전자 사람들").

### 인수 기준

- 그룹 생성·지정·해제·이름변경·삭제(삭제 시 명함은 유지, 참조만 제거)
- 칩 필터·정렬이 검색과 조합돼도 옳게 동작
- 재설치 왕복에서 그룹 복원(전체 테스트 슬롯)
