## 0. 왜 이것이 필요한가 — **이게 없으면 결정을 못 합니다**

사용자가 새 자르기를 실제로 써 보고 말했습니다.

> **"각 필드에 넣는 것은 아직… 부족해 보이네."**

그리고 **"새 방식(테두리 검출)을 기본으로 바꿀지"**가 이 숫자에 걸려 있습니다.
2단계 지시서 4절이 판정 기준을 미리 정해 뒀는데, **필드 숫자가 없어 아직 아무
판정도 못 내렸습니다.**

⚠️ **지금 판정을 내리면 그건 짐작입니다.** 어제 이 저장소에서 *"재보지 않고
단정한 것"*이 **여섯 번** 뒤집혔습니다.

이유가 여기 있습니다.

## 2. 도구는 이미 있습니다 — **새로 만들지 마십시오**

### 정답지 만들기

```bash
open tool/ocr_review/index.html
```

**설치할 것도 띄울 서버도 없습니다.** 실물 명함과 인식 결과를 나란히 놓고 정답을
남기는 로컬 도구입니다.

⚠️ **왜 정답지가 필요한가**: 정답지가 없으면 **잴 수 있는 것이 채움률뿐**입니다.
2026-08-14에 실제로 그 함정에 빠졌습니다 — *"오분류 0장"*이라고 적힌 수치가 값의
**모양만** 본 것이라, **빈 값을 전부 "정상"으로 세고** 있었습니다(추가 198).

### 채점

```bash
TSV=~/Downloads/scan_result.tsv \
TRUTH=~/Downloads/ocr_truth.tsv \
flutter test test/ocr_accuracy_score_test.dart
```

⚠️ **이 테스트는 "통과"가 목적이 아니라 숫자를 뽑는 것이 목적입니다.** 파일이
없으면 **조용히 건너뜁니다**(CI에 개인정보를 안 두므로). **출력을 봐야 합니다.**

**재는 칸 아홉**: 이름 · 회사 · 직함 · 휴대폰 · 사무실 · 이메일 · 우편번호 ·
주소 · 상세주소

**판정 다섯**: 일치 / 틀림 / 미검출 / 오검출 / **둘 다 빔(분모 제외)**

📌 *"둘 다 빔"*을 빼는 이유: 명함에 원래 전화가 없는 경우까지 *"맞혔다"*고 세면
**정확도가 부풀려집니다.**

⚠️ **비교 전 정규화는 앞뒤 공백만** 정리합니다. **그 이상 손대지 마십시오** —
*"맞다고 쳐 주는"* 범위가 슬금슬금 넓어져 숫자가 부풀려집니다.

## 3. 무엇을 재나 — **세 경로를 같은 명함으로**

지금 앱에 촬영 경로가 **셋**입니다. debug 스위치로 고릅니다.

| | 무엇 | 특징 |
|---|---|---|
| **기존 가이드** | 고정 상자를 자름 | 배경이 함께 들어감 · 크기 일정(커버 1,805 · 편 2,934) |
| **A안 문서 스캐너** | OS 스캐너 화면 | ⚠️ 아이폰은 문서용이라 아쉬움 |
| **B′ 테두리 검출** | 우리 화면 + OS 검출 | 명함만 자름 · **크기가 촬영 거리에 좌우**(1,208~2,353) |

⚠️ **같은 명함을 세 경로에 각각** 넣어야 비교가 됩니다. 스위치가 그것을 위해
있습니다.

### 표본

**정답지가 이미 있는 17장을 그대로 쓰기를 권합니다.** 새로 만들면 정답지
작성에만 시간이 다 갑니다. ⚠️ **실물 카드가 손에 있어야** 세 경로로 다시 찍을 수
있습니다.

## 4. 판정 기준 — **미리 정해져 있습니다**

**재고 나서 기준을 정하면 결과에 맞춰 기준이 움직입니다.**

| 결과 | 판단 |
|---|---|
| 검출·필드 **둘 다 새 경로가 나음** | 3단계로 — **기본값 교체** |
| 검출은 나은데 **필드가 나빠짐** | ⚠️ **멈춘다.** 원인부터 — 자른 뒤 글자가 잘렸을 수 있다 |
| **비슷** | 교체하지 않는다. **의존성만 늘어난다** |
| 새 경로가 **더 나쁨** | 되돌린다. 코드는 남기고 스위치만 끈다 |

⚠️ **"조금 나음"으로 교체하지 않습니다.**

## 5. 📌 이 측정이 함께 답하는 것

**필드별 숫자가 나오면 다음 작업이 자동으로 정해집니다.**

| 어디가 나쁜가 | 다음에 할 것 |
|---|---|
| **글자 자체가 틀림**(`길`→`킬`) | **R-03** 다중 OCR 패스 → **E-04**가 닫힌다 |
| 글자는 맞는데 **엉뚱한 칸에 들어감** | **R-05** 좌표 기반 분류 |
| 특정 형식만 틀림(전화·우편번호) | **R-04** 규칙 보강 — 가장 싸다 |

📌 **지금 이 중에 고르면 찍는 것입니다.**

### ⚠️ 그리고 아직 안 풀린 물음이 하나 있습니다

**새 경로가 해상도에서 유리한가 불리한가** — 어제 두 번 말이 뒤집혔습니다.

```
가이드   명함 X px → 배경 붙여 1805 → 1600으로 축소 → 명함 0.89X
B′       명함 X px → 그대로 1326    → 축소 없음      → 명함 X
```

⚠️ **이건 계산이고 실측이 아닙니다. 결론으로 쓰지 마십시오.**
**이번 측정이 그 답입니다** — 인식률이 실제로 어느 쪽이 나은지 보면 됩니다.

**정답지와 TSV에는 실존 인물의 이름·전화·이메일·주소가 그대로 들어갑니다.**

- ⚠️ **저장소에 넣지 마십시오.** `~/Downloads/` 같은 곳에 두고 **결과는 숫자만**
  문서에 남깁니다

- ⚠️ 로그·PR 본문에 **값을 적지 마십시오.** *"이름 92%"*는 되고 *"김○○이 틀렸다"*는
  안 됩니다

## 7. 알아야 할 함정 (어제 실물로 겪은 것)

| | |
|---|---|
| **빌드는 `profile`로** | 아이폰 debug는 **디버거 없이 아예 안 뜹니다.** 안드로이드 release는 서명이 안 맞아 앱을 지워야 하는데 **그러면 기기의 명함이 사라집니다** |
| **아이폰은 로그를 못 봅니다** | `flutter run`도 `idevicesyslog`도 앱 로그를 못 잡습니다(iOS 26). 진단값을 **화면에 띄웁니다.** 안드로이드는 `adb logcat`이 잡힙니다 |
| ⚠️ **캐시는 폴더가 둘** | `Directory.systemTemp`(`code_cache`)와 `getTemporaryDirectory()`(`cache`). **아이폰은 둘이 같습니다** |
| **개수로 판정 금지** | 기기에 명함 20장. **파일명·크기·시각**을 봅니다 |
| ⚠️ **`Success`는 코드가 돈다는 뜻이 아님** | 설치 뒤 **force-stop → 재실행 → PID 바뀐 것 확인** |
| **cmake 필요** | 없으면 `flutter test`가 통째로 실패합니다(`brew install cmake`) |

### 검증 시작 전에 먼저 적습니다

```
커밋 해시 / 빌드 시각 / 설치 시각 / PID
```
