# AI 관여 화면 설계서 (AS-IS, 2026-08-04 코드 기준)

- 작성일: 2026-08-04
- 기준: 이 저장소의 **현재 실제 코드**(BYOK 방식, 서버 프록시 전환 전). 표시된
  문구·색상·조건 분기는 전부 아래 "근거 파일" 목록의 소스를 직접 읽고
  옮긴 것이며, 상상으로 채운 값은 없다.
- 범위: "AI 대화 브리핑"(30초 AI 대화 브리핑) 기능에 직접 관여하는 화면과,
  그 기능이 정상 동작하기 위해 사용자가 반드시 거치게 되는 주변 화면
  (AI 연동 설정, 전송 동의, 소통기록 입력/가져오기)까지 포함한다. 명함
  스캔(OCR)은 로컬 ML Kit 처리이며 AI 제공사 API를 호출하지 않으므로 이
  문서 범위에서 제외했다(가정 1 참고).
- **이 문서와 `ai_briefing_screens_spec.html`의 관계(중요)**: 같은
  `docs/planning/design/` 폴더에 `ai_briefing_screens_spec.html`이 이미
  있다(2026-08-04, 커밋 `070e405`, backlog/HANDOFF에 기록이 누락돼 있던
  걸 이번에 확인해 발견 — 아래 "발견 사항" 참고). 그 문서는 **P1-8(BYOK→
  서버 프록시 전환)이 구현된 이후의 미래 상태(To-Be)** 스펙이라 Provider
  선택/API 키 입력 UI가 이미 사라진 모습으로 그려져 있다. **이 문서
  (`ai_screens_asis_spec.md`)는 그 반대로, 아직 아무것도 바뀌지 않은 지금
  코드 그대로의 AS-IS 상태**를 다룬다. 두 문서는 같은 기능의 "전/후"
  스냅샷이므로 헷갈리지 않도록 필요할 때 서로 참조할 것.

## 3. 화면별 상세

### 0-A. 레이더 화면 — AI 브리핑 진입점
**파일**: `radar_view.dart`

- **구성요소**: 대표(가장 가까운) 인맥 카드(`_FeaturedContactCard`, "연락하기"/"상세보기" 버튼), 나머지 인맥 리스트 카드.
- **AI 관련 트리거 2곳**:
  - 대표 카드의 "상세보기" 텍스트 버튼 → `viewModel.openBriefing(nearby)`
  - 리스트의 각 인맥 카드 `onTap` → `viewModel.openBriefing(contact)`
- **분기**: 근처 인맥이 하나도 없으면(`nearby == null`) 대표 카드 자리에
  "주변에 감지된 인맥이 없습니다"(GPS 정상)/"위치 권한이 없어 거리를
  표시할 수 없습니다"(GPS 비정상) 안내만 뜨고, 이 경우 AI 브리핑 진입
  트리거 자체가 화면에 없다(명함 지갑에서 인맥을 등록하거나 위치 권한을
  허용해야 트리거가 생김).
- **코드 주석 근거**: "가까운 인맥 리스트 항목을 눌렀을 때와 똑같이 AI
  브리핑 화면으로 간다 — 예전엔 명함 수정 폼이 열려서 혼동을 줬다"는
  주석이 있어, **명함 지갑(잘못 짐작하기 쉬운 화면)이 아니라 레이더
  화면에서만 AI 브리핑에 들어갈 수 있게 의도적으로 분리**돼 있다.

### 0-B. 설정 화면 — AI 연동 진입점
**파일**: `settings_view.dart` (일부)

- "데이터 및 개인정보" 섹션에 두 행이 있다.
  - **"AI 연결"** 행: `subtitle`이 `activeProvider == null`이면 "AI
    기능을 사용하지 않는 상태", 있으면 "{제공사명} API 사용 중". `value`
    배지는 "연결 안 됨"/"연결됨". 탭하면 화면 1(AI 연동 설정)이 뜬다.
  - **"AI 데이터 안내"** 행: 탭 불가능한 정적 안내
    ("AI 기능 실행 시 선택된 인맥 정보가 사용자가 연결한 AI 제공사로
    전송될 수 있습니다.") — 인터랙션 없이 정보 전달만 한다.

### 1. AI 연동(BYOK) 설정
**파일**: `ai_connection_modal_view.dart`

- **구성요소**: 상단 안내 문구("API 키는 이 기기에만 안전하게 저장되고
  서버로 전송되지 않습니다"), Claude/ChatGPT/Gemini 3장의 제공사 카드.
- **제공사 카드별 상태(3분기)**:
  1. **미연동**: "발급 페이지 열기" 버튼(외부 브라우저로 콘솔 URL 오픈,
     실패 시 인라인 배너로 URL 텍스트 안내) + 제공사별 발급 단계 5단계
     안내 + API 키 입력 필드(마스킹 토글 가능) + "연동" 버튼.
  2. **연동됨 · 비활성**(다른 제공사가 활성일 때): 마스킹된 키 미리보기
     (`sk-ant-...a1b2` 형태) + "이걸로 사용" 버튼 + "연동 해제" 버튼.
  3. **연동됨 · 활성**: 카드 테두리가 강조되고 "사용 중" 배지가 붙음 +
     마스킹 키 미리보기 + "연동 해제" 버튼만(이미 활성이라 "이걸로
     사용" 버튼은 숨김).
- **처음 연동 시 자동 활성화**: 첫 키를 저장하면 `activeProvider`가
  비어 있을 때 자동으로 그 제공사가 활성이 된다(`??=` 로직) — 사용자가
  별도로 "이걸 쓸게요"를 다시 누르지 않아도 된다.
- **에러/피드백 처리**: 이 화면은 자체 `Scaffold`가 없는 바텀시트라
  `ScaffoldMessenger` 스낵바 대신 폼 안에 그려지는 인라인 배너
  (`_buildInlineNotice`)를 쓴다(HANDOFF "5. 알아두면 좋은 설계 패턴"의
  프로젝트 공통 규칙). 배너가 뜨는 3가지 경우: 키 미입력 상태로 "연동"
  누름, 연동/해제 성공, 발급 페이지 오픈 실패.
- **관찰(문서화 목적 기록, 이번 범위에서 수정하지 않음)**: 모델명을
  덮어쓰는 `AiCredentialsRepository.setModel()`이 리포지토리 계층에
  이미 있지만, 이 화면 어디에도 모델을 직접 지정하는 입력 UI는 없다 —
  사용자는 항상 `AiProvider.defaultModel`(Claude는
  `claude-opus-5`, OpenAI는 `gpt-4o-mini`, Gemini는
  `gemini-3.6-flash`)만 쓰게 된다.

### 2. AI 브리핑 오버레이 (핵심 화면)
**파일**: `briefing_overlay_view.dart`

전체화면 오버레이(`Colors.black.withValues(alpha: 0.85)` 배경 위에 흰
카드들이 얹힘). 상단바(제목 + 닫기), 스크롤 본문(프로필 헤더 카드 → 대화
포인트 섹션 → 최근 소통 기록 섹션 → 메모), 하단 고정 "안부 전화 걸기"
버튼으로 구성.

**대화 포인트 섹션의 상태/분기(5가지, 상호 배타적)**:

| 상태 | 조건 | 화면에 뜨는 것 |
|---|---|---|
| ① AI 미연동 | `activeProvider == null` | "AI 연동이 필요합니다" 카드 + "AI 연동하기" 버튼(→ 화면 1) |
| ② 최초 로딩 | 연동됨 & `_isGenerating == true` & `_points`가 비어 있음 | 중앙 원형 스피너 |
| ③ 에러(결과 없음) | 연동됨 & `_errorMessage != null` & `_points`가 비어 있음 | 에러 카드(빨간 테두리) + "다시 시도" 버튼 |
| ④ 빈 상태(최초 진입, 캐시 없음) | 연동됨 & 에러 없음 & `_points`가 비어 있음 | "아직 생성된 AI 가이드가 없습니다..." + "AI 가이드 만들기" 버튼 |
| ⑤ 결과 표시 | `_points`가 1개 이상 | 대화 포인트 카드 최대 3개, 헤더에 "{제공사명}가 생성" 텍스트, 헤더 우측에 새로고침 아이콘 |

- **재생성 중 에러가 나도 이전 결과는 사라지지 않는다**: 상태 ⑤에서
  새로고침을 눌렀다가 실패하면, `_points`는 이전 값을 유지한 채 카드
  상단에 "새로 생성하지 못해 이전 결과를 보여드려요: {메시지}" 배너만
  얹힌다(빈 상태로 리셋되지 않음).
- **결과 카드 인터랙션**: 카드를 탭하면 `_selectedIndex`가 바뀌어 체크
  아이콘·테두리·배경이 강조된다. **관찰**: 이 선택 상태가 시각적 강조
  외에 실제로 쓰이는 곳이 코드에 없다(예: 선택한 문장을 복사하거나
  전화 연결 시 활용하는 로직 없음) — 의도된 "그냥 골라보기" UI인지,
  향후 "이 문장 복사"/"이 문장으로 전화 걸기" 같은 후속 기능이 빠진
  것인지는 코드만으로 판단 불가(아래 "확인이 필요할 수 있는 사항"
  참고).
- **재생성 트리거**: 활성 제공사가 있을 때만 헤더에 새로고침 아이콘이
  보인다. 누르면 화면 3(전송 정보 확인)이 다시 뜬다 — **재생성도 매번
  동의 절차를 거친다**(한 번 동의했다고 다음부터 생략되지 않음).
- **성공 시 캐시**: 생성된 3개 문장은 `WalletViewModel.updateContact`로
  `ContactModel.talkingPoints`에 저장돼, 다음에 같은 인맥의 브리핑을
  열면 API를 다시 호출하지 않고 캐시된 결과가 바로 상태 ⑤로 뜬다.

**최근 소통 기록 섹션**:
- 기록이 없으면 안내 카드("최근 소통 기록이 없습니다. 위 '추가'
  버튼에서...") — 빈 상태.

파싱 결과 문장이 0개면 "AI가 빈 응답을 반환했습니다."를 던진다. **주의**:
이 메시지들은 제공사 원문 에러를 그대로 노출하는 구조라, 사용자에게
다소 기술적인 문구(예: 제공사 쪽 rate limit 문구)가 그대로 보일 수
있다 — HANDOFF의 P0-3(실제 키로 E2E 검증 안 됨)과 연결되는 지점.

## 6. 가정 (해석이 갈릴 수 있어 명시)

1. **"AI가 관여하는 화면"의 범위**: AI 제공사 API를 직접 호출하는
   화면(2)뿐 아니라, 그 호출이 성립하기 위해 사용자가 반드시 거치는
   동의(3)·설정(1)·소통기록 입력/가져오기(4~6)까지 포함했다. 반대로
   명함 스캔(OCR)은 Google ML Kit **로컬** 처리라 어떤 AI 제공사
   API도 호출하지 않으므로 제외했다.
2. **상태 이름은 코드 상 enum이 아니라 이 문서에서 붙인 서술적 이름**
   이다(예: "빈 상태", "결과 표시"). Dart 코드에는 이런 이름의 상수가
   없고 `if`/`else` 조건 조합으로만 존재한다 — 실제 조건은 각 절 안에
   원문 그대로 적어 뒀다.
3. **"화면"의 단위**: 전부 `Navigator`의 독립 `Route`가 아니라
   바텀시트/오버레이지만, 사용자 관점에서 별개 화면으로 인지되므로 이
   문서에서는 "화면"으로 취급했다.
4. **기준 시점**: 2026-08-04 코드 스냅샷. `docs/planning/HANDOFF.md`
   P1-8(AI 서버 프록시 전환)이 실제 배포되면 화면 1(AI 연동 설정)과
   화면 3의 문구("{제공사명}로 전송" 부분)가 크게 바뀔 예정이며, 그
   미래 상태는 `ai_briefing_screens_spec.html`에 이미 스펙이 있다.

  있는 항목이라 이 문서에서 새로 만들지는 않았고, 위 3절/4절 표에서
  실제 색상값 근거만 재확인해 남겼다.
- **선택된 대화 포인트(`_selectedIndex`)가 시각적 강조 외 기능이
  없음**: 카드를 탭해 하나를 "선택"할 수 있지만, 그 선택이 복사·전화
  연동 등 어떤 후속 동작에도 쓰이지 않는다(아래 "확인이 필요할 수
  있는 사항" 참고).

## 8. 확인이 필요할 수 있는 사항 (구현 착수 전 PM/사용자 확인 권장)

이 항목들은 문서 작성 자체를 막지는 않으므로 가정으로 진행했지만,
후속 구현(특히 P1-8 서버 프록시 전환이나 UX 개선 백로그)에 들어가기
전에는 답이 있는 게 안전하다.

1. **선택한 대화 포인트에 후속 기능이 있어야 하는지** — 지금은 카드
   탭이 시각적 선택만 하고 끝난다. "이 문장 복사"나 "이 문장으로
   메시지 앱 열기" 같은 기능이 원래 계획에 있었는데 빠진 것인지,
   아니면 단순히 "마음에 드는 걸 하나 짚어보는" 용도로 의도된 것인지
   확인이 필요하다.
2. **모델 오버라이드 UI 노출 여부** — `AiCredentialsRepository.
   setModel()`이 이미 구현돼 있지만 설정 화면에 입력 UI가 없다. 고급
   사용자를 위해 모델명을 직접 입력할 수 있게 노출할지, 아니면 항상
   `defaultModel`만 쓰게 지금처럼 숨겨 둘지는 제품 판단 영역이다.
