## ⑤ 명함 상세 시트 개선 — `contact_detail_view.dart`

사용자 직접 요청(스크린샷 표시 기반). 셋을 한 번에:

1. **큰 파란 "전화" 띠 버튼 제거.** 화면을 차지하고 부담스럽다는 제보.
2. **연락처 줄마다 오른쪽에 동작 아이콘.**
   - 휴대폰 줄: 전화 + 문자(두 개) · 사무실 줄: 전화 · 이메일 줄: 메일
   - 40dp 원형(accentSoft 배경, accentText 아이콘), 터치 영역 44dp 이상
   - **값이 없는 줄은 아이콘을 그리지 않는다** (빈 상태 그대로 — 가짜 데이터 원칙)
   - 접근성 라벨: "OOO에게 전화", "문자 보내기", "이메일 보내기"
3. **하단 닫기·편집 통일** — 같은 크기, 같은 무채색 외곽선 스타일(파란 강조
   제거), 나란히 배치.

⚠️ 주의:
- 띠에 전화 외 동작(AI 브리핑 등)이 함께 있었다면 **그 진입로는 없애지 말고**
  기존 다른 위치(목록 행의 AI 버튼 등)와 중복인지 확인 후 처리 — 진입로가
  사라지는 변경은 별도 보고.
- 전화·문자·메일 실행은 기존 앱의 launch 경로(목록 행의 전화 버튼과 같은
  코드)를 재사용한다. 새 권한·새 플러그인 금지.

## ⑥-C 주변 홈 지도 카드 — `radar_view.dart` 요약 카드

**⚠️ 착수 게이트: PR #401 병합 후.** 같은 파일을 #401(지역 구획 표시)이 고치고
있다 — 먼저 들어가면 충돌한다.

A안(실시간 지도)은 **미채택** — 방침 10-3(*"지도 화면을 열지 않으면 어떤
요청도 발생하지 않는다"*) 수정과 타일 요청 비용 때문. **C안 확정**:

1. 기존 요약 카드("지금 가까운 사람 N명", map.jpg 배경)를 **높이 ~300dp의
   지도풍 카드**로 확대.
2. 배경은 **앱이 직접 그린 사실적 지도풍 그래픽** — 크림 바탕, 테두리 있는
   흰 도로망(간선은 노란 중앙선), 건물 발자국, 공원 녹지, 물길. 캔버스
   ⑥-C 아트보드의 SVG 구도를 기준으로 CustomPainter 또는 번들 벡터로 구현.
   **외부(지도 사업자) 요청 0을 유지한다** — 방침 10-3이 이 구현의 전제다.
3. 그 위에 반경 동심원 + **실제 근처 인맥의 거리·방위로 계산한 점**(이름
   이니셜 원형, 거리 칩, 같은 주소 묶음은 숫자 배지). 표시 수 상한을 두고
   넘치면 묶음/생략.
4. 카드 안에 정직 표기: **"거리·방향 기준 표시 (실제 지도가 아님)"** — 이
   문구는 빼지 않는다(과장 금지 원칙).
5. "지도로 보기" 버튼 → 기존 지도 화면(nearby_map_view). 탭 동작은 기존
   카드와 동일 유지.
6. 위치 동의 없음·근처 0명일 때의 빈 상태를 각각 설계 — 가짜 점 금지.

⚠️ 주의:
- map.jpg 일러스트를 걷어낼 때, 그 카드에 걸린 기존 동작(위치 토글 연동,
  탭 시 지도 열기 — F-13·F-11 관련 회귀 방지 주석들)을 깨지 않는다.
- `radar_view.dart`의 기존 회귀 방지 테스트와 #401이 새로 넣은 지역 구획
  표시와의 배치 관계를 확인한다(카드가 커지므로 화면 구성 재점검).

## ⑦ 목록 상단 고정 — `wallet_view.dart` · `radar_view.dart` (2026-08-21 저녁 확정)

명함이 많을 때 스크롤하면 제목·검색·정렬까지 다 올라가 버린다는 사용자
제보. 원칙: **스크롤 중에도 계속 쓰는 도구는 고정, 콘텐츠는 흘려보낸다.**
목업은 캔버스 ⑦ 아트보드 2장.

| 화면 | 고정 | 흘려보냄 |
|---|---|---|
| 명함 지갑 | 축약 제목("명함 지갑"+개수 배지) · 검색창 · 정렬 칩 줄 | 큰 제목 블록 · 신규 칩 |
| 주변 | 축약 제목+"가까운 N명" 배지 · 반경 칩·지도 버튼(제목 줄 흡수) · 검색창 | 큰 제목 · 지도 카드(⑥-C) |

구현 지침:
- `CustomScrollView` + `SliverAppBar(pinned)` / `SliverPersistentHeader` 계열.
  고정 블록 총높이 **~150dp 이하** 유지(목록 가시 영역 확보), 고정 상태에서
  아래 그림자로 층 표현.
- 스크롤 최상단에서는 지금처럼 큰 제목이 보이고, 내리면 축약형으로 접히는
  collapsing 패턴. 두 탭이 같은 패턴·같은 컴포넌트를 쓰게 한다.
- 기존 화면 회귀 주의: 지갑 선택 모드(F-06)의 상단 바, 주변 검색 중 상태
  (F-11 — 검색 중 카드 숨김), 기준점 안내 줄(F-13)이 고정 블록과 어떻게
  겹치는지 각각 확인.

⚠️ 착수 게이트: **지갑 쪽은 즉시 가능**(wallet_view.dart — 점유 없음).
**주변 쪽은 ⑥-C와 함께 #401 병합 후**(radar_view.dart 충돌).

## P2 4건 (2026-08-22 사용자 전체 확정 — 목업 캔버스 윗줄 기준)

8/20 계획(추가 348)에서 "스펙만 만들고 다음 판"으로 보류했던 4건. 목업으로
확정됐고, 목업의 미결정 2건도 목업안대로 확정: **묶음 판정 = 목록(F-15)과
같은 도로명 일치 기준**, **묶음 탭 = 바텀시트**.

### P2-① 지도 같은 건물 다중 노출 — `nearby_map_view.dart`

⚠️ **착수 게이트: 393(fix/nearby-map-fit-outlier) 병합 후** — 같은 파일.

- 같은 도로명 주소(F-15 규칙 재사용)의 핀을 **숫자 묶음 마커 + "같은 주소
  N명" 라벨**로 표시. 탭하면 바텀시트: 주소 머리글(+N명 배지) + 인맥 목록
  (아바타·이름·회사·거리, 탭 시 명함 상세). 목록 화면의
  same-address 묶음 컴포넌트 패턴 재사용.
- 낱개 핀·기준점 재계산(F-13)·393의 fit과 공존 확인.

### P2-④ 앞뒤 이어찍기 단축 — 촬영 직후 화면

- 앞면 촬영 직후: 읽은 필드 칩(있음/없음 — 없음은 warning 톤) + 안내
  *"주소·이메일이 뒷면에 있는 경우가 많아요"* + **[뒷면 이어 찍기]**(주요)
  / **[앞면만으로 등록]**(보조). 기존 "뒷면 스캔" 경로는 제거하지 않는다
  (판정 원칙: 공존+안내).
- 이어 찍으면 기존 앞/뒷면 필드 누적 로직 그대로 합쳐진다. "앞면 1/2" 단계
  칩 표시.

### P2-② 이미지 2장 선택 — 갤러리 선택 흐름

- 갤러리에서 **최대 2장** 선택. 선택 순서로 앞(1)·뒷(2) 지정, 배지 표시,
  **"앞·뒷면 순서 바꾸기"** 제공. [2장 불러와 인식하기] → 앞·뒷 각각 OCR
  후 기존 누적 병합 경로.
- 1장만 고르면 기존 동작 그대로(회귀 0).

### P2-③ 크롭 UX 공존안 — 크롭 화면

- 상단 세그먼트 **[자동 인식] / [직접 조정]** — 기본은 자동(기존 유지).
  자동 결과 위에 안내 배너: *"테두리를 자동으로 찾았어요 — 모서리 점을
  끌어 바로 고칠 수 있어요"* + 모서리 핸들 상시 노출.
- 하단 [회전]·[다시 찾기]·[이대로 자르기]. 기존 자동/수동 크롭 동작·저장
  경로는 변경 없음 — 이 건은 **배치와 안내의 재구성**이지 크롭 엔진 변경이
  아니다(F-03 기능 회귀 0).

## 398 — 갤러리 경로에도 자르기 화면 (2026-08-22 사용자 확정)

배치 확인 중 사용자 지적("자르기 회전 이런 게 없네")에서 나온 확장. 갤러리
사진은 원래 자르기 없이 OCR로 직행했는데(기존 동작, P2-③ 범위 밖), 갤러리
사진일수록 여백이 많아 자르기가 더 필요하다.

- 갤러리에서 고른 이미지도 OCR 전에 **자르기 화면(ManualCropView)**을 거친다
  — 자동 테두리 검출로 미리 채우고, 수동 조정·회전 가능(P2-③ 화면 그대로).
- **[자르기 없이 사용]** 탈출구를 둔다(공존 원칙 — 기존처럼 바로 쓰고 싶은
  사용자를 막지 않는다).
- P2-②(2장 선택)와 결합: 2장이면 앞면 → 뒷면 순서로 각각 자르기. 단계
  표시("앞면 자르기 1/2").
- ⚠️ 397 수정(수동 경로 좌표계: cornersAreImageRelative·autoUpright:false)을
  그대로 태울 것 — 갤러리 이미지는 EXIF 방향이 다양해 그 경로가 더 중요하다.
- 회귀: 촬영 경로·내 프로필 OCR(갤러리 단일 선택) 무변경.
