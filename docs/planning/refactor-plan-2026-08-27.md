# 초대형 파일 분리 — 착수 전 검토 (2026-08-27)

사용자가 리팩터링 권고를 가져왔고 **실행이 아니라 검토를 요청**했다. 진단을
실측으로 확인하고, **왜 지금 착수하지 않는지**와 **착수한다면 어디부터인지**를
남긴다.

⚠️ **이 문서는 계획이지 착수가 아니다.** 코드는 한 줄도 안 고쳤다.

## 진단 — 실측했고 **전부 정확하다**

| 파일 | 권고가 말한 것 | 실측 |
|---|---|---|
| `add_card_modal_view.dart` | 4,425줄 · `build()` 약 780줄 | **4,425** · **779** |
| `ocr_scanner_service.dart` | 3,482줄 · `_parse()` 약 1,370줄 | **3,482** · **1,358** |
| `camera_scan_modal_view.dart` | 2,441줄 · `build()` 약 900줄 | **2,441** · **901** |
| `functions/src/index.ts` | 2,427줄 | **2,427** |
| `settings_view.dart` | 2,148줄 | **2,148** |

원칙도 이 저장소 규약과 어긋나지 않는다 — 개인정보 로그 금지, **평문 임시 파일
삭제 시점 유지**, 가짜 데이터 금지, 요청 전 커밋 금지. 특히 둘이 정확하다.

```
part 파일로 옮겨 줄 수만 줄이지 말 것
기능 변경과 리팩터링을 섞지 말 것
```

## 🚨 그런데 지금 착수하지 않는다 — 이유 셋

### ① 안전망이 없다

```
파일                       테스트   이 파일을 참조하는 곳
add_card_modal_view          0개          14곳
camera_scan_modal_view       0개           4곳
settings_view                0개           3곳
ocr_scanner_service          1개          20곳
```

권고 자신이 *"특성 테스트를 먼저 추가하라"* 고 한다. **그 테스트를 쓰는 것만으로
큰 작업**이고, 리팩터링보다 먼저 끝나야 한다.

### ② 이 저장소는 자동 테스트가 못 잡는 유형을 반복해서 냈다

리팩터링의 전제는 *"동작이 같다"* 인데, **같은지를 확인할 방법이 실기기밖에 없는
화면들**이다. 2026-08-26 광고 수신 동의에서 **자동 테스트를 전부 통과하고도
실기기에서 결함이 하나 더** 나왔다(추가 514 참고 — ①이 ②를 가리고 있었다).

📌 CLAUDE.md 4절: *"자동 테스트는 규칙을 보고 사람은 화면을 본다."*

### ③ `functions/src/index.ts` 는 성질이 다르다

**배포되는 서버 코드**다. 쪼갠 뒤 배포했을 때 함수 이름·리전·시크릿·App Check·
`maxInstances` 가 하나라도 어긋나면 **서비스가 멈춘다.** 권고도 *"그대로 유지"*
라고 하지만, ⚠️ **확인할 방법이 배포뿐**이고 배포는 사용자 결정이다.

🚨 **다섯 중 이것만 「되돌리기가 비싼」 축에 있다.** 나머지 넷은 앱을 다시 깔면
되지만 이건 서비스가 멈춘다.

## 착수한다면 — **`ocr_scanner_service.dart` 가 첫 대상**

| 왜 | |
|---|---|
| 순수 로직이다 | 화면이 아니라 **입력 → 출력**이라 테스트로 고정할 수 있다 |
| 이미 테스트가 있다 | `ocr_scanner_parse_test.dart` — 기존 규칙이 일부 고정돼 있다 |
| 실기기가 덜 필요하다 | 파싱 결과가 같으면 화면도 같다 |
| 값이 크다 | `_parse()` **1,358줄**이 한 메서드다 |

⚠️ **그래도 먼저 할 일이 있다** — *"기존 규칙 실행 순서와 fallback 우선순위를
테스트로 고정"*. **지금 테스트가 그 순서를 다 덮고 있지 않다.**

📌 **참조가 20곳**이라 공개 시그니처를 바꾸면 파급이 크다. `_parse` 는 파일
내부 전용이고 테스트가 우회 진입점으로 부르고 있다(2005행 근처) — **그 구조를
먼저 이해하고 손대야 한다.**

### 마지막 대상

```
functions/src/index.ts   ← 배포 위험 때문에 맨 뒤
```

## 착수 전에 사용자에게 받아야 할 것

CLAUDE.md 4절대로 **검증 종류를 먼저 제시하고 선택을 받는다.**

```
전체 테스트   전 항목 실기기 (~1시간)          [배포 직전용]
부분 테스트   고친 곳 + 영향받는 화면 (~수 분)
자동 테스트   flutter analyze / test (~수 초)
```

📌 **리팩터링은 「저장·복원·마이그레이션」에 닿는 경우가 있다**(예: `settings_view`
의 계정 삭제·로컬 정리). 그 경우 4절 표에 따라 **전체 테스트 대상**이다.
