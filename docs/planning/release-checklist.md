# 릴리스 체크리스트

스토어 제출 전과 테스터 배포 전에 밟는 순서. 지금까지 이 절차가
[`backlog.md`](./backlog.md) 산문에 흩어져 있어, 매번 기억에 의존했다.

**전제**: [`CLAUDE.md`](../../CLAUDE.md)의 작업 규약과
[`tool/README.md`](../../tool/README.md)의 검증 도구를 먼저 읽을 것.

---

## 0. 왜 이 순서인가

이 프로젝트에서 실제로 터진 결함은 대부분 **자동 검사가 원리상 못 잡는
자리**에 있었다. 그래서 아래 단계는 "덮는 범위"가 서로 다르게 짜여 있다.

| 단계 | 덮는 것 | 못 덮는 것 |
|---|---|---|
| 자동 검사 | 컴파일·정적분석·순수 로직 | 화면, 저장소 실물, 기기 |
| 실물 점검 | 서버·기기 저장소의 실제 내용 | 화면, 사용자 흐름 |
| 기기 확인 | 화면·조작·크래시 | 저장소 내부, 서버 권한 |
| 사람 눈 | 위 전부의 빈틈 | — |

**"테스트가 통과했다 = 동작한다"가 아니다.** 서버에 개인정보가 평문으로
남아 있던 것도, 좌표 재계산이 죽어 있던 것도, 그때 테스트는 전부 초록불이었다.

## 1. 코드 (자동)

```bash
flutter analyze     # error·warning 0건 (info는 기존 잔재라 허용)
flutter test
```

브랜치에 push하면 CI가 같은 것을 자동으로 돌린다. **PR 검사가 통과해야 병합**한다.

보안에 닿는 변경(인증·암호화·규칙·개인정보 전송)이 있으면 **머지 전에**
`/security-review`를 돌린다. 커밋을 마친 뒤에 돌리면 대상 diff가 0이라 아무것도
안 나온다.

## 2. 실물 점검 (저장·암호화·마이그레이션을 건드렸을 때 필수)

```bash
python3 test/firestore_rules/verify_rules.py    # 규칙을 고쳤다면 배포 전에
python3 tool/verify_server_privacy.py           # 서버: 평문 0건, 좌표 0건
python3 tool/verify_device_local.py             # 기기: 암호문 + 좌표 채워짐
```

서버와 기기는 **짝으로** 본다. 설계 의도가 "좌표는 기기에만, 서버에는 없음"
이라 한쪽만 보면 절반만 확인한 것이다.

⚠️ 기기 점검은 **디버그 빌드**에서만 된다(`run-as` 제약). 릴리스로 테스트
중이라면 잠시 디버그로 바꿔 확인하고 되돌린다.

### 명함 사진 한도 — **배포 직전에 여기서 본다** (2026-08-16 사용자 확정)

절차는 [`card-photo-quota-verification-spec-2026-08-16.md`](./card-photo-quota-verification-spec-2026-08-16.md).
**저장·복원·재설치에 걸려 전체 테스트 등급**이라, 수정할 때마다가 아니라
**배포 직전에 한 번** 돌린다.

⚠️ **화면만 보고 판단하지 않는다.** 한도에 걸려도 **명함은 로컬에 정상
저장되는 것이 설계**라 화면으로는 걸렸는지 알 수 없다. **서버 실물을
조회**해야 한다.

⚠️ **V-3(재설치 후 카운터)은 지금 실패하는 것이 정상이다.** 업로드 장수를
세는 값이 기기 안에만 있어 **재설치하면 0으로 돌아간다** — 알려진 결함이고
아직 안 고쳤다. 고치기 전에도 **그 실패를 확인해 두는 것 자체가 값**이다.

📌 이 결과에 **손익 문서가 걸려 있다**. 한도가 제대로 걸리면 원가 계산의
천장이 성립하고, **안 걸리면 천장이 없는 것이라 손익 16-6을 다시 써야 한다.**

### ⚠️ 명함 사진 서버 백업(`kCardPhotoBackupEnabled`)을 켜기 전에 — 잠긴 관문

지금 이 플래그는 **`false`** 다(`card_photo_backup_service.dart`). **켜기 전에
아래가 전부 끝나 있어야 한다.** 순서를 어기면 되돌리기 어렵다.

- [ ] 계정 전환에서 **선택이 끝나기 전에는 서버로 아무것도 쓰지 않는다**(377)
- [ ] 전환 다이얼로그가 **"유지"가 무슨 일인지** 말한다(377)
- [ ] 이미 생긴 **이중 사본 정리**가 끝났다(380)

**왜 이 순서인가**: 켜는 순간 계정 전환 경로로 **제3자의 얼굴이 담길 수 있는
명함 사진**까지 다른 계정으로 넘어간다. 명함 텍스트는 그렇게 넘어간 것이 실제로
확인됐다 — 2026-08-21 실측에서 같은 명함 95건이 **세 계정 서버에 전부** 있었다.

⚠️ 텍스트는 지우면 되지만 **사진은 되돌리기가 더 어렵다.** 지금은 서버 백업이
없어 기기의 암호문이 유일본이라, 정리 과정에서 잘못 지우면 복구할 방법이 없다.

📌 근거: `docs/planning/legal-review-reply-2026-08-21.md` 질문 9-④7.

## 3. 빌드

### ⚠️ 서명 키부터 확인한다 — 워크트리마다 다르다 (2026-08-16 실측)

```bash
ls android/key.properties   # 없으면 **경고 없이 debug 키로 서명된다**
```

`android/app/build.gradle.kts`는 이 파일이 없으면 **조용히 debug 키로
폴백한다**(빌드가 깨지지 않게 하려는 의도다). 그런데 이 파일은
`.gitignore` 대상이라 **git이 워크트리 사이로 옮겨 주지 않는다.**

**본체가 아닌 워크트리에서 릴리스를 빌드하면 debug 서명본이 나온다.**
파일 이름도, 화면도, 로그도 그대로라 **알아챌 방법이 없다.** 그것을 스토어에
올리면 **업데이트를 영영 못 올린다**(업로드 키가 바뀌면 Google이 거부한다).

### 실측 — 나빠지고 있다

| 언제 | 잰 것 | 없는 곳 |
|---|---|---|
| 2026-08-16 | 워크트리 4개 | **3개** |
| 2026-08-25 | 워크트리 **15개** | **11개** |

⚠️ **08-25에 세어 보니 워크트리가 15개였다.** 08-16 기록이 4개를 기준으로
*"넷 중 하나에만 있다"*고 적어 두었는데, 그 뒤로 에이전트용 워크트리
(`.claude/worktrees/agent-…`)가 여럿 생겼고 **그것들에는 전부 없다.**

📌 **표에 적힌 워크트리 이름으로 세면 안 된다.** 이름을 적어 두면 그 목록에
없는 워크트리는 세지 않게 되고, 실제로 08-16 표의 `sharp-chebyshev-…`는
지금 존재하지도 않는다. **셀 때마다 다시 센다:**

```bash
for w in $(git worktree list --porcelain | grep '^worktree ' | cut -d' ' -f2-); do
  [ -f "$w/android/key.properties" ] && s="있음" || s="없음"
  printf '%-58s %s\n' "${w##*/}" "$s"
done
```

### ✅ 2026-08-25 — `tool/build_app.sh`가 이제 막는다 (추가 478)

`apk`·`appbundle`을 `release`로 빌드할 때 `android/key.properties`가 없으면
**빌드를 시작하지 않고 종료 코드 3으로 멈춘다.** `debug`·`profile`은 검사하지
않는다.

⚠️ **`build.gradle.kts`의 폴백 자체는 그대로 두었다** — `flutter run --release`가
서명 파일 없는 환경에서도 돌게 하려고 일부러 둔 것이라, 없애면 다른 것이
깨진다. 대신 **배포용 산출물을 만드는 진입점**에서 막았다.

📌 그래서 **`flutter build`를 직접 쓰면 이 안전장치를 지나친다.** 커밋 해시가
안 들어가는 것과 별개의 이유가 하나 더 생겼다.

```bash
tool/build_app.sh apk release     # Android 테스터 배포용
tool/build_app.sh ios release     # iOS
```

`flutter build`를 직접 쓰지 말 것 — 커밋 해시가 안 들어간다.

⚠️ **`KAKAO_JS_KEY` 환경변수를 설정하지 말 것(2026-08-20 결정, backlog
추가 359).** 카카오맵이 이 계정에서 유료로 판명돼 과금 사용자 결정
대기 중이다. 설정 안 하면 웹뷰에서 카카오 SDK 태그가 통째로 빠지고
주소 검색은 기존(OS 지오코더 폴백)대로 동작한다(PR #365의 방어 설계) —
**안전한 기본값이니 그냥 비워 두고 빌드하면 된다.**

- 테스터·스토어 배포는 **반드시 release**. debug 빌드에는 로그인 화면에
  "로그인 건너뛰기" 버튼이 그대로 보인다.
- 빌드 후 **설정 → 앱 버전**에서 방금 만든 커밋 해시가 보이는지 확인한다.
  `+수정중`이 붙어 있으면 커밋되지 않은 코드가 섞인 빌드다.

### ⚠️ Cloud Functions 2세대 — 서비스 계정 권한 (2026-08-20 실측)

2세대 함수는 **`{프로젝트번호}-compute@developer.gserviceaccount.com`** 을
빌드·실행 계정으로 쓴다. `firebase-adminsdk@` 가 아니다.

⚠️ **문서 대부분이 1세대 기준이라 이 구분이 잘 안 드러난다.** `firebase-adminsdk@`
쪽에는 권한이 있어서 *"권한이 있는데 왜 안 되지"* 하고 헤매기 쉽다.

| 무엇을 하려면 | 필요한 역할 | 없으면 나는 증상 |
|---|---|---|
| `createCustomToken` | **서비스 계정 토큰 생성자** | `Permission 'iam.serviceAccounts.signBlob' denied` — 앱에는 그냥 "로그인 실패" |
| `createUser`·`updateUser` | **Firebase 인증 관리자** | `insufficient permission` — 계정에 이름·사진이 안 붙는다 |
| 함수 빌드 | **Cloud Build 관리자** (+편집자) | `missing permission on the build service account` |

📌 셋 다 **증상이 원인을 안 알려 준다.** 특히 첫째는 화면에 "로그인 실패"로만
떠서, 리다이렉트 URI나 동의항목부터 뒤지게 된다.


⚠️ **`firebase` 명령이 PATH에 없을 수 있다** — 셸에 따라 `command not found`가
난다. 전체 경로는 `~/.npm-global/bin/firebase`(firebase-tools 15.25.1).

⚠️ **비밀값을 넣을 때는 `2>&1 | cat`을 붙인다** (2026-08-20 실측).

```
~/.npm-global/bin/firebase functions:secrets:set <이름> 2>&1 | cat
```

붙이지 않으면 `Invalid secret key … must start with an uppercase ASCII letter`가
뜬다. **이름이 규칙에 맞는데도 뜬다** — 이름 문제가 아니므로 이름을 고치려
들지 말 것. 원인은 규명하지 못했다.

⚠️ **참조된 비밀값이 하나라도 없으면 `deploy --only functions`가 통째로 막힌다.**
함수를 골라 배포해도 소스 분석 단계에서 전부 요구한다. 현재 필요한 것:

```
GEMINI_API_KEY · APPLE_SIGNIN_KEY · DEVICE_HASH_SALT · APPLE_IAP_SHARED_SECRET
KAKAO_REST_KEY · KAKAO_CLIENT_SECRET · NAVER_CLIENT_ID · NAVER_CLIENT_SECRET
```

## 6. 배포

테스터에게 보낼 안내문은 [`tester-guide.md`](./tester-guide.md)에 있다.
**매번 새로 쓰지 말고 그 문서를 고쳐 쓸 것** — 새로 쓰면 "지금 안 되는 기능"
목록이 빠져 정상 동작을 결함으로 제보받는다.

```bash
firebase appdistribution:distribute build/app/outputs/flutter-apk/app-release.apk \
  --app 1:79345379389:android:24e13cbaadaf82ac182254 \
  --project connection-sense \
  --release-notes "..." \
  --testers "..."      # 지정하지 않으면 아무에게도 안 간다
```

릴리스 노트에 반드시 넣을 것:

- 이번에 고친 것과 **확인해 달라는 것**
- 지금 동작하지 않는 기능(안 그러면 정상 상태를 결함으로 제보받는다)
- **테스트 데이터가 실제 서버에 저장되므로 끝나면 설정 → 계정 삭제로 정리**
