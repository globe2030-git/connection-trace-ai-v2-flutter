### E-01 · 자동 촬영이 빈 공간을 찍음 🟡 부분

- **증상**: 명함이 아닌 빈 벽·책상·모서리가 자동 촬영된다.
- **원인**: 자동 촬영 조건이 **"화면이 흔들리지 않으면"** 하나뿐이었다. 역설적으로
  아무것도 없는 면이 가장 안정적이라 더 잘 찍혔다.
- **조치**: 안정 조건에 **"가이드 안에 볼 것이 있는가"**를 더했다 — 밝기 표준편차
  (민무늬 면 차단)와 지배톤 비율(반반으로 갈린 모서리 차단). 계산을
  `core/utils/frame_contrast.dart`로 빼 7가지 장면을 테스트로 고정.
- **남은 것**: 각이 진 빈 곳은 밝기로 못 가른다(실측: 명함 톤 0.653 vs 책상 0.611,
  차이 0.04). **문서 경계 검출**(R-02)이 필요하다. → R-02와 한 덩어리.
- 근거: 추가 208·209·210.

### E-05 · 필드 매핑 오류 ✅ 종결 (대폭 개선)

이번 통합본에서 가장 크게 개선된 항목. 사용자 진단이 출발점이었다 — *"OCR 추출은
정확히 하는데 분리하는 과정에서 잘못되는구나."* 실제로 이름 미검출 17장 중 16장은
원문에 이름이 있었다.

- **원인 1 — 자리를 뺏기면 끝**: 이름 후보 검사가 줄 순회가 끝난 뒤에만 돌아,
  슬로건 조각이 먼저 자리를 차지했다가 지워지면 진짜 이름을 다시 볼 기회가 없었다.
  → **"넣고 → 빈자리 재검증"** 구조로 전환(추가 199).
- **원인 2 — 이름 후보가 선착순**: OCR이 잘못 읽은 슬로건 끝자락이 먼저 이름이 되고
  진짜 이름은 회사 칸으로 밀렸다. → 이름 후보를 **강·약 두 갈래**로 나눠 강이
  있으면 약은 쓰지 않는다. 틀린 이름 14장이 정답으로 교정(추가 200).
- **원인 3 — 한 줄로 뭉친 명함**: 전화·이메일을 뽑은 뒤 `continue`해서 주소·회사·
  이름 검사를 아예 건너뛰었다. → 연락처를 걷어낸 나머지를 **같은 루프에 다시**
  넣는다(추가 201).
- **개선 측정(103장)**: 이름 82→**100**, 주소 76→**85**, 휴대폰 97→**100**.

- 근거: 추가 199·200·201·202.

### E-07 · 프로필 사진 미리보기가 안 바뀜 ✅ 종결 (실기기 확인)

- **증상**: 갤러리에서 사진을 골라도 미리보기가 그대로. **껐다 켜면 정상.**
- **원인**: `FileImage`의 **캐시 키가 파일 경로**다. 프로필 사진은 매번 같은
  파일명(`my_profile_avatar.jpg`)으로 덮어써서, 내용이 바뀌어도 캐시가 옛 픽셀을
  돌려줬다. `setState`가 소용없던 이유.
- **조치**: `evictImageFileCache(path)` — 덮어쓴 직후 그 경로를 캐시에서 비운다.

```dart
// camera_scan_modal_view.dart:546
final rectOk = !_requiresCardRect || _hasRecentCardRect;
if (avgDiff < _stabilityDiffThreshold && hasContent && rectOk) { … 자동 촬영 … }
```

`_requiresCardRect`(:252)가 자동 촬영에 **"최근에 사각형이 잡혔을 것"**을 요구한다.

#### ⚠️ 그런데 6초 유예가 보호를 지운다

```dart
static const _cardRectGrace = Duration(seconds: 6);   // :244
```

검출을 **한 번도 못 하면 6초 뒤 조건이 저절로 풀린다.** 안 그러면 검출이 안 되는
기기에서 자동 촬영이 **영영 안 되기** 때문이다. 즉 **정작 못 잡는 상황에서는
보호가 조용히 사라진다.**

⚠️ 그 유예에는 더 나쁜 성질이 있다 — **네이티브 등록을 빠뜨려도 6초 뒤 조건이
풀려 "잘 도는 것처럼" 보인다.**
