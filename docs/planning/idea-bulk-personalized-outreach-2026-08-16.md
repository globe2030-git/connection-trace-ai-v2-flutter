# 아이디어 — PC 화면에서 "공통 글 + 개인별 한 줄" 발송

**기록**: 2026-08-16 (PM 세션) · **사용자 지시: 기록만. 고도화 항목으로 둔다**
**상태**: ⚠️ **착수하지 않는다.** 지금은 아이디어 보존이 목적이다.

---

## 1. 사용자가 말한 것 (원문에 가깝게)

> **"사용자가 PC에서 다룰 수 있는 기능의 홈페이지도 나중에 필요해."**
>
> **"명절에 단체로 문자·이메일·카톡 등을 보내거나, 회사의 변경 정보를 알리거나
> 할 때 일괄된 내용을 보내면 식상해서, 개별적으로 공통된 글과 함께 개인별 글을
> 추가할 수 있는 화면을 만들어서 발송될 수 있는 기능이 있으면 좋을 것 같아."**

---

## 2. 왜 이게 이 앱에 맞나

**이 앱의 무기는 "무슨 말을 걸지"다.** 그 무기를 **한 사람이 아니라 여러 사람에게
동시에** 쓰는 것이 이 아이디어다.

| | |
|---|---|
| 지금 | 명함 하나를 열고 **AI가 첫 문장**을 만들어 준다 |
| 이 아이디어 | 여러 명에게 **공통 글 + 그 사람에게만 맞는 한 줄** |

**"일괄된 내용을 보내면 식상해서"**가 핵심이다. 단체 문자는 받는 사람이 **단체
문자인 줄 안다.** 그런데 한 줄만 달라도 **읽는 사람에게는 개인 문자**가 된다.

📌 그리고 **PC 화면이어야 하는 이유가 분명하다** — 수십 명에게 각각 한 줄씩
쓰는 일은 **휴대폰에서 못 한다.** 키보드가 있어야 한다.

---

## 3. 그려 본 화면 (초안 수준)

```
┌─────────────────────────────────────────────┐
│  공통 글                                     │
│  ┌─────────────────────────────────────┐   │
│  │ 새해 복 많이 받으세요.               │   │
│  │ 올 한 해도 잘 부탁드립니다.          │   │
│  └─────────────────────────────────────┘   │
├─────────────────────────────────────────────┤
│  받는 사람 (34명)          [AI로 한 줄 채우기]│
│                                             │
│  ☑ 김○○ (○○회사)  │ 지난번 미팅 감사했습니다 │
│  ☑ 이○○ (○○그룹)  │ 승진 축하드립니다      │
│  ☑ 박○○           │ (비어 있음)            │
├─────────────────────────────────────────────┤
│  보낼 방법:  ○ 문자   ○ 이메일   ○ 카카오톡  │
│                            [ 미리보기 ] [보내기]│
└─────────────────────────────────────────────┘
```

**AI가 붙는 자리는 "개인별 한 줄"이다.** 명함에 이미 회사·직책·메모·마지막 소통일이
있으므로 **재료가 있다.**

⚠️ **AI가 쓴 것을 그대로 보내게 하지 않는다.** 반드시 **사람이 보고 고칠 수 있게**
한다 — 이 저장소의 원칙(가짜 데이터를 만들지 않는다)과 같은 결이다. 틀린 말을
아는 사람에게 보내면 **명함 앱이 아니라 사고다.**

---

## 4. ⚠️ 미리 알아 둘 벽 — 여기가 진짜 난이도다

**기능이 어려운 게 아니라, 보내는 길이 막혀 있다.**

### 4-1. 카카오톡 대량 발송은 개인 계정으로 못 한다

친구에게 하나씩 공유하는 것과 **여러 명에게 발송하는 것은 완전히 다른 길**이다.
후자는 **알림톡·친구톡**이고 **사업자 등록·채널 개설·템플릿 심사**가 필요하며
**건당 요금**이 든다.

### 4-2. 문자 대량 발송도 유료 서비스가 필요하다

앱에서 문자 앱을 여는 것과 **서버에서 34명에게 보내는 것**은 다르다. 후자는
**문자 발송 사업자**를 거쳐야 하고 건당 요금이 든다.

### 4-3. ⚠️ 법이 걸린다 — 이게 가장 무겁다

**정보통신망법**상 **광고성 정보**를 보내려면 **사전 동의**가 필요하고, 제목에
**(광고)** 표기, **수신거부 방법 안내**, **야간(21시~08시) 발송 제한**이 붙는다.

| | |
|---|---|
| 명절 인사 | 광고가 아닐 **가능성이 높다** |
| **회사 변경 정보 알림** | ⚠️ **경계에 있다.** 내용에 따라 광고로 볼 수 있다 |
| 영업 목적이 섞이면 | **명백히 광고다** |

⚠️ **그리고 받는 사람은 우리 이용자가 아니다.** 명함 주인은 우리에게 동의한 적이
없다. **"이용자가 자기 인맥에게 보내는 것"과 "우리가 대신 보내는 것"의 경계**를
법적으로 정리해야 한다. **리갈 검토 없이 착수하면 안 된다.**

### 4-4. 개인정보처리방침도 또 걸린다

전달 기능(추가 260)에서 이미 방침 개정이 필요한데, **대량 발송은 그보다 훨씬
크다.** 발송 이력·수신자 정보를 서버에 두게 되기 때문이다.

## 5. PC 홈페이지 자체에 대해

**필요하다는 판단에 동의한다.** 다만 이 아이디어만을 위해 만들 일은 아니다.

- ⚠️ 지금도 Flutter 앱은 **웹으로 빌드된다**(`chrome` 기기가 잡힌다). 다만
  카메라·위치 같은 것이 안 돌아 **그대로 쓰기는 어렵다**
- 법적 고지는 이미 `connection-sense.web.app`에 있다
- **PC에서 하면 좋은 일**을 모아 봐야 한다 — 대량 발송, 명함 일괄 등록
  (추가 236 아이디어), 리멤버 `.vcf` 가져오기, 관리자 화면
