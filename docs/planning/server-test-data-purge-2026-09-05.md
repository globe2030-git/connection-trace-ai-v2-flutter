## 0. 🚨 「무엇이 있는지」를 **서버에 물었다** — 문서로 세지 않았다

```
POST {BASE}:listCollectionIds     →  최상위 컬렉션 **13개**
```

📌 **rules 도 코드도 「있는 것의 목록」이 아니다.** rules 에는 27개가 선언돼 있고
코드는 22개를 부르는데, **서버에 실제로 있는 것은 13개**다. Admin SDK 는 규칙을
우회하므로 **rules 에 없는 컬렉션이 있을 수도** 있어 양쪽 다 답이 못 된다.

### ⭐ 그래서 「지울 것」 목록에서 아홉이 빠졌다

인계받은 목록에는 아래가 들어 있었는데 **서버에 존재하지 않는다.**

```
phoneAccounts · deviceLedger · phoneSendLedger · phoneOtpChallenges
purchases · creditGrants · creditGrantAudits · adminSessions · people
```

⚠️ **지울 것이 없다.** 목록이 **설계 문서와 rules 에서 만들어진 것**이라 그렇다.
🚨 **`people` 은 C안 설계이고 아직 구현 전**이다(`personId` 는 살아 있는 코드에
0건 — [추가 686]).

## 2. 🚨 실측하다 나온 것 셋

### ① `cardSources` 가 **0건이다** — 그리고 **손실은 없다**

```
✅ 명함 파싱 원문(제3자 개인정보)이 서버에 **한 건도 없다.**
   #855 는 「샌 것을 치우는」 것이 아니라 **예방**이다
```

> 🚨 **여기 처음 적었던 원인이 틀렸다 — 지우지 않고 남긴다.**
>
> 처음에 *"0건인 이유가 #833 규칙이 미배포라 쓰기가 거부되고 있어서다.
> 지금 등록되는 명함은 파싱 원본이 안 남고, 나중에 배포해도 못 되살린다"*
> 라고 적었다. **셋 다 틀렸다.**
>
> ⚠️ **어떻게 틀렸나 — 「재지 않고 문서에서 읽어 옮겼다」.**
> 근거는 `RESUME.md` 의 *"cardSources 규칙이 미배포다"* 한 줄이었고,
> **나는 서버 규칙을 열어 보지 않았다.** 🚨 그리고 **그 문서는 내가 읽은 뒤에
> 정정됐다** — 지금 그 절은 *"흐르던 것이 멈췄다 — 09-05 저녁에 배포됐다"* 이다.
>
> 📌 **「0건이니 거부됐겠지」는 결과에서 원인을 지어낸 것이다.** 0건에는
> 원인이 여럿 있는데(거부됐다 · 코드가 없다 · 시도된 적이 없다) 그중 하나를
> 골라 놓고 **잰 것처럼 말했다.**

**실측으로 다시 잰 것 (2026-09-05):**

```
규칙 배포        PM 실측 — 배포본이 origin/main 과 **차이 0줄**(759 = 759)
                 배포 시각 12:44:03 UTC · 배포본에 cardSources 규칙 2건 ✅
앱 코드          `cardSources` 를 쓰는 코드는 **c85f1c8d(#833, 09-05)부터** 있다
                 (`data_backup_service.dart` → `AccountPaths.cardSources`)
명함 49건        🚨 **가장 최근 것이 2026-08-29** 이다
규칙 배포 이후    생성된 명함 **0건** · 수정된 명함 **0건**
```

⭐ **그래서 창(window)에 든 명함이 0건이다.**

```
08-29    마지막 명함 등록          ← 여기까지는 **기능 자체가 없었다**
09-05    #833 이 앱 코드를 넣음
09-05 12:44  규칙 배포
지금      그 사이 등록된 명함 **0건**  →  **놓친 원본이 없다**
```

⚠️ **49건에 원본이 없는 것은 「거부돼서」가 아니라 「그때는 기능이 없어서」다.**
그것은 손실이 아니라 **기능 이전**이다.

📌 **다만 「없다」의 근거를 적어 둔다** — 명함의 `createTime`·`updateTime` 을
Firestore 메타데이터로 읽어 12:44:03Z 와 비교했다. **다른 기기가 오프라인에
쌓아 두었다가 나중에 올리는 경우는 이 방법이 못 본다.**

### ② 탈퇴한 uid 의 자료가 **실제로 남아 있다** — #855 의 실물 증거

살아 있는 `users` 18개와, 다른 컬렉션에 문서 ID 로 남은 uid 를 맞대어 찾았다.

```

  🚨 users/eNTMRJXw…/deletedContacts  묘비가 남아 있다
  socialUnlinkRequests            1건 — 이건 **일부러 남기는 것**이다
```

⭐ **#855 가 고치는 결함이 가정이 아니라 실물이다.**

## 3. ⚠️ 이 셈이 못 본 것

```
⬜ 탈퇴 uid 의 하위 컬렉션은 **부모 문서가 없으면 목록에 안 잡힌다**
   🚨 그래서 「다른 컬렉션에 남은 uid」로 **역추적**했다. 그 흔적조차 없이 탈퇴한
   계정이 있으면 **그 하위 컬렉션은 이 방법으로도 못 찾는다**
⬜ 하위의 하위 (`pilotEvents/{uid}/events`) 는 안 셌다
⬜ Firestore 색인·TTL 정책은 안 봤다
⬜ Authentication 의 계정 목록은 안 봤다 — Firestore 와 별개다
```

📌 **첫 줄이 이 셈의 한계다.** 「없다」가 아니라 **「이 방법으로는 못 찾았다」**이다.
