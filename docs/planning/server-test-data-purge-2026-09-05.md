## 0. 🚨 「무엇이 있는지」를 **서버에 물었다** — 문서로 세지 않았다

```
POST {BASE}:listCollectionIds     →  최상위 컬렉션 **13개**
```

📌 **rules 도 코드도 「있는 것의 목록」이 아니다.** rules 에는 27개가 선언돼 있고
코드는 22개를 부르는데, **서버에 실제로 있는 것은 13개**다. Admin SDK 는 규칙을
우회하므로 **rules 에 없는 컬렉션이 있을 수도** 있어 양쪽 다 답이 못 된다.

### ⭐ 그래서 「지울 것」 목록에서 아홉이 빠졌다

인계받은 목록에는 아래가 들어 있었는데 **서버에 존재하지 않는다.**

```
phoneAccounts · deviceLedger · phoneSendLedger · phoneOtpChallenges
purchases · creditGrants · creditGrantAudits · adminSessions · people
```

⚠️ **지울 것이 없다.** 목록이 **설계 문서와 rules 에서 만들어진 것**이라 그렇다.
🚨 **`people` 은 C안 설계이고 아직 구현 전**이다(`personId` 는 살아 있는 코드에
0건 — [추가 686]).

## 2. 🚨 실측하다 나온 것 셋

### ① `cardSources` 가 **0건이다** — 좋은 소식이면서 나쁜 소식이다

```
좋은 소식   명함 파싱 원문(제3자 개인정보)이 서버에 **한 건도 없다.**
            #855 는 「샌 것을 치우는」 것이 아니라 **예방**이다
나쁜 소식   🚨 0건인 이유가 **#833 의 규칙이 미배포**라 쓰기가 거부되고 있어서다
            → **지금 등록되는 명함은 파싱 원본이 안 남는다**
            → 원본은 **저장하는 순간에만** 남길 수 있어 **나중에 배포해도 못 되살린다**
```

### ② 탈퇴한 uid 의 자료가 **실제로 남아 있다** — #855 의 실물 증거

살아 있는 `users` 18개와, 다른 컬렉션에 문서 ID 로 남은 uid 를 맞대어 찾았다.

```
users 에 없는데 흔적이 남은 uid   6개
  🚨 ocrStats                    그중 **5건이 남아 있다**
     → 방침 594행 *"이 통계는 … 회원 탈퇴 시 함께 파기됩니다"* 와 어긋난다
  🚨 users/eNTMRJXw…/deletedContacts  묘비가 남아 있다
  socialUnlinkRequests            1건 — 이건 **일부러 남기는 것**이다
```

⭐ **#855 가 고치는 결함이 가정이 아니라 실물이다.**

### ③ ✅ 고아 사진은 없다

`deleteUserCardPhotos`(탈퇴 트리거)가 제대로 돌고 있다. 사진 14개가 전부 **살아
있는 uid** 것이다.

## 3. ⚠️ 이 셈이 못 본 것

```
⬜ 탈퇴 uid 의 하위 컬렉션은 **부모 문서가 없으면 목록에 안 잡힌다**
   🚨 그래서 「다른 컬렉션에 남은 uid」로 **역추적**했다. 그 흔적조차 없이 탈퇴한
   계정이 있으면 **그 하위 컬렉션은 이 방법으로도 못 찾는다**
⬜ 하위의 하위 (`pilotEvents/{uid}/events`) 는 안 셌다
⬜ Firestore 색인·TTL 정책은 안 봤다
⬜ Authentication 의 계정 목록은 안 봤다 — Firestore 와 별개다
```

📌 **첫 줄이 이 셈의 한계다.** 「없다」가 아니라 **「이 방법으로는 못 찾았다」**이다.
