# 이름만 같은 명함 — 「같은 이름 N명」 (추가 579)

**globe2030님 확정(2026-08-29)**: *"이름만 같은 경우는 확인창을 띄우지 말고
목록에 조용히 표시한다. **단 사용자 선택으로 결정하게 한다.**"*

이 문서는 **화면설계**다. 캔버스(화면설계 모음 ①)에 옮길 내용을 글로 적은
것이고, 구현은 globe2030님이 화면을 보고 확정한 뒤다.

---

## 1. 왜 확인창이 아닌가

globe2030님이 처음 물으신 것은 **「이름만 같아도 확인창」**이었다. 그러지
않기로 한 이유:

```
🚨 동명이인 — 명함이 500장을 넘으면 김민수·이지은은 여러 번 나온다
🚨 그러면 남남에게 계속 "같은 사람인가요?"를 묻게 된다
🚨 확인창이 자주 틀리면 사람이 안 읽고 누른다 → 확인창 자체가 망가진다
```

📌 **2026-08-28에 그것을 실제로 봤다.** 합치기에서 세 번 잃었는데
(사진·이력·빈 값) **셋 다 사람이 확인창을 보는 경로였다.** 늑대소년이 되면
**진짜 중복도 대충 넘어간다.**

⭐ 그래서 원리는 동기화에서 낸 결론과 같다 — **합치지 말고 표시만 한다.
판정이 틀려도 아무 일도 안 일어난다.**

---

## 2. 층을 지킨다 — 579가 577을 덮지 않는다

```
추가 577   이름 + 휴대폰(또는 다른 연락처)이 같다   →  확인창 (지금 동작)
추가 579   이름만 같다                            →  조용한 표시  ← 이 문서
추가 572   합쳐도 잃을 것이 없나                   →  판정만 (부르는 곳 없음)
```

⚠️ **휴대폰이 맞아 확인창이 떠야 할 상황을 579가 「표시만」으로 내려서는 안
된다.** 등록 흐름은 지금 그대로 두고, 579는 **이미 저장된 명함들 사이**에서만
본다.

## 3. 화면 ① — 지갑 목록의 한 줄

```
┌──────────────────────────────────────────────┐
│  명함 지갑            103명의 인맥            │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 👥 같은 이름 3명 · 확인해 보기      ›  │  │  ← 조용한 한 줄
│  └────────────────────────────────────────┘  │
│                                              │
│  [ 전체 ] [ + 그룹 ]                          │
│  ─────────────────────────────────────────   │
│  김다미  대리 · 서울관광재단        2026.08.28 │
└──────────────────────────────────────────────┘
```

**조용하다는 것의 뜻**(⚠️ 이게 이 화면의 핵심이다):

```
① 묶음이 하나도 없으면 줄 자체가 없다
② 빨강·배지·숫자 알림을 쓰지 않는다 — 회색 한 줄이다
③ 「모두 확인함」을 누르면 사라지고, **새 묶음이 생기기 전까지 다시 안 뜬다**
```

📌 ③이 없으면 **줄이 늘 떠 있게 되고 그것도 늑대소년이 된다.** 사람이 한 번
보고 판단한 것을 계속 들이밀지 않는다.

같을 뿐**이고, 그 판단은 사람이 한다.

│  사무실    02-111-2222      02-111-2222       │
│  이메일    a@b.com           a@b.com          │
│                                              │
│  ⚠️ 직함이 다릅니다. 승진이라면 같은 사람이고,  │
│     아니라면 다른 분일 수 있어요.              │
│                                              │

📌 **`contact_field_diff.dart`를 그대로 쓴다** — 추가 552에서 「합치면 무엇이
어떻게 되는지 안 보인다」는 문제로 만든 것이고, 여기가 바로 그 화면이다.

🚨 **합치기를 누르면 지금 등록 흐름의 합치기와 같은 규칙을 탄다** — 사진·이력을
버리지 않고, 빈 값으로 덮지 않는다(추가 552·553).

## 6. 「따로 두기」는 다시 안 묻는다

```
사람이 "다른 사람이다"라고 한 쌍을 계속 다시 보여 주면 그것도 늑대소년이다
```

**무엇을 기억하나**: 명함 두 장의 id 쌍(순서 없음).

**어디에 두나**: 🚨 **서버(계정 단위)**. 기기에만 두면 **다른 기기에서 또
묻는다** — 2026-08-28에 기기별 장부가 사실과 어긋나 하루를 쓴 자리와 같은
모양이다(추가 555·558).

```
users/{uid}/notDuplicates/{쌍 id}   ← 담는 것은 명함 id 둘뿐, 개인정보가 아니다
```

⚠️ **되돌릴 수 있어야 한다.** 잘못 눌렀을 때 방법이 없으면 그 쌍은 영영 안
보인다 → 묶음 목록에 **「따로 두기로 한 것 N쌍」**을 열 수 있게 둔다.

⚠️ **명함이 지워지면 그 기록도 지운다.** 안 지우면 id가 남아 쌓인다
(`deletedContacts` 정리에서 겪은 것과 같다).

## 7. 판정 규칙

```
이름이 같다(공백·대소문자 무시)          → 묶는다
그런데 추가 577에 걸린다(연락처가 맞다)   → 여기 안 넣는다. 그건 확인창이 처리한다
「따로 두기」로 표시된 쌍                → 안 넣는다
```

⚠️ **이름 정규화는 지금 `_normalizeName`을 그대로 쓴다** — 넓히면 동명이인이
더 걸린다. `홍 길동`과 `홍길동`까지는 같게 보고, 그 이상은 손대지 않는다.

## 8. ⬜ 못 잰 것 — 실측이 필요하다

```
연락처가 하나도 없는 명함이 얼마나 되나        모른다
「같은 이름」 묶음이 실제로 몇 개나 생기나      모른다
```

⚠️ **8/20 표본(95장)은 못 쓴다** — 그때는 휴대폰이 **단독 필수**여서 빈 채로
저장할 방법이 없었다. **재는 도구가 답을 미리 정해 놓은 표본**이다(추가 577).

📌 **두 기기가 지금 비어 있으므로**, globe2030님이 명함을 다시 등록하시면
**그때 셀 수 있다.** 그 숫자가 나오면 **「조용한가」를 실측으로 확인할 수
있다** — 100장에 묶음이 두어 개면 조용한 것이고, 스무 개면 시끄러운 것이다.

🚨 **그 실측 전에는 「조용하다」고 단정하지 않는다.**
