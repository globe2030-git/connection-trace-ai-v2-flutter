# 승인된 알림톡에 채널추가 버튼이 붙었다 — 야간에 인증이 막히나 (2026-09-06)

> 카카오는 **채널추가형을 「비광고성」으로 정의**하고 우리 본문은 인증번호다.

> ⚠️ **다만 「카카오가 안 걸린다고 말한」 것이 아니다.** 카카오 공식 문서에는

>
> 🚨 **이 결론은 「알림톡(정보성)」에 대한 것이다. 광고성 메시지는 반대다.**
> **브랜드메시지(구 친구톡)** 는 `§50③` 이 그대로 걸리고, 시행령의 야간 예외는
> **전자우편뿐**이라 카카오톡은 예외가 아니다 — 카카오 기준 발송 가능 시간은

## 0. 🚨 먼저 — 전달받은 전제 셋이 틀렸다

조사를 시작하며 받은 내용과 실물이 달랐다. **결론은 안 바뀌지만, 근거를 그대로
옮기면 다음 사람이 헛다리를 짚는다.**

| 전달받은 것 | 실물 | 어떻게 확인했나 |
|---|---|---|
| 템플릿 유형이 **「광고추가형」** | **「채널추가형」** 이다 | 카카오 공식 가이드 원문 |
| **`정보통신망법 §50②`** 가 야간 제한 | **`§50③`** 이다. ②는 수신거부·철회 조항 | 조문 전문 대조 |
| 기획서 `:388 :398 :521 :909` | **`:411 :421 :544 :932`** | 파일 999줄, `grep -n "버튼"` |

⭐ **가장 중요한 정정은 첫째다.** 전달받은 근거는 *"AC 버튼은 광고추가형·복합형에서만
쓸 수 있다 → 즉 우리 것은 광고추가형이다"* 였는데, **카카오 원문은 정반대에 가깝다:**

> **채널추가형** — *"**비광고성 메시지** 하단에 카카오톡 채널 추가가 포함 된 경우
> 사용할 수 있습니다."*
> — [카카오 비즈니스 가이드 · 알림톡 유형](https://kakaobusiness.gitbook.io/main/ad/infotalk/content-guide) (2026-09-06 확인)

**「광고라서 이 유형을 쓴다」가 아니라 「비광고성일 때 쓸 수 있는 유형」이다.**

📌 전달한 쪽도 *"이것도 검색 요약이지 원문을 연 것이 아니다"* 라고 스스로 단서를
달아 두었다. **그 단서가 값을 했다** — 원문을 여니 뜻이 뒤집혔다.

## 1. ① 야간 발송 제한(21시~08시)에 걸리나 — **안 걸린다**

> 🚨 **여기서 말하는 것은 「알림톡」뿐이다.**
> **광고성 브랜드메시지(구 친구톡)는 반대로 걸린다** — 야간 예외가 전자우편뿐이라
> 카카오톡은 해당이 없고, 카카오 기준 발송 가능 시간이 **08:00~20:50** 이다.
> 근거는 `docs/legal/research/legal-review-reply-alimtalk-ad-send-2026-09-06.md`.
> ⭐ **모순이 아니라 대상이 다른 것이다** — `§50③` 은 「광고성인가」로 갈린다.

### 1-1. 법령 원문 — 걸리는 대상이 명확하다

> **정보통신망법 제50조 제3항**
> *"오후 9시부터 그 다음 날 오전 8시까지의 시간에 전자적 전송매체를 이용하여
> **영리목적의 광고성 정보**를 전송하려는 자는 제1항에도 불구하고 그 수신자로부터
> 별도의 사전 동의를 받아야 한다."*
> — [CaseNote · 정보통신망법 제50조](https://casenote.kr/법령/정보통신망_이용촉진_및_정보보호_등에_관한_법률/제50조) (2026-09-06 확인)

참고로 같은 조의 다른 항은 이렇다 — **②를 야간 조항으로 잘못 알기 쉽다:**

```
제1항  영리목적의 광고성 정보 전송 시 명시적 사전 동의
제2항  수신거부·동의철회한 사람에게는 전송 금지
제3항  🚨 야간(21:00~08:00)에는 별도의 사전 동의   ← 여기다
```

⭐ **조항이 걸리는 것은 「전송 시간」이 아니라 「그 정보가 광고성인가」다.**
광고성이 아니면 이 조항 자체가 적용되지 않는다.

### 1-2. 우리 메시지는 광고성인가 — **아니다**

```
본문        인증번호 안내 (OTP_TEMPLATE_BODY)  ← 승인된 템플릿 본문과 코드가 일치함이
                                               이미 대조로 확인됨
템플릿 유형  채널추가형 — 카카오 정의: "**비광고성 메시지** 하단에
             카카오톡 채널 추가가 포함 된 경우"
버튼         AC(채널추가) 1개 · 이름과 문구가 **고정**이라 우리가 못 바꾼다
```

📌 **버튼 문구는 카카오가 정해 놓고 수정을 막는다:**

> *"카카오톡 채널명을 제외한 영역은 **「채널 추가하고 이 채널의 마케팅 메시지 등을
> 카카오톡으로 받기」** 문구만 사용해야 하며, **수정이 불가능**하다."*
> — [카카오 비즈니스 가이드 · 채널추가 요청 메시지](https://kakaobusiness.gitbook.io/main/partner/smb/channel/step2/message) (2026-09-06 확인)

⚠️ **전달받은 승인 화면 문구와 다르다.**

```
카카오 공식 문구   "채널 추가하고 이 채널의 **마케팅 메시지 등을** 카카오톡으로 받기"
전달받은 화면      "채널 추가하고 이 채널의 **광고와 마케팅 메시지를** 카카오톡으로 받기"
```

🚨 **어느 쪽이 맞는지 저는 모른다.** 승인 화면을 직접 못 봤다. 가능한 것 셋:
**(가)** 카카오가 문구를 개정했고 가이드가 낡았다 · **(나)** 화면을 옮겨 적는
과정에서 바뀌었다 · **(다)** 유형이 채널추가형이 아니라 다른 것이다.

⭐ **(다)라면 이 문서의 결론이 흔들린다.** **승인 화면에서 「템플릿 유형」 필드를
그대로 읽어 확인해 주십시오** — 그 한 줄이 이 조사의 전제다.

### 1-2-1. ⭐ 법무 회신이 같은 결론을 독립적으로 냈다

같은 날 나온 법무 회신
(`docs/legal/research/legal-review-reply-alimtalk-channel-add-2026-09-06.md`)이
**서로 모르는 채로 같은 근거에 도달했다:**

```
· 카카오의 「비광고성 메시지 하단에」 정의를 같이 인용한다
· 🚨 **§50조의 의무는 「전송」에 붙는다** — 제1·4·5·7항 모두 주어가
  *"…전송하려는 자"* 다. **버튼을 실어 보낸 것만으로는 광고성 정보를
  전송한 것이 아니다**
· 승인 화면의 「유형」 필드를 못 봤다는 한계도 똑같이 적고 있다
```

⭐ **셋째가 겹친 것이 특히 값나간다** — 저도 그 회신도 *"승인 화면 한 줄이
전제"* 라고 따로 적었다. **두 사람이 각자 같은 구멍을 짚었다면 그 구멍은 실재한다.**

📌 **그 회신은 「우리가 그 동의를 쓸 것인가」까지 본다** — 카카오톡 채널로 광고성
메시지를 **한 번이라도 보내는 순간** 방침 문구를 고쳐야 한다는 결론이다. 이 문서의
3절(사실관계)이 거기로 이어진다.

### 1-3. ⚠️ 그런데 「안 걸린다」의 성격을 정확히 적는다

```
✅ 확인된 것   §50③ 은 「영리목적의 광고성 정보」에만 적용된다        (법령 원문)
✅ 확인된 것   카카오는 채널추가형을 「비광고성」으로 정의한다          (카카오 원문)
✅ 확인된 것   우리 본문은 인증번호다                                (코드 대조 완료)

🚨 확인 못 한 것  **카카오 공식 문서에 「알림톡은 야간 제한을 안 받는다」는
                 문장이 없다.** 「알림톡 유형」·「메시지 발송 유의사항」 두 페이지를
                 열었는데 **야간(21~08) 언급이 아예 없다.**
```

📌 **즉 이 결론은 「카카오가 그렇다고 말해서」가 아니라 「법령의 적용 대상이
아니어서」다.** 두 근거의 무게가 다르므로 구분해 적는다.

⚠️ **그리고 이것이 이 조사의 한계다** — 규제기관 유권해석이나 카카오의 명시적
확인이 있으면 더 단단해진다. **선임 변호사 확인 대상이다.**

### 1-4. 그래서 배포 계획에 미치는 영향

**⛔ 야간에 인증이 막히는 일은 없다** — 지금 확인한 범위에서는 그렇다.
**오늘 배포 계획을 이 사유로 바꿀 필요는 없어 보인다.**

⚠️ 다만 위 **(다) 가능성**(유형이 채널추가형이 아닐 수 있음)이 남아 있으므로,
**승인 화면의 「템플릿 유형」 한 줄을 확인한 뒤 최종 판단**하시는 편이 안전하다.

## 2. ② 발송할 때 버튼 파라미터를 보내야 하나 — **문서로는 못 가렸다. 실측하면 나온다**

### 지금 코드

`AligoSendPayload`(`functions/src/phoneOtpSender.ts`)에 **button 관련 필드가 없다**:

```
apikey · userid · token · senderkey · tpl_code · sender
receiver_1 · subject_1 · message_1
failover · fsubject_1 · fmessage_1 · testMode
```

`grep -rn "button" functions/src` → **0건**.

### 문서로 가려지지 않는 이유

AC 버튼은 **템플릿에 등록된 고정 버튼**이고 이름도 문구도 우리가 못 바꾼다(위 인용).
즉 **동적으로 채울 값이 없다.** 일반적으로 이런 버튼은 발송 시 재전송이 필요 없지만,
**대행사(알리고) API 가 무엇을 요구하는지는 대행사 규격의 문제**이지 카카오 정책의
문제가 아니다. 공개 문서만으로는 확정할 수 없었다.

### ⭐ 그런데 이건 실측이 가능하다

`AligoSendPayload` 에 **`testMode` 필드가 이미 있다.** `testMode: "Y"` 로 한 번
왕복시키면 **버튼 없이 보냈을 때 성공하는지**가 그 자리에서 나온다.

```
testMode: "Y" 로 발송 → 성공하면   버튼 파라미터 불필요 (지금 코드 그대로 OK)
                      → 실패하면   응답 메시지가 무엇을 요구하는지 알려 준다
```

⚠️ **제가 안 돌렸다.** 실제 발송 API 를 치는 일이고, 자격증명이 필요하며,
**되돌릴 수 없는 조작에 가깝다**(대행사 로그에 남는다). **globe2030님 또는 PM
판단**으로 남긴다.

📌 **문서를 더 뒤지는 것보다 이 왕복 한 번이 빠르고 확실하다.** 오늘 이 저장소가
배운 것 그대로다 — **「계산은 틀려도 그럴듯하고, 실측은 틀리면 티가 난다.」**

## 3. ③ 광고 동의 경로가 하나 늘었다 — **사실관계만**

⚠️ **법적 판단은 하지 않는다.** 확인한 사실만 적는다.

### 3-1. 버튼을 누르면 무엇이 일어나나

```
누르는 사람   카카오톡 채널을 **추가**한다
동의하는 것   그 채널의 **마케팅 메시지 수신**
              (문구: "채널 추가하고 이 채널의 마케팅 메시지 등을 카카오톡으로 받기")
기록 위치     🚨 **카카오 쪽이다.** 우리 서버(`users/{uid}`)가 아니다
철회 방법     카카오톡에서 채널 차단·삭제 — **우리 앱 안에서는 못 한다**
안 보이는 경우 **이미 채널을 추가한 사람에게는 버튼이 안 보인다**
```

### 3-2. 앱 안의 광고 동의와 어떻게 다른가

| | 앱 안 광고 동의 | 채널추가 버튼 |
|---|---|---|
| 무엇에 동의 | 우리가 보내는 광고성 정보(이메일·푸시) | **카카오 채널**의 마케팅 메시지 |
| 기록 위치 | `users/{uid}.adConsent*` (우리 서버) | **카카오** |
| 철회 | 앱 설정에서 | **카카오톡에서** |
| 동의 시각 보존 | `adConsentAt` — 철회해도 안 지운다(입증자료) | 우리가 모른다 |

### 3-3. 🚨 방침·약관이 이것을 말하고 있나 — **말하고 있지 않다**

```
grep "채널|카카오톡 채널|알림톡"  docs/legal/*.html
  → 걸린 것은 privacy-policy.html:179 한 줄뿐이고, 그것은
    *"계정 배포일이 행정(알림톡 심사·발송 대행사 계약)에 걸려 미확정"* 이라는
    **일정 이야기**다. 채널 추가나 채널 마케팅 수신에 관한 서술은 **0건**이다.
```

**즉 이용자가 방침·약관을 읽어도 「채널을 추가하면 무슨 메시지를 받게 되는지」를
알 수 없다.**

📌 **이것을 「위반」이라고 적지 않는다** — 그 판단은 이 문서의 범위 밖이고,
채널 추가는 **카카오 플랫폼에서 카카오 문구로 이뤄지는 동의**라 우리 방침이 다뤄야
하는지 자체가 검토 대상이다. **사실은 「우리 문서에 없다」는 것 하나다.**

⚠️ **법무 검토가 필요하면 이 절을 그대로 넘기시면 된다.**

## 4. 이 문서가 못 본 것

```
① **승인 화면을 직접 못 봤다**
   템플릿 유형 필드·버튼 문구를 전달받은 대로만 알고 있다. 그런데 그 문구가
   카카오 공식 가이드와 **다르다**(1-2 절). **유형 한 줄 확인이 이 조사의 전제다.**

② **카카오가 「야간 제한 없음」을 명시한 문장을 못 찾았다**
   공식 두 페이지에 야간 언급이 아예 없다. 결론은 **법령 적용 대상이 아니라는
   추론**이지 카카오의 확인이 아니다(1-3 절).

③ **버튼 파라미터를 실측 안 했다**
```
