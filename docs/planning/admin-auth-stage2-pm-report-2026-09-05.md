## 3. 🚨 PM 이 알아야 할 것 — 「끝났다」가 「켜졌다」가 아니다

```
function adminSessionRequired() { return false; }   ← firestore.rules 안의 스위치
```

**켜는 것은 설계 4단계(콘솔 인증 화면) 배포와 같은 배포여야 한다.** 지금 켜면
관리자가 아무것도 못 한다 — 인증할 화면이 없기 때문이다.

### 왜 주석이 아니라 스위치인가

인수인계에는 *"③ 은 화면과 함께 배포해야 한다"* 라고만 적혀 있었는데,
**그것을 지킬 수단이 없었다.**

```
firebase deploy --only firestore:rules  는 이 파일을 통째로 올린다
   → cardSources 규칙이 미배포라 누군가 곧 이 명령을 돌린다
   → 그때 ③ 이 딸려 나가면 관리자가 전부 잠긴다
```

⭐ **「안 나가게」는 지킬 수 없으므로 「나가도 안 켜지게」로 바꿨다.**
꺼져 있는 동안은 `||` 가 앞에서 끊겨 `get()` 이 아예 안 돈다(조회 비용 0).

📌 **그래서 이 브랜치는 지금 배포해도 안전하다.** ~~①② 는 아무도 안 쓰는
컬렉션을 잠그는 것이고,~~ ③ 은 꺼져 있다. 그 「안전함」자체를 테스트로 고정했다
(*"꺼져 있는 동안은 세션 없이도 관리자 조작이 된다"* ALLOW 케이스).

> ⚠️ **2026-09-05 정정 — 근거의 절반이 없었다.** 이 PR 에는 ①② 가 없었으므로
> **그때의 근거는 ③ 하나뿐**이었다. **결론(배포해도 안전)은 그때도 지금도
> 맞다** — 다만 이유가 하나였다.
>
> 📌 그리고 ①② 가 들어간 지금도 **동작은 안 바뀐다.** 두 경로는 맨 아래
> `match /{document=**} { allow read, write: if false; }` 가 이미 거부하고 있었다.
> ①② 를 적은 것은 **나중에 누가 `match /config/{doc}` 같은 넓은 규칙을 넣는
> 순간 조용히 뚫리는 것**을 막기 위해서다(추가 683).

## 4. 🚨 인수인계가 틀렸던 곳 하나 — 실물이 잡았다

```
문서   rules 는  request.time < expiresAt  한 줄로 비교만 한다
실물   expiresAt 은 Timestamp 가 아니라 epoch 밀리초 「숫자」다
       functions/src/index.ts writeAdminSession → adminAuth.ts:167 이 number 를 돌려준다
```

- **증상**: 관리자가 아무 조작도 못 한다
- **원인**: 타입이 달라 비교가 **오류**가 되고, rules 의 오류는 곧 **거부**다

로그에는 「거부」로만 남고 **왜** 거부인지는 안 남는다.
→ `request.time.toMillis() < expiresAt` 로 썼다.

### ⚠️ 이것이 왜 안 잡힐 뻔했나 (PM 이 다른 세션에 옮길 값이 있는 대목)

음성 대조군으로 틀린 규칙을 일부러 넣어 봤다.

```
DENY 케이스 셋   전부 통과했다  ← 오류 → 거부라서 기대와 결과가 같다
ALLOW 케이스 하나 여기서만 터졌다
```

> **「막히는지」만 재면 「잘못 막히는 것」은 안 보인다.**

**「그런 일은 없었다」**로 읽혀야 한다.

📌 **왜 커밋 메시지만 낡았나**: 병합 전에 PR 본문에는 정정 블록이 붙었는데,
