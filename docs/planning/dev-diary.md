# 커넥션센스 개발 좌충우돌 (연재 기록)

**이 문서는 기술 로그가 아니라 이야기다.** 이 앱을 **처음 시작한 순간부터
스토어에 최종 등록되는 날까지**, 개발자가 별별 것에 걸려 넘어지며 한 걸음씩
나아가는 여정의 기록. 이 일지가 개발 후기 **동영상**과 **만화(개발 좌충우돌
시리즈)**를 만드는 **1차 소스**다 — 실제 생성 프롬프트는
[`dev-story-prompt.md`](./dev-story-prompt.md)에 있다(동영상용 + 만화용).

> ⚠️ **이 문서는 진행 중이다.** 프로젝트 시작부터 지금까지의 주요 국면을
> 담고, **iOS·Android 양쪽 앱이 스토어에 최종 등록될 때까지 계속 이어 붙인다.**
> 새 세션에서 의미 있는 사건이 있으면 해당 국면/일차에 에피소드를 추가할 것.
> 에필로그(만화/영상 구성)는 여정이 끝나면 완성한다.

> 톤: 각 에피소드는 **[상황] → [함정] → [깨달음]** 구조의 공감형 코미디.
> 관통 주제: **"코드는 맞는데 실물이 틀린" 결함**과 **"증상 이름이 범인을
> 가리키지 않는" 순간들.**
>
> 시간순 사실관계의 원본은 [`backlog.md`](./backlog.md)(추가 1~110+),
> 국면 요약은 [`HANDOFF.md`](./HANDOFF.md)("0" ~ "0-8" 섹션),
> 스토어 절차는 [`store-registration-playbook.md`](./store-registration-playbook.md).
> "📸"는 실제 캡처가 남아 있는 장면(주로 스토어 등록 편).

# 🌱 국면 0 — 시작: "근처에 있으면 알려주는 명함첩"

명함을 아무리 모아도 결국 서랍 속에서 잠든다. **"그 사람 근처에 갔을 때
알려주고, 무슨 말을 꺼낼지도 귀띔해주면 어떨까?"** — 이 한 문장이 커넥션센스의
시작이었다. 명함을 스캔해 인맥을 등록하고(OCR), 그 사람의 주소 근처에 가면
알려주고(위치), AI가 대화 포인트까지 만들어 준다.

**첫 번째 다짐**: 화면을 채우려고 **가짜 데이터를 만들지 않는다.** 이건
개발 내내 지킨 대원칙이 됐다. (지키기가 생각보다 어려웠다 — 국면 1 참고.)

# 🎭 국면 1 — 가짜의 유혹: "스톡 사진 4장의 비밀"

**[상황]** 프로필 사진 선택 기능이 잘 동작하는 것처럼 보였다.

**[함정]** 알고 보니 "사진 선택"이 실제로는 **미리 넣어둔 스톡 사진 4장을
돌려가며 보여주는** 가짜 구현이었다. 화면은 그럴듯했지만 진짜가 아니었다.

**[깨달음]** 데이터가 없으면 **빈 화면을 그대로 보여준다.** 가짜로 채우는
순간, 사용자는 "되는 줄" 알고 우리는 "된 줄" 안다. 이 사건 이후 "그럴듯해
보이는 것"을 특히 의심하게 됐다.

# 🕵️ 국면 2 — "코드는 완벽한데 실물이 틀렸다"

이 프로젝트에서 진짜로 터진 결함들은 **테스트가 전부 초록불인데도** 실물에서만
드러났다. 이 국면의 교훈이 이후 모든 검증 방식을 바꿨다.

**에피소드 2-1 — 서버에 발가벗겨진 개인정보 🔓**
명함을 암호화한다고 믿었는데, 실기기 저장소를 직접 열어보니(`adb run-as`)
**전화번호·이메일·주소가 평문 그대로** 읽혔다. 서버(Firestore)에도 5건 중
3건이 평문. "다음에 저장될 때 암호화"되는 구조라, 한 번도 다시 저장 안 된
데이터는 계속 벗은 채였다. → 로컬·서버 양쪽 **AES-256-GCM**으로 전환.

**에피소드 2-2 — 죽어 있던 재시도 🧟**
좌표 재계산 재시도 로직이 코드상 멀쩡했다. 그런데 **부르는 곳이 복원 경로
하나뿐**이라, 평소엔 한 번도 안 돌았다. 서비스는 살아있는데 아무도 호출하지
않는 유령 코드. → 로그인할 때마다 이어서 처리하도록 연결.

**에피소드 2-3 — 앱을 지워도 남는 유령 (iOS) 👻**
앱을 삭제했는데 로그인 정보와 암호화 키가 남았다. 범인은 **iOS Keychain은
앱을 지워도 안 지워진다**는 OS 특성. → 첫 실행 감지(`FreshInstallService`)로
해결. 덤으로 "기기 변경 시 키 복원" 경로까지 실기기에서 검증됐다.

**[국면 깨달음]** **"테스트 통과 = 동작함"이 아니다.** 저장·복원·재설치·
서버 실물은 자동 검사가 원리상 못 본다. 그래서 실기기 덤프와 서버 직접 조회가
검증 루틴에 들어왔다.

# 🏠 국면 3 — 주소가 안 눌리던 날

**[상황]** 도로명주소 검색 화면에서 주소가 선택이 안 됐다. 화면엔
**`ERR_UNKNOWN_URL_SCHEME`**이라는 낯선 에러.

**[함정]** 이 에러 이름만 보면 URL이 잘못된 것 같다. 하지만 진짜 원인은
웹뷰가 **`file://` origin**에서 열려 카카오 우편번호 서비스의 콜백이 막힌
것이었다. **증상(에러 이름)과 원인이 다른 곳**에 있던 첫 사례.

**[깨달음]** 이 구분(증상 vs 원인)이 이후 모든 디버깅의 기본기가 됐다.
커밋 메시지에도 "증상은 X였고 원인은 Y였다"를 꼭 남기게 됐다.

# 🎨 국면 4 — 보라에서 파랑으로: 하룻밤의 리브랜딩

**[상황]** 디자인 핸드오프가 왔다. 24×24 격자에 38종 아이콘, 브랜드 블루
`#2563EB`. "내일 아침까지 iPhone·Android 모두 적용하고 검수까지."

**[함정]** 아이콘 색을 바꾸려 `colorFilter`로 덮었더니 **강조색까지 다
덮여버렸다.** 기본색만 바꾸고 강조색은 살려야 하는데.

**[깨달음]** `SvgTheme(currentColor:)`로 기본색만 치환하는 방법으로 전환.
퍼플(`#6C5CE7`)에서 브랜드 블루로, 아이콘 38종·런처 아이콘·스플래시까지
하룻밤에 갈아끼웠다. 테마 토큰 3개가 유일한 소스라 나머진 자동으로 따라왔다.

# 🤖 국면 5 — AI가 영어로 헛소리하던 밤

**[상황]** AI 대화 가이드가 한국어 대화 포인트를 만들어줘야 하는데, 화면엔
영어 파편만 떴다.

**[함정]** 겹겹의 함정이었다. Gemini 크레딧 고갈 → 월 지출 한도 → 서버 하루
호출 한도 소진… 다 걷어내니 진짜 범인이 나왔다. **`gemini-3.6-flash`가
사고 과정(thinking)과 초안을 먼저 쓰느라 출력 토큰(400)을 다 써버려**,
정작 한국어 답변이 나오기 전에 잘렸던 것.

**[깨달음]** 출력 토큰을 3000으로 올리고, 한글 없는 줄을 걸러내는 방어
로직 추가. 마침내 두 연락처에서 정상 한국어 대화 포인트 3개가 떴다.
**"에러 하나를 고치면 그 뒤에 진짜 에러가 숨어 있다."**

# 🚀 국면 6 — 출시 준비의 복병들

**에피소드 6-1 — 앱이 안 켜져요 (무한 로딩) ⏳**
보안 장치(App Check)를 켰더니 앱이 시작 화면에서 멈췄다. `await`가 시작을
막았는데, **예외가 아니라 "응답 없음"이라 `try/catch`로도 안 잡혔다.**
증상은 "무한 로딩", 원인은 "시작 코드가 스스로를 막음".

**에피소드 6-2 — 지워진 명함 (돌이킬 수 없는 삭제) 💔**
계정 삭제 다이얼로그가 **무엇을 지우는지 안 보여줘서**, 의도와 다른 계정이
삭제됐다. 계정 삭제는 암호화 키까지 지우므로 다른 기기의 사본도 복구 불가.
명함 몇 건이 영영 사라졌다. → 다이얼로그가 삭제 대상을 명확히 표시하도록 수정.
**"되돌릴 수 없는 버튼은 반드시 무엇을 하는지 보여줘야 한다."**

# 📅 스토어 등록 편 · 1일차 (2026-08-09) — 미로의 절반

코드는 다 짰다. 이제 **세상에 내보내는** 마지막 관문. 앱을 만드는 것과
앱을 등록하는 것은 완전히 다른 일이었다.

**에피소드 1 — 안드로이드 열쇠공이 되다 🔑**
Android는 앱 서명 "열쇠(키스토어)"를 직접 만들어 보관해야 한다. 터미널이
갑자기 한국어로 심문을 시작한다. "이름과 성을 입력하십시오." 📸 손이 미끄러져
인증서에 영원히 **"지금 CreamHouse"**가 박혔다(표시용이라 무해하지만 두고두고
웃김). 깨달음: 열쇠는 **잃어버리지 않는 게** 100배 중요하다 — 잃으면 앱
업데이트를 영원히 못 올린다. iCloud·맥 메모 2곳에 백업.

**에피소드 2 — `CHANGE_ME`라는 함정 🪤**
비밀번호 자리표시자 `CHANGE_ME`를 보고 **"새 비번을 지어내라"**는 줄 알고
엉뚱한 값을 넣었다. `keystore password was incorrect`. 📸 고치니 이번엔
`Get Key failed`(문은 열리는데 금고가 안 열림). 깨달음: 비번은 **지어내는 게
아니라 열쇠 만들 때 정한 값을 기억해내는** 것. 마침내 `✓ Built app-release.apk`.

**에피소드 3 — 어제의 유령 👻**
어제는 애플 업로드가 `Unable to authenticate`로 막혔다. 각오하고 열었더니
**그냥 됐다.** 📸 어제 실패는 실력이 아니라 **애플 서버 밤 점검**에 걸린
일시 장애였다. "안 되면 내 잘못"이라 자책하기 전에 밖을 의심하라.

**에피소드 4 — 안 쓰는 기능 때문에 혼나다 🗺️**
`90683: Missing purpose string` 경고. 📸 우리는 위치를 "사용 중에만" 쓰는데
'항상' 설명이 없다고. 알고 보니 지도 부품(geolocator)이 '항상' 기능을
**참조만** 해도 애플은 해명을 요구한다. 한 줄 추가로 해결, 새 빌드에서
경고 삼각형이 사라졌다. 📸

**에피소드 5 — 수출업자가 된 명함 앱 📦**
"앱 암호화 문서" 팝업. 📸 명함 앱이 갑자기 국제 수출 규제 대상 + **"프랑스에서
사용 가능합니까?"** 심문까지. 우리가 AES-256을 쓰니 "표준 알고리즘"에 해당.
미리 정리해둔 정답 문서 덕에 30분을 아꼈다.

**에피소드 6 — "외부 테스팅"은 어디 있나요 🔍**
베타 테스터 그룹을 만들려 ➕를 눌렀더니 **"내부 그룹"** 창. 사이드바 어디에도
**"외부 테스팅"이 없다.** 📸 함정은 UI에 있었다 — 외부는 위쪽 배너의
**"그룹 생성"** 링크로 만들어야 하고, 외부 그룹이 하나도 없으면 사이드바
항목 자체가 안 생긴다. "버튼이 없는 게 아니라 다른 곳에 있었다."

**에피소드 7 — 오늘은 여기까지 🌙**
외부 그룹을 만들려다 깨달았다. **테스터가 있어야 초대를 하지.** 무리하지
않고, 내일 직원들 아이폰 사용 여부를 확인해 이메일을 모으기로. 오늘 넘은
문턱: Android 서명 키 완성, iOS 경고 없는 빌드 업로드, 수출 규정 통과,
테스트 정보 입력. 미로의 절반을 지났다.

**➡️ 2일차 예고**: 테스터 이메일 수집 → 외부 그룹 → 심사용 계정 → 베타 심사
제출. 애플과 구글의 심사를 무사히 통과할 것인가…?
