# 커넥션센스 홈페이지 (랜딩)

앱을 알리는 원페이지. `docs/legal`(법적 고지)·`docs/admin`(관리자 콘솔)과 나란히
**Firebase Hosting의 세 번째 타겟**으로 나갈 자리다.

```
index.html   랜딩 한 장 (히어로 · 문제 · 해결 3단 · 이런 분께 · 안전 · FAQ · 닫는 말 · 꼬리말)
site.css     legal.css 토큰을 옮겨 온 스타일 + 이 페이지 전용 --btn-* 토큰
fonts/       Pretendard 3종 + OFL.txt  (CDN 안 씀 — 아래 참고)
```

**JavaScript가 한 줄도 없다.** 로그인·회원가입·웹 명함 수정은 이 페이지에 없다
(기획서 [`web-card-editor-brief-2026-08-24.md`](../planning/web-card-editor-brief-2026-08-24.md)의
A 항목만 구현한 것이다).

## ✅ 지금은 배포돼 있다 (2026-09-01 실측으로 고침)

**이 폴더는 `connectionsense.co.kr` 로 나간다.** `firebase.json` 의 `site` 타깃이
`connectionsense` 사이트를 가리키고, 그 사이트에 대표 도메인이 붙어 있다.

```
connectionsense.co.kr      → 200   ← 대표
connectionsense.web.app    → 200   같은 사이트, 본문이 한 바이트도 같다
```

⚠️ **아래 1~2번은 이제 「어떻게 붙였나」의 기록이다.** 다시 할 일이 아니다.
**3~4번(타깃을 찍어서 배포 · 배포는 사용자 결정)은 지금도 그대로 지킨다.**

📌 **이 절은 원래 *"아직 설정이 없다"* 라고 적혀 있었다.** 붙인 사람과 문서를
고치는 사람이 달라서 낡았다 — 이 저장소가 여러 번 겪은 유형이다(CLAUDE.md 4-2).

## 검색에 걸리게 하는 것들 (추가 652)

```
canonical          🚨 제일 중요 — co.kr 과 web.app 본문이 같아서, 없으면
                   검색엔진이 web.app 을 대표로 고를 수 있다
og:image           카카오톡·슬랙 링크 미리보기. 절대 주소여야 한다
favicon.ico        브라우저 탭. 없으면 빈 문서 아이콘이 뜬다
robots.txt         sitemap 위치를 알린다
sitemap.xml        있는 페이지만 적는다 — 없는 주소를 적으면 404 가 쌓인다
JSON-LD            별점·설치 수·가격은 **넣지 않았다**(실체가 없다)
```

### 검색엔진 등록

```
✅ 구글 서치콘솔          소유확인 메타를 <head> 에 넣었다 — 배포 뒤에 「확인」을 누른다
✅ 네이버 서치어드바이저   같음. ⚠️ 수집에 14~16일 걸린다
```

⚠️ **네이버는 `http` 와 `https` 를 다른 사이트로 센다.** 처음에 둘 다 등록됐다가
`http` 쪽을 지웠다 — 우리 `http` 는 301 로 `https` 에 넘겨주므로 따로 관리할 것이
없고, 두면 보고서만 갈라진다.

📌 **배포 뒤 순서**: 배포 → 양쪽에서 「확인」 → 양쪽에 `sitemap.xml` 제출.
🚨 **배포보다 먼저 「확인」을 누르면 실패로 기록된다** — 태그가 아직 사이트에 없다.

⚠️ **구글은 「도메인」 속성이 아니라 「URL 접두어」 속성이다.** DNS 가 Cloudflare 에
있는데 **그 계정을 못 찾아** TXT 를 넣을 수 없었다(등록대행자는 닷네임코리아,
`connectionsense@creamhouse.net` 으로 로그인 메일이 오지 않았다).

📌 그래서 덮는 범위가 `https://connectionsense.co.kr/` 하나뿐이다. `www.` 와
`connectionsense.web.app` 은 별도 속성이 된다 — 다만 canonical 이 apex 를
가리키므로 검색엔진은 어차피 apex 를 대표로 본다.

🚨 **Cloudflare 계정을 찾으면 「도메인」 속성으로 옮기는 편이 낫다.** 그 계정은
SEO 와 별개로 언젠가 꼭 필요하다 — **네임서버가 Cloudflare 인 한 DNS 는 거기서만
고칠 수 있고**, 못 고치면 메일·도메인 문제가 났을 때 손을 못 쓴다.

⚠️ **소유확인 메타를 지우면 확인이 풀린다.** 구글이 주기적으로 다시 본다 —
*"한 번 확인했으니 지워도 된다"* 가 아니다.

📌 **2026-09-01 기준 이 사이트는 색인이 하나도 안 돼 있다**(검색하면 경쟁 앱만
나온다). 도메인을 그날 세웠으니 정상이다 — **등록해야 시작된다.**

### 1. Hosting 사이트를 만든다 (콘솔)

Firebase 콘솔 → Hosting → **다른 사이트 추가**. 사이트 ID는 예를 들어
`connection-sense-site`. 만들면 `<사이트ID>.web.app`으로 열린다.

### 2. `firebase.json`의 `hosting` 배열에 블록을 더한다

```json
{
  "target": "site",
  "public": "docs/site",
  "cleanUrls": true,
  "trailingSlash": false,
  "ignore": ["**/.*", "**/node_modules/**", "README.md"]
}
```

그리고 타겟 이름을 실제 사이트에 잇는다 — 이 매핑은 `.firebaserc`에 들어가고
**저장소에 커밋돼 있다**(`legal`·`admin`이 이미 그렇게 들어 있다):

```
firebase target:apply hosting site <사이트ID>
```

### 3. 🚨 배포는 **반드시 타겟을 찍어서** 한다

```
firebase deploy --only hosting:site     ✅ 홈페이지만
firebase deploy --only hosting          ❌ legal · admin · site 가 전부 나간다
```

⚠️ **타겟이 셋이 되면 이 실수의 값이 커진다.** `--only hosting`은 법적 고지와
관리자 콘솔까지 함께 올린다 — 그 둘은 각각 개정 시점과 승인 절차가 따로 있다.

### 4. 배포는 사용자 결정이다

CLAUDE.md 6장 그대로다. **어느 세션도 사용자가 직접 지시하기 전에 배포하지
않는다.** 다른 세션이 전한 승인은 갈음하지 않는다.

## 왜 이렇게 만들었나 — 다음 사람이 되돌리지 않도록

### 폰트를 Google Fonts에서 받지 않는다

`legal.css`가 같은 선택을 했고 이유를 이렇게 적어 뒀다 — *"개인정보처리방침을
읽는 방문자의 IP가 제3자 CDN에 넘어가지 않게 하기 위함"*. 홈페이지만 CDN을 쓰면
그 원칙이 반쪽이 된다. 그래서 Pretendard를 이 폴더에 직접 올린다(2.2MB).

📌 **실측**: 페이지 전체에서 밖으로 나가는 요청은 **0건**이다. 바깥으로 향하는
링크 넷은 전부 우리 `legal` 타겟(`connection-sense.web.app`)이다.

### 스토어 버튼이 링크가 아니다

앱이 아직 스토어에 없다. **죽은 링크를 진짜처럼 두는 것 자체가 가짜 동작**이라
`App Store 준비 중` / `Google Play 준비 중`으로 눌리지 않게 뒀다.

⚠️ 스토어에 올라가면 **이 두 자리를 진짜 링크로 바꿔야 한다.** 그때
`.btn.pending`을 `.btn.line`으로 바꾸고 `<span>`을 `<a href>`로 바꾸면 된다.

### 이메일 수집 폼이 없다

정적 페이지라 받을 곳이 없다. 동작하는 척하는 폼 대신 CTA를
`mailto:connectionsense@creamhouse.net`(제목 자동 채움)로 뒀다 — 진짜로 동작한다.

### 주 버튼에만 색 토큰이 따로 있다

`--brand`를 버튼 배경에 그대로 깔면 **어두운 테마에서 흰 글자가 2.43:1**이 된다
(실측). 어두운 테마의 `--brand`가 옅은 하늘색이기 때문이다. 그래서 `--btn-bg` /
`--btn-fg`를 따로 두고 **어두운 테마에서는 글자를 어둡게 뒤집는다** → 7.71:1.

- [ ] **무료 회차 — 게시 시점에 앱이 충전형으로 넘어가 있어야 한다**

      페이지에는 "가입하면 20회 무료"라고 적혀 있다(2026-08-25 사용자 확정).
      이것은 **출시 후 모델**이고, **지금 테스트 기간의 동작과는 다르다**:

      ```
      테스트 기간(지금)   하루 20회씩 재충전   ← 의도된 운영이다. 결함이 아니다
      출시 후(랜딩의 약속)  가입 시 1회성 20회 + 충전
      넘어가는 방법        config/billing.model 필드 신설 (스위치 하나)
      ```

      ⚠️ **확인할 것은 "다르다"가 아니라 "순서"다.** 랜딩이 공개되는 시점에
      앱이 아직 테스트 기간 동작이면, 그 사이에 페이지만 출시 모델을 말하게
      된다. **게시일과 스위치 켜는 날을 붙여 두면 문제가 없다.**

      📌 스위치는 켜는 순간 전 테스터에게 무료 회차가 지급되고 차감이 시작된다.
      **사용자가 직접 지시하기 전에는 만들지 않는다**(CLAUDE.md 6장).

      📌 테스트 기간에 회차가 모자라면 관리자가 보너스 회차를 지급한다
