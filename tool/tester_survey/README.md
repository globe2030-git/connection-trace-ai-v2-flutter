# 테스터 설문 — 워드와 구글폼을 **한 벌에서** 만든다

배포할 때마다 테스터에게 보내는 확인·질문지다. **워드(종이·대면용)**와
**구글 설문(원격·자동 집계)** 두 가지로 나가는데, **문항은 한 곳에만 적는다.**

```
tool/tester_survey/tester_survey_spec.py  ← ⭐ 문항은 여기만 고친다
tool/tester_survey/make_tester_doc.py     → connection-sense-assets/문서/…확인및질문지_….docx
tool/tester_survey/make_tester_form.py    → connection-sense-assets/문서/…설문_구글폼_만들기.gs
```

📌 **산출물은 저장소 밖 `connection-sense-assets/문서/`에 떨어진다**(CLAUDE.md 4장).
자리를 정하는 것은 `tool/assets_dir.py` 한 곳이고, 폴더가 없으면 **만들지 않고
멈춘다** — 옛 코드처럼 조용히 엉뚱한 자리에 떨어지지 않게. 다른 자리에 두었으면
`CS_ASSETS_DIR=/경로 python3 …`로 알려준다.

⚠️ **두 곳에 따로 적으면 반드시 어긋난다.** 워드에서 고치고 구글폼을 안 고치면,
같은 배포에 서로 다른 질문이 나간다.

---

## 쓰는 순서

```bash
python3 -m pip install python-docx      # 처음 한 번만
python3 tool/tester_survey/make_tester_doc.py   # 워드
python3 tool/tester_survey/make_tester_form.py  # 구글폼 스크립트
```

### 구글 설문 만들기 (5분)

1. `script.google.com` → **새 프로젝트**
2. `…설문_구글폼_만들기.gs` 내용을 통째로 붙여넣기
3. 함수 목록에서 **`makeForm`** → **실행**
4. 처음 한 번 **권한 확인** (내 계정에 설문·시트를 만드는 권한)

실행 로그에 주소 셋이 찍힌다 — **테스터용 · 응답 시트 · 편집용**.
응답은 시트에 자동으로 쌓인다.

⚠️ 스크립트 맨 위 `APP_VERSION`을 배포 버전으로 채운다.

### 🚨 5. 보내기 전에 **시크릿 창으로 한 번 연다**

```
테스터용 주소를 시크릿 창(로그아웃 상태)에 붙여넣는다
→ 설문이 바로 보이면 OK
→ 구글 로그인 화면이 뜨면 아직 못 보낸다
```

**만든 사람 화면에서는 늘 멀쩡해 보인다.** 자기 계정으로 로그인돼 있으니까.

2026-08-18에 이걸 안 하고 주소를 받았다가, `curl`로 열어 보니 **HTTP 401**이었다.
워크스페이스 계정으로 만든 폼은 기본이 *"조직 내 사용자로 제한"*이라 **테스터에게만**
로그인 화면이 뜬다. 스크립트에 이 셋을 넣어 막아 뒀지만,

```javascript
form.setRequireLogin(false);            // ⚠️ 워크스페이스 계정에서만 동작
form.setCollectEmail(false);            // 이메일 수집은 로그인을 강제한다
form.setLimitOneResponsePerUser(false); // 1회 제한도 로그인을 강제한다
```

⚠️ **조직 정책이 더 강하면 스크립트가 뒤집지 못한다.** 그래서 코드로 막는 것과
별개로 **로그아웃 상태에서 눈으로 확인**하는 절차가 필요하다. 안 뜨면 편집
화면에서 **설정 → 응답**의 로그인 관련 항목 셋을 직접 끈다.

## 왜 이 구조인가

### 화면 순서로 묻는다 — **우리가 고친 순서가 아니라**

빌드6 때 테스터가 보내온 문서(`커넥션센스 앱 빌드 6_테스트_피드백_이예은.docx`)가
이런 모양이었다.

```
테스트 기기 환경: iPhone 13 (iOS 26.5.2)
테스트 앱 버전: 1.0.0(6)

1. 명함 > 새 명함 직접 등록
   테스트 상황 / 발생 문제
```

📌 **테스터는 자기가 앱을 쓰는 순서대로 적는다.** 그래서 1부를
`명함 등록 → 지갑 → 주변·지도 → AI → 그 밖`으로 두고, 각 화면 끝에
**자유 서술 칸**을 뒀다(그 문서의 *"발생 문제"*에 해당).

⚠️ 처음에는 *"우리가 고친 것"* 순서로 만들었는데, 그건 **우리 머릿속 순서**지
테스터가 화면을 여는 순서가 아니다.

### ⭐ 표시로 "이번에 바뀐 것"을 구분한다

테스터가 **무엇을 봐야 하는지** 바로 알 수 있다.

### 인식률을 숨기지 않는다

```
홈페이지 100 · 팩스 97 · 사무실 96 · 이메일 94 · 주소 92 · 이름 85
⚠️ 회사 66 · 직함 58
```

⚠️ **숨기면 테스터가 정상 동작을 결함으로 제보**하거나, 반대로 **고쳐야 할 값을
안 알려준다.**

### 값은 "사시겠습니까"로 묻지 않는다

⚠️ **테스터는 공짜로 쓰고 있어 후하게 답한다.** 그래서
*"얼마짜리로 느꼈나"* → *"1,000원이면 비싸다/싸다"* 순으로 묻고,
**"안 낼 것 같다"도 좋은 답**이라고 미리 적어 둔다.

⚠️ **던지는 값은 확정된 사다리의 최저 티어여야 한다.** 2026-08-18까지 이 문항은
*"30회에 3,300원"*이었는데, 그 3,300원은 **한국 스토어의 소액 가격 자리**
(1,100·2,200·3,300·5,500)에서 따온 것이지 우리 티어가 아니었다. 확정된 사다리
(추가 303·917f061)의 최저 티어는 **₩1,000 = 30회**다. 없는 값에 대한 반응을
모으면 그 답으로는 아무것도 정할 수 없다.

### AI는 두 갈래로 나눠 묻는다

```
(가) 매번 다른 말이 나오는가   ← 고쳤다. 안 되면 그게 제보 대상
(나) 그 문장이 쓸 만한가        ← 아직 손대지 않았다
```

⚠️ **섞어 물으면 어느 쪽이 문제인지 영영 모른다.** *"매번 다르긴 한데 셋 다
별로다"* 같은 답이 가장 쓸모 있다.
