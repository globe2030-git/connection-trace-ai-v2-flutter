# 명함 인식 검수 도구

실물 명함과 인식 결과를 나란히 놓고 **정답을 남기는** 로컬 도구다.
`index.html`을 브라우저로 열면 된다. 설치할 것도, 띄울 서버도 없다.

```bash
open tool/ocr_review/index.html
```

## 왜 필요한가

인식 규칙을 고칠 때마다 "좋아졌나"를 재야 하는데, **정답지가 없으면 잴 수 있는
것이 채움률뿐이다.** 실제로 2026-08-14에 그 함정에 빠졌다 — "오분류 0장"이라고
적어 둔 수치가 사실은 값의 **모양만** 본 것이라, 빈 값은 전부 "정상"으로 세고
있었다(backlog 추가 198).

정답지가 있으면 **정확도**로 잴 수 있다. 그게 이 도구의 목적이다.

## 버튼이 무슨 뜻인가 — **단계로 묶어 뒀다**

이름만으로는 어느 것이 시작이고 어느 것이 끝인지 알기 어렵다는 지적을 받아
(2026-08-18) 툴바를 셋으로 묶었다. **각 버튼에 마우스를 올리면 설명이 뜬다.**

| 묶음 | 버튼 | 무엇을 |
|---|---|---|
| **① 열기** | 인식 결과 열기 | 앱에서 뽑은 `scan_result.tsv` — **여기서 시작한다** |
| | 명함 사진 열기 | 원본 사진 폴더(건너뛰어도 된다) |
| **② 이어하기** | 지난 정답지 | 저번에 저장한 `ocr_truth.tsv`를 불러와 이어 채운다 |
| | 중간 저장분 | 하다 만 작업(`…progress.json`)을 되살린다 |
| **볼 것 고르기** | 칸·범위 선택 | 특정 칸만, 또는 아직 안 본 장만 보기 |
| | 정확도 보기 | 지금까지의 정답으로 칸별 정확도 계산 |
| **③ 저장** | 중간 저장 | **작업 상태**를 남긴다(.json) |
| | **정답지 저장** | **결과물**을 내보낸다(`ocr_truth.tsv`) |

### ⚠️ 파일이 두 가지다 — 이름이 비슷한데 쓰임이 다르다

| | 무엇인가 | 언제 쓰나 |
|---|---|---|
| **정답지** `ocr_truth.tsv` | **결과물.** 각 칸의 정답 | 인식률을 재는 **자**가 된다. 다음 검수 때 **② 지난 정답지**로 불러온다 |
| **중간 저장** `…progress.json` | **작업 상태.** 어디까지 봤는지·무엇을 ✓ 했는지 | **하다 말고 덮을 때.** 다른 컴퓨터로 옮길 때도 이것 |

📌 한 장 볼 때마다 브라우저에도 자동으로 남지만 **브라우저를 지우면 같이
사라진다.** 오래 걸리는 작업이면 **중간 저장**을 한 번씩 눌러 둔다.

## 쓰는 순서

1. 앱 관리자 화면 → **명함 일괄 스캔** → TSV 저장
   (`원문` 칸이 있어야 한다. 없으면 앱이 낡은 빌드다)
2. 기기에서 TSV와 이미지를 꺼낸다

   ```bash
   ADB=~/Library/Android/sdk/platform-tools/adb
   PKG=com.connectiontrace.connection_trace_ai_flutter
   $ADB exec-out run-as $PKG cat app_flutter/card_samples/scan_result.tsv > scan_result.tsv
   ```

3. `index.html`을 열고 **TSV 불러오기** → **이미지 폴더** 선택
4. 한 장씩 확인한다
   - 왼쪽: 실물 이미지 (⟲ ⟳ 회전, `원본 크기`로 확대 — 눕혀 찍힌 명함이 있다)
   - 오른쪽: 인식 원문 + 칸별 `추출값 / 정답`
   - **회색 추출값을 누르면** 그대로 정답이 된다
   - **원문 줄을 누르면** 방금 고른 정답 칸에 들어간다 (타이핑을 줄이는 게 핵심)
   - **앞으로 넘어가면(확인 완료·다음 / 다음 → / →) 그 장은 `확인함(Y)`으로
     기록된다.** 채점기는 Y로 표시된 장만 세므로, 검수한 장은 반드시 앞으로
     넘어가며 지나가야 한다. 뒤로 가기(←)는 재확인이라 Y를 건드리지 않는다
   - <kbd>Ctrl</kbd>+<kbd>Enter</kbd> = 확인 완료·다음
5. **정답지 내보내기** → `ocr_truth.tsv`

## 정답지 작성 규칙 (칸마다 이렇게 적는다)

**원칙: "OCR이 어떻게 읽었나"가 아니라 "명함에 뭐라고 적혀 있나".** 정답지가
이 규칙을 안 지키면 파서가 맞아도 채점이 틀리게 나온다 — 실제로 첫 채점에서
끝 쉼표·괄호·라벨 때문에 정확도가 89%로 눌렸다가, 규칙대로 고치니 94%가
됐다(backlog 추가 212).

| 칸 | 규칙 |
|---|---|
| 전화·휴대폰·사무실 | `010-1234-5678` — 라벨(M/T/F)·국가번호(`+82`) 빼고 하이픈만 |
| 이메일 | **명함 실물 기준**. OCR이 `,kr`로 읽었어도 `.kr`, 공백 없이 |
| 주소 | 끝 쉼표 빼기 (`…135,` → `…135`) |
| 우편번호 | 숫자만 (`(08511)` → `08511`) |
| 직함 | 이름 빼고 직함·부서만 |
| 회사 | 명함에 인쇄된 대표 표기 하나 |

## ⚠️ 진행 상황 저장

Chrome은 `file://`에서 자동 저장(localStorage)을 막는다. 그런 브라우저에서는
화면 위에 **경고가 뜬다** — 그때는 중간중간 **진행 저장**을 눌러
`ocr_review_progress.json`으로 남기고, 다음에 **진행 불러오기**로 이어서 한다.

Safari는 대개 자동 저장이 된다. 어느 쪽이든 검수가 끝나면 정답지를 내보내 둘 것.

## 정답지가 생기면 — 채점하기

정답지를 내보낸 뒤 이렇게 돌리면 **필드별 정확도**가 나온다.

```bash
TSV=~/card-ocr-data/scan_result.tsv \
TRUTH=~/card-ocr-data/ocr_truth.tsv \
flutter test test/ocr_accuracy_score_test.dart
```

출력 예:

```
검수 완료 42장 / 정답지 103장

=== 필드별 정확도 ===
이름    일치38 틀림2 미검출2 오검출0 둘다빔0 → 90%
회사    일치31 틀림5 미검출4 오검출1 둘다빔1 → 76%
...
전체 정확도: 84% (301 / 358)

=== 틀린 것 57건 ===
  틀림  card_56.png [회사] "크림하우스주)" ≠ "크림하우스(주)"
  ...
```

- **확인함(Y)으로 표시한 명함만** 센다 — 안 본 것을 정답으로 쓰면 그게 다시 추측이다
- 원문(rawLines)을 **지금 파서에 다시 먹여** 채점하므로, 규칙을 고칠 때마다 바로
  다시 돌리면 된다. 기기가 필요 없다
- ⚠️ **진짜 숫자는 이 채점기 쪽이다.** 검수 도구 화면의 집계는 TSV에 저장된
  **옛 추출값**을 비교하지만, 채점기는 **원문을 지금 파서에 다시 먹인다.** 그래서
  둘이 다르다(첫 채점 때 도구 이름 65% vs 채점기 94%). 도구 집계는 참고용이고,
  파서 개선 효과는 채점기로 본다
- 전부 검수하지 않아도 된다. **20~30장만 해도** 어느 칸이 약한지 드러난다

## 비어 있는 칸을 어떻게 적을 것인가

**명함에 그 값이 없으면 정답 칸을 비운 채로 둔다.** 집계에서 "둘 다 빔"으로
세고 **분모에서 뺀다** — 없는 것을 못 찾았다고 점수를 깎으면 안 되기 때문이다.

실제로 표본의 `card_134`(삼성SDI)는 전화·이메일·주소가 명함에 아예 없다.
처음 결함 목록은 이걸 "미검출"로 적어 두어서, 없는 문제를 쫓을 뻔했다.

| 집계 항목 | 뜻 |
|---|---|
| 일치 | 추출값 = 정답 |
| 틀림 | 둘 다 값이 있는데 다름 |
| **미검출** | 명함에는 있는데 인식이 못 찾음 |
| **오검출** | 명함에 없는데 값이 들어감 |
| 둘 다 빔 | 명함에 없고 인식도 안 함 → **분모에서 제외** |

정확도 = 일치 ÷ (일치 + 틀림 + 미검출 + 오검출)

## 개인정보

명함은 **이용자 본인이 아닌 제3자의 개인정보**다(CLAUDE.md 4절).

- 이 도구는 **네트워크를 쓰지 않는다.** 외부 스크립트·폰트·이미지도 없다.
- 그러니 **어디에도 배포하지 말 것.** 웹에 올리는 순간 성격이 달라진다.
- 내보낸 `ocr_truth.tsv`와 진행 JSON에는 실명·전화번호·주소가 들어 있다.
  저장소에 커밋하지 말고(루트 `.gitignore` 확인) 안전한 곳에 둘 것.
